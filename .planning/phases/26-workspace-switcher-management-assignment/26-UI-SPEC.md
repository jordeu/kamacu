# Phase 26 — UI Design Contract

> Visual and interaction contract for the Workspace Switcher, Management & Assignment phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is an established codebase (phase 26).** The design system, tokens, and component
> primitives are already locked from prior milestones. This contract does **not** introduce a
> new visual language — it codifies the existing one and pins the phase-specific interaction
> and copywriting contracts for the switcher, management dialogs, transfer submenu, and empty
> state. Nearly every field is pre-populated from the codebase (`web/src/index.css`,
> `components.json`, existing sidebar components) and `26-CONTEXT.md`. No user questions were
> required.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |

CSS-variable / Tailwind utility name (e.g. `bg-sidebar`, `text-muted-foreground`), never a raw hex.

## Spacing Scale

Tailwind 4 default 4px step. The switcher, dropdown, dialogs, and empty state use only multiples of 4:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `gap-1` between stacked menu rows and sidebar items; inline icon gaps |
| sm | 8px | `gap-2` switcher trigger (name ↔ chevron); dialog footer button gap; `px-2` sidebar list padding |
| — | 12px | `px-3` switcher/row horizontal padding, `gap-1.5` label→input (multiple of 4) |
| md | 16px | `gap-4` dialog form vertical rhythm; dialog content padding |
| lg | 24px | Manage-workspaces dialog row block spacing |
| xl | 32px | `py-8` empty-state vertical padding |

Exceptions (all multiples of 4, inherited from the existing sidebar shell — do not re-derive):
- `min-h-7` (28px) sidebar/menu row min height (switcher trigger matches the project-row height).
- `size-10` (40px) collapsed-rail icon button — **not used by the switcher** (switcher is expanded-only) but the filtered project rail keeps it.
- `--sidebar-width: 15rem` (240px) expanded, `3rem` (48px) collapsed icon rail.
- Fixed `h-9` (36px) global Active Sessions bar — untouched by this phase (WSBAR-01 guardrail).

## Typography

Two font weights only — **regular (400)** and **medium (500)**. The app uses no semibold; both
`DialogTitle` and `AlertDialogTitle` in this preset are `text-base font-medium`. Do not introduce
`font-semibold` or `font-bold` for any new workspace surface.

| Role | Size | Weight | Line Height | Where in this phase |
|------|------|--------|-------------|---------------------|
| Label | 12px (`text-xs`) | medium (500) | ~1.33 (`leading-4`) | Dialog field labels ("Name"); inline error text (`text-xs text-destructive`); tooltips |
| Body | 14px (`text-sm`) | regular (400) | ~1.43 (`leading-5`) | Switcher trigger label; dropdown-menu items; workspace-list rows; Input text; empty-state body |
| Heading | 16px (`text-base`) | medium (500) | 1.0 (`leading-none`) | `DialogTitle` / `AlertDialogTitle` ("New workspace", "Rename workspace", "Manage workspaces", "Delete workspace?") |
| Display | 20px (`text-xl`) | medium (500) | ~1.4 (`leading-7`) | Workspace-scoped empty-state heading ("No projects in {workspace} yet") |

Emphasis convention: the switcher trigger label uses `text-sm font-medium` (matching the "Kamacu"
brand-lockup weight) so it reads as a section header. Everything else is regular 400.

## Color

Dark-only 60/30/10 split. Values are the `.dark` OKLCH tokens; the hex column is an approximate
reference only — **implement with the token/utility name**.

| Role | Token (utility) | ~Hex | Usage |
|------|-----------------|------|-------|
| Dominant (60%) | `--background` (`bg-background`) | ~#131316 | Board/main area, dialog overlay backdrop base, empty-state canvas |
| Secondary (30%) | `--sidebar` = `--card` = `--popover` (`bg-sidebar` / `bg-popover` / `bg-card`) | ~#1e1e22 | Sidebar surface where the switcher trigger lives; the dropdown-menu panel; Manage-workspaces + create/rename + delete dialog surfaces |
| Accent (10%) | `--primary` (`bg-primary` / near-white) and `--sidebar-accent` (`bg-sidebar-accent`) | ~#e8e8ea / ~#29292e | See reserved-for list below |
| Destructive | `--destructive` (`bg-destructive` / `text-destructive`) | ~#e5484d | The Delete-workspace confirm **action button** and inline validation error text only |

Accent reserved for (explicit — never "all interactive elements"):
- **`--primary` (near-white fill)** — the single primary action button per dialog: **Create** (create dialog),
  **Save** (rename dialog). One primary button max per surface; Cancel is always `variant="ghost"`.
- **`--sidebar-accent` (subtle fill)** — the selection/hover state on the switcher trigger and on rows:
  the open/hovered switcher trigger and the active project row use `bg-sidebar-accent` (the same filled-row
  treatment established for the selected project in phase 19, reversing D-06).
- **`✓` active-workspace marker** — a lucide `Check` icon (default foreground, via the standard
  `DropdownMenuCheckboxItem`/`RadioItem` indicator slot), marking the active workspace in the switcher
  dropdown and the project's current workspace in the "Move to workspace" radio submenu. Not a color accent —
  a monochrome indicator glyph.

Explicitly NOT accented in this phase:
- No new brand/hue color. Workspaces are **name-only** (no icon/color identity — WSFUT-01 deferred).
- No amber. `amber-400` remains reserved for the existing per-project waiting badge and is not introduced
  on any workspace surface.
- Disabled delete affordances are **muted, not red** — a disabled control + tooltip (`text-muted-foreground`),
  never `text-destructive` (the guard is a UX affordance, not a destructive action; D-05/D-06).

## Copywriting Contract

No toast/sonner library exists in the app — **all feedback stays inline / tooltip / dialog, never a toast.**
Errors surface as inline `text-xs text-destructive` under the input (via `ApiError` → `sentenceCase`),
exactly as `RenameProjectDialog` already does.

| Element | Copy |
|---------|------|
| Primary CTA (create) | Dropdown quick entry: **"New workspace"** (with a lucide `Plus` icon). Create dialog title: **"New workspace"**, primary button: **"Create"** |
| Secondary entry (manage) | Dropdown entry: **"Manage workspaces…"** (with a lucide `Settings`/`Sliders` icon) — opens the Manage dialog |
| Rename | Dialog title: **"Rename workspace"**, primary button: **"Save"** (mirrors `RenameProjectDialog`) |
| Transfer entry | `⋯`-menu submenu label: **"Move to workspace"** (radio items = all workspaces; the project's current workspace is checked + disabled) |
| Empty state heading | **"No projects in {workspace} yet"** (workspace-scoped, D-13 — never the global "No projects yet" while other workspaces have projects) |
| Empty state body | **"Add a project to this workspace to get a board."** + primary button **"Add project"** (creates into the active workspace, D-10) |
| Error state (duplicate name) | Inline under input: server message sentence-cased, e.g. **"A workspace with that name already exists."** (from `name UNIQUE COLLATE NOCASE`, migration 00012). Generic fallback: **"Couldn't save. Try again."** |
| Destructive confirmation | **Delete workspace (empty):** `AlertDialog` — title **"Delete workspace?"**, description **"\"{name}\" will be removed. Its projects are unaffected — it has none."** (or a shorter *"This workspace has no projects and will be removed."*), Cancel (ghost) + **"Delete workspace"** (`variant="destructive"`). Mirrors `ProjectMenu.tsx`'s AlertDialog. |
| Delete guard — non-empty | Delete control **disabled** + tooltip: **"Move or remove its {n} project{s} first."** (count from client-side `useProjects()` by `workspace_id`, D-05) |
| Delete guard — default workspace | Delete control **disabled** + tooltip: **"The default workspace can't be deleted."** (keyed off the `is_default` flag, never the name "Personal" — rename-proof, D-06) |

Copy conventions to hold:
- Sentence case for all body/labels/buttons (matches the codebase: "Add project", "Delete project", "Rename").
- Ellipsis (`…`) only on entries that open a further surface ("Manage workspaces…"). Direct actions
  ("New workspace", "Create", "Save", "Delete workspace") take no ellipsis.
- Buttons are verb-first and specific ("Create", "Save", "Delete workspace", "Add project") — never "OK"/"Submit".

## Interaction & State Contract

| Surface | State | Contract |
|---------|-------|----------|
| Switcher trigger | Default | `bg-sidebar` surface, `text-sm font-medium` label + trailing chevron; full width, `min-h-7 px-3` |
| Switcher trigger | Hover / open | `bg-sidebar-accent` fill (same as selected project row) |
| Switcher trigger | Collapsed rail | **Hidden** (`group-data-[collapsible=icon]:hidden`); the icon rail shows only the filtered project avatars (WSNAV-01) |
| Switcher dropdown | Active workspace | Marked with a leading `✓` (Check indicator); picking any row sets it active and closes the menu (D-02) |
| Project list (both surfaces) | Filtered | Expanded rows AND collapsed rail show only the active workspace's projects (client-side filter by `workspace_id`, D-12) |
| Create / rename dialog | Pending | Primary button `disabled` while mutation pending or trimmed name empty (matches `RenameProjectDialog`) |
| Create / rename dialog | Error | Inline `text-xs text-destructive` under Input; dialog stays open |
| Delete control | Empty workspace | Enabled → opens `AlertDialog` confirm (D-07) |
| Delete control | Non-empty | Disabled + tooltip "Move or remove its {n} project(s) first." (D-05) |
| Delete control | Default workspace | Disabled + tooltip "The default workspace can't be deleted." (D-06) |
| Transfer submenu | Current workspace | Radio item checked + disabled; other workspaces selectable (D-08) |
| Transfer of open project | Follow | View follows the moved project: active workspace flips to target, `localStorage` updates, project stays selected (D-09) |
| Transfer of other project | Silent | Project drops out of the filtered list; active workspace unchanged (D-09) |
| Switch navigation | Has projects | Navigate to first project by name (sidebar order, D-11) |
| Switch navigation | No projects | Workspace-scoped empty state (D-13) |
| Reload / deep-link | URL project wins | If URL project's workspace ≠ saved active, set active to the project's workspace + update `localStorage`; stale/missing saved id falls back to `is_default` (D-14) |
| Active Sessions bar | Any workspace | Unchanged — reads its own `useAgentStatuses()` poll, cross-workspace, no filter (WSBAR-01 / D-15) |

Active-workspace persistence: `localStorage` key follows the `kamacu.*` convention (e.g. `kamacu.workspace`),
using the `getItem/setItem` + sensible-default idiom from `AppLayout.tsx`. The active-workspace state shape
(localStorage-backed hook vs. context vs. zustand) is Claude's Discretion per CONTEXT.md — not a visual concern.

Accessibility:
- Switcher trigger: accessible name announces the active workspace (e.g. `aria-label="Workspace: {name}"`);
  chevron is decorative.
- Active/selected rows carry the standard Radix `role`/`aria-checked` from `DropdownMenuCheckboxItem`/`RadioItem`.
- Disabled delete controls remain focusable-with-tooltip so the reason is discoverable (don't use raw `disabled`
  that swallows the tooltip; follow the existing tooltip-on-disabled pattern or wrap appropriately).
- Tooltips use `TooltipProvider delayDuration={0}` (already set app-wide in `AppLayout.tsx`).
