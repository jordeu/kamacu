| startup -> backfill UPDATE | Boot-time pass reads + writes existing rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-05 | Tampering | PATCH icon_color | mitigate | validateIconColor enforces curated-palette membership (D-11) at the route entry; off-palette/arbitrary hex rejected with 400 before any SQL runs (defends ICON-FUT-03 deferral) |
| T-18-06 | Tampering | PATCH icon_letters | mitigate | validateIconLetters trims/uppercases/caps at 2/requires >=1 (D-10) at route entry; empty rejected with 400, row left untouched |
| T-18-07 | Tampering (SQLi) | update + create INSERT/UPDATE | mitigate | All values bound via `?` placeholders (icon_letters/icon_color/id); never string-concatenated - matches the existing projects.go idiom |
| T-18-08 | Tampering | backfill not corrupting rows | mitigate | Backfill only fills blank rows (WHERE icon_letters='' OR icon_color='') and writes only the two icon columns by id; non-empty values and all other columns untouched |
| T-18-09 | Repudiation/DoS | startup backfill failure | accept | Backfill failure is fatal (slog.Error+os.Exit(1)) by design - surfaced loudly at boot, local single-user app, operator restarts |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs (all stdlib + the Plan 01 helpers); slopcheck not triggered |
</threat_model>
