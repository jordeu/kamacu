<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| project name -> deriveLetters | Project names (folder basename / repo name) are user-influenced text flowing into the monogram deriver and into SQL via the backfill |
| stored row -> backfill UPDATE | Existing DB rows are read and written back during the one-shot backfill |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Tampering | BackfillProjectIcons SELECT/UPDATE | mitigate | Parameterized queries only (`?` placeholders for letters/color/id); never string-concat name or id into SQL - matches the projects.go idiom |
| T-18-02 | Denial of Service | deriveLetters on hostile/huge name | mitigate | deriveLetters reads at most the first two usable tokens/chars and returns <=2 runes; bounded work regardless of input length |
| T-18-03 | Tampering | migration 00009 on existing rows | mitigate | Up only ADDs columns with DEFAULT '' (no UPDATE/DELETE of existing data); backfill only fills blank rows via WHERE clause - never overwrites non-empty letters/color |
| T-18-04 | Information Disclosure | error messages from validators | accept | Validator errors are static copy ("...must be...") with no user data echoed beyond the rejected token; local single-user app, no PII |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | No new package-manager installs in this plan (math/rand/v2 + unicode + strings + database/sql are all stdlib); slopcheck not triggered |
</threat_model>
