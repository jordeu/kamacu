    Define the pure wire types. `activityTask` carries the raw *_at strings through (the handler's SQL scan fills them; buildDurationSlices parses them): ID int64 `json:"id"`, Title string `json:"title"`, DoneAt string `json:"doneAt"`, InProgressAt string `json:"-"` (not serialized — internal carry for stat compute), InReviewAt string `json:"-"`, ProjectID int64 `json:"projectId"`, ProjectName string `json:"projectName"`. `timeStat`: N int `json:"n"`, Min int64 `json:"min"`, Max int64 `json:"max"`, Median int64 `json:"median"` (all seconds). `statsBlock`: TaskCount int `json:"taskCount"`, ReviewCount int `json:"reviewCount"`, Cycle timeStat `json:"cycle"`, DwellInProgress timeStat `json:"dwellInProgress"`, DwellInReview timeStat `json:"dwellInReview"`.

    Add parseActivityTime(s string) (time.Time, bool). Try the two ISO layouts in order — the reaper millisecond layout "2006-01-02T15:04:05.000Z" first, then the gh closedAt second-precision layout "2006-01-02T15:04:05Z" — and return the first successful time.Parse result with true. Empty or unparseable → (time.Time{}, false). This is the SHARED parse primitive: buildDurationSlices uses it for the *_at columns (ms precision), and plan 10-02's aggregateReviews uses it for the reviews-window cutoff comparison (gh closedAt is second precision) — the dual-layout loop is what makes a single time-comparison correct across the mismatched precisions (parse both sides; never string-compare).

    Add parseScope(raw string) (kind string, id int64, err error). Empty or "global" → ("global", 0, nil). Otherwise split once on ":": the prefix must be exactly "workspace" or "project"; strconv.ParseInt the suffix (reject negative/non-numeric); return kind + id. Any other shape → non-nil error.

    Add parseWindow(raw string) (time.Duration, error). Empty or "week" → 7*24*time.Hour; "month" → 30*24*time.Hour; else non-nil error.

    Add computeTimeStat(durations []time.Duration) timeStat. Empty → zero-valued (N:0). Otherwise copy into a local slice and sort.Slice ascending; median = odd-N → sorted[n/2], even-N → (sorted[n/2-1]+sorted[n/2]) truncated to int64 seconds; Min/Max = int64 of the first/last sorted element. Min/Max/Median are int64 seconds (Pitfall 6).

    Add buildDurationSlices(tasks []activityTask) (cycle, dwellInProgress, dwellInReview []time.Duration). For each task: parse doneAt via parseActivityTime; if it fails, skip ALL three slices for this row (D-09 — no done_at means it cannot contribute to any time stat). Otherwise: parse inProgressAt and inReviewAt via parseActivityTime (each independently; either may be false/absent). cycle: if inProgress ok → append done.Sub(inProgress). dwellInReview: if inReview ok → append done.Sub(inReview). dwellInProgress: if inReview ok AND inProgress ok → append inReview.Sub(inProgress) (Open Q3 — time in In Progress BEFORE entering In Review); else if inProgress ok (inReview absent) → append done.Sub(inProgress) (the skipped-In-Review case). A NULL/unparseable *_at excludes the row from THAT slice only — never append, never panic (Pitfall 7).

The exact ordering among degraded states is low-stakes (plan 10-02 / Phase 11 only branch on ok/partial/degraded) but the priority is stable and documented.
