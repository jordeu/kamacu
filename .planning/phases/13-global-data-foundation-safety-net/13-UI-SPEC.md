## Naming & Label Contract (LOCKED — the core of this spec)

The single naming decision made once, early, so Phases 14–16 never re-ask (CONTEXT "UI naming" block):

| Layer | Value | Rule |
|-------|-------|------|
| **User-facing name** | **`Scratchpad`** | Every string a human reads: Settings section title, view title, "Open Scratchpad" affordance, error copy (D-09) |
| **Synthesized label pair** | `projectName:"Global"`, `taskTitle:"Scratchpad"` | The wire values the server synthesizes for the status feed / MCP session detail. Non-nullable — the existing TS contract is preserved (D-10) |
| **Bar/status row rendering** | `Global · Scratchpad` | Maps 1:1 onto the existing `SessionRow` slots — projectName span, literal `·` separator span, taskTitle span (`ActiveSessionsBar.tsx:260-267`). **Zero rendering changes**; scope slot + name slot, never "Scratchpad" duplicated into both (CONTEXT specifics) |
| **Bar-row aria label** | `Open Scratchpad in Global` | Derived by the existing `` `Open ${taskTitle} in ${projectName}` `` template (`ActiveSessionsBar.tsx:247`) |
| **Internal naming** | `global` everywhere | `scope:"global"` (API values), `/global` route, `global_task` table, `kamacu-global-*` tmux mint, `~/.kamacu/repos/global/<owner>/<name>` namespace (D-11). The label is presentation-only; architecture churn is zero |

**Why "Scratchpad" (D-09):** the v1.12 Activity scope selector already labels `scope=global` as **"Global"** (`ScopeSelector.tsx:28`) meaning *all workspaces*. Naming the scratchpad "Global" too would collide two meanings in one app.

**Coexistence rule (locked):** the Activity scope selector's "Global" is NOT renamed — it is a different surface with v1.12 vocabulary. From v1.13 on, in the bar row and session labels, `Global` (scope slot) means *the scratchpad's scope*. The two never appear on the same surface.

**Deliberate URL/label divergence:** the route is `/global` while the title says `Scratchpad` (D-11 presentation-only rule). Auditors: this asymmetry is the contract, not a bug.

## tmux Session Naming (LOCKED)

| Scope | Name pattern | Mint | Example |
|-------|--------------|------|---------|
| Task (existing, unchanged) | `kamacu-<taskID>-<n>` | `sessions.go:422` | `kamacu-42-1` |
| **Global (locked this milestone)** | **`kamacu-global-<n>`** | Phase 15 (spawn path; `n` reserved app-side via `MAX(n)+1 WHERE scope='global'` per 13-RESEARCH A7/A8) | `kamacu-global-1` |

Contract notes:
- The `kamacu-` prefix filter and sweep machinery treat both shapes identically; the scope-aware known-set (`WHERE scope='global' OR task_id IN (SELECT id FROM tasks)`) is what keeps live globals alive (GDATA-03).
- `defaultTmuxLabel` parses the **last** `-`-delimited segment, so `kamacu-global-3` → `Bash 3` with zero code change — label parity with task tabs for free.
- Names are server-minted (never user input); user-visible label is the `label` column, which migrates byte-for-byte.
