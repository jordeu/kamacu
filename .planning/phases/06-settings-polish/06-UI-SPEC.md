# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Sources: PROJECT.md Current Milestone v1.1 + ROADMAP.md Phase 6 notes (locked milestone decisions — no 06-CONTEXT.md exists; these are canonical), REQUIREMENTS.md SET-01..04 / AGENT-01..02 / WT-01..02 / SHELL-01..02 / BRANCH-01..02 / UI-01, Phase 1 UI-SPEC (approved — design system foundation, copy patterns, form/dialog conventions), Phase 3 UI-SPEC (approved — meta-line/mono conventions, task-page layout contract), Phase 4 UI-SPEC (approved — sidebar anatomy, status palette), existing code (`ProjectSidebar.tsx` footer, `TaskPage.tsx` header wrapper, `App.tsx` routes, `web/src/components/ui/` inventory). Claude's discretion areas (form layout/grouping, save model, copy, restore-to-default shape, dirty-state indication) resolved below. No user questions were needed.

**Scope note:** This contract EXTENDS Phases 1–5; it never redefines them. Board, terminal, agent, and diff surfaces are untouched. This phase ADDS: (1) the sidebar gear control, (2) the `/settings` full-page route with four setting groups (agent params, worktree base directory, bash-tab shell, branch-name template), per-field save with inline validation and restore-to-default, (3) the UI-01 task-view header width fix. **Reverses D-51 (intentional):** the extra-params field ships pre-filled with `--dangerously-skip-permissions`; the spec treats that default as specified behavior, presented with a plain explanatory line — no warning chrome.

### Per-field affordances (SET-04)

| Element | Copy |
|---------|------|
| Restore affordance | `Reset to default` — 12px muted text button, right-aligned on the field's label row, rendered **only** when the saved value differs from the default |
| Saved feedback | `Saved` — 12px muted text appearing right of the field label for 2 seconds after a successful save, then removed. No motion beyond appear/disappear (`motion-reduce` safe by construction) |
| Save failure (network/5xx) | Inline under the field, destructive 12px: `Couldn't save. Try again.` — the draft value is never cleared (Phase 1 save-failure pattern verbatim) |

Empty states: none — every setting always has a value (its default). Destructive actions: none this phase — `Reset to default` is routine and instantly re-editable, so it gets no confirmation ceremony.

## Interaction Contract

States the executor must implement; the auditor will check these.

### Sidebar gear (SET-01)

| Interaction | Contract |
|-------------|----------|
| Placement | `SidebarFooter` becomes one row, sm (8px) gap: existing `Add project` ghost button (`flex-1 justify-start`, unchanged copy and behavior) + gear ghost icon button (28px square, 16px `settings` icon) flush right |
| Click | Navigates to `/settings`. The gear is a Link-wrapped button (sidebar navigation convention), not a dialog trigger |
| Active state | While the route is `/settings`, the gear shows the selected-item treatment (`#27272a` background, zinc-50 icon); no project row is active |
| Collapsed sidebar | Offcanvas mode hides the whole sidebar including the gear — no special collapsed affordance; reopen the sidebar to reach Settings |

### Settings page — save model (discretion, resolved)

**Per-field commit, no page-level Save button.** Each field is an independent mutation: text inputs commit on blur and on Enter; the select commits on change. This satisfies SET-04 by construction — a validation error on one field can never touch another field's state, and there is no dirty page to lose.

| Interaction | Contract |
|-------------|----------|
| Commit (text fields) | Blur or Enter → if the draft equals the saved value, no request and no feedback; otherwise PUT the single setting. While in flight: input stays enabled, no spinner |
| Commit (select) | Selection change → immediate PUT. v1.1's single `bash` option makes this a formality, but the wiring is the SHELL-02 seam |
| Revert (text fields) | Esc while focused reverts the draft to the last saved value and keeps focus. Esc never navigates on this page (no Esc-to-board binding on `/settings`) |
| Success | `Saved` flash on the field's label row, 2s, then gone. The saved value becomes the new revert target |
| Validation failure (4xx) | Inline destructive message under the field, server copy mirrored verbatim. The draft stays in the input for correction; the stored setting is unchanged; **all other fields keep their state untouched** (SET-04). The error clears on the next successful commit of that field or when the draft is edited |
| Network failure | `Couldn't save. Try again.` under the field, draft kept, same isolation rule |
| Reset to default (SET-04) | Click → PUT the default immediately → input shows the default + `Saved` flash → the button disappears (value now equals default). Disabled while that field's save is in flight. No confirmation |
| Dirty-state indication (discretion, resolved) | None beyond focus — with commit-on-blur, a field is only ever transiently dirty while focused, so no dirty badges, no unsaved-changes prompt, no navigation guard |
| Applied-at-next-spawn (SET-03) | Communicated once by the page sub-line; individual fields do not repeat it. No toast, no restart prompt — there is nothing to restart |
| Concurrency | Single-user app: last write wins; no conflict UI |

### UI-01 — task-view header width fix

| Interaction | Contract |
|-------------|----------|
| Container | In `TaskPage.tsx`, the `max-w-[860px]` wrapper around the header + meta line is removed: the wrapping block becomes full width (`w-full shrink-0 space-y-2`), spanning the same content area as the tab strip below it |
| Header row | `back button (28px icon) → title (flex-1, min-w-0, truncate) → ellipsis menu trigger` — the trigger sits flush against the container's right padding edge (the lg/16px page padding), exactly where the tab strip ends. `align="end"` on the dropdown is unchanged |
| Title edit | The click-to-edit button and the edit `Input` both span the full flex-1 width — editing never shifts the ellipsis trigger |
| Meta line | The Phase 3 branch meta line / no-worktree slot moves with the header (full-width row); it still truncates with `truncate` and its copy is unchanged |
| Prose island | Description tab content keeps its `max-w-[860px]` constraint (Phase 1/3 prose-comfort rule) — **only the header block changes width**. Loading/error page states are out of scope for UI-01 |
| Collapsed-sidebar gutter | The existing `pl-9` gutter on `<main>` (AppLayout) already keeps the back button clear of the floating sidebar trigger; the full-width header changes nothing on the left edge |

Focal point: the settings page intentionally has no inverted high-contrast CTA — saves are per-field, so the visual anchor is the `Settings` heading and the calm one-column form; nothing competes. On the task view, the header gains no new chrome — UI-01 is alignment only.
