Up section: `PRAGMA foreign_keys = OFF;` then `BEGIN;` then `CREATE TABLE workspaces` with columns `id INTEGER PRIMARY KEY`, `name TEXT NOT NULL`, `is_default INTEGER NOT NULL DEFAULT 0`, and `created_at`/`updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now'))` (per D-01, mirror 00001_init.sql defaults; NO `position` or icon columns — WSFUT-01/02 are deferred); then `CREATE UNIQUE INDEX idx_workspaces_name_nocase ON workspaces (name COLLATE NOCASE)` (D-03); then `INSERT INTO workspaces (name, is_default) VALUES ('Personal', 1)` (D-02 — inserted FIRST into the empty INTEGER PRIMARY KEY table so it is deterministically id=1); then `ALTER TABLE projects ADD COLUMN workspace_id INTEGER NOT NULL DEFAULT 1 REFERENCES workspaces(id) ON DELETE RESTRICT` (D-04/D-05 — the `DEFAULT 1` assigns every existing project to Personal as part of the ALTER, no separate UPDATE loop); then `COMMIT;`; then `PRAGMA foreign_key_check;` (non-gating parity, harmless); then `PRAGMA foreign_keys = ON;` (mandatory re-arm — Pitfall 3). Do NOT use a full-table rebuild (Approach C) — with FK ON, `DROP TABLE projects` cascades and wipes all tasks (verified 3→0). Use `ON DELETE RESTRICT`, never CASCADE, for workspace_id.
