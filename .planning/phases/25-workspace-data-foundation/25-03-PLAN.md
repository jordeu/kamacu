**D-07 says "collect-then-update is REQUIRED."** Under the recommended migration (Approach A) the migration's `ADD COLUMN ... NOT NULL DEFAULT 1` already assigns EVERY existing project to Personal at migration time, so a reassignment loop would find zero rows (provably empty). This plan implements the **lean hook** (RESEARCH §3): `BackfillWorkspaces` only guarantees the default workspace row exists (`SELECT id FROM workspaces WHERE is_default = 1`; re-create Personal only if missing). This reinterprets D-07's mechanism but fully meets its stated job ("guarantee a default workspace exists and no project is workspace-less") — invariant 1 by the hook, invariant 2 structurally by the NOT NULL+FK+DEFAULT schema. Both forms are behaviorally identical with no data risk (RESEARCH Open Q1 / Assumption A2). Because the user confirmed the lean hook (2026-07-05), the literal collect-then-update variant is no longer under consideration.
