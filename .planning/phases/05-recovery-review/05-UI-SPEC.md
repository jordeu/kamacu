# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Sources: 05-CONTEXT.md decisions D-54..D-67 (locked), Phase 1 UI-SPEC (approved — design system foundation), Phase 2 UI-SPEC (approved — TerminalPane + banner anatomy, ANSI content palette precedent), Phase 3 UI-SPEC (approved — disabled-`+` tooltip pattern, tab strip mechanics), Phase 4 UI-SPEC (approved — agent tab states incl. checkpoint revisions: code-free `Agent session ended.` banner, `Reset session`, dimmed exited terminal), existing code (`AgentTab.tsx` exited-banner props, `TaskTabs.tsx` TabDef seam, `TerminalPane.tsx`). Claude's discretion areas (resumable pre-start body copy, diff palette values, diff layout anatomy) resolved below. No user questions were needed.

**Scope note:** This contract EXTENDS Phases 1–4; it never redefines them. Terminal internals, connection banners, and Stop semantics are Phase 2's contract, untouched. Status dots are Phase 4's contract, untouched — D-57 adds **no new dot states**. Cleanup dialogs are Phase 3's, untouched. This phase ADDS: (1) the **Resume/Reset button pair** in both exited-banner and pre-start surfaces (D-54), (2) the **resumable pre-start variant** of the Agent tab, (3) the **Diff tab** (Agent, Description, Diff, Bash 1..N) with its scoped add/remove content palette, (4) the disabled-Diff-tab pattern, (5) silent post-restart surfaces (D-58, D-65 — defined here mostly as *absences*).

## Color

Inherited Phase 1 budget unchanged: dominant zinc-950 `#09090b`, secondary zinc-900 `#18181b` surfaces / zinc-800 `#27272a` borders, accent blue-500 `#3b82f6` (focus rings, active tab indicator, drag-over, prose links), destructive red-500 `#ef4444`. Text: zinc-50 `#fafafa` / zinc-400 `#a1a1aa` muted / zinc-600 `#52525b` disabled. xterm theme + ANSI 16: Phase 2 verbatim. Status palette (dots, waiting border, sidebar chip): Phase 4 verbatim — **D-57: no new dot states, no new status colors.**

### Diff content palette (NEW — content-semantic, scoped to the Diff tab only)

Like the ANSI palette (Phase 2 precedent), these are content colors exempt from the 60/30/10 chrome budget: the *diff data* chooses them, the app only defines the ramp. They reuse the ANSI ramp values already shipped in `xtermTheme.ts` — no new hues enter the product.

| Element | Value | Hex / class |
|---------|-------|-------------|
| Added line background | green-500 at 10% | `bg-green-500/10` |
| Added line ± marker (`+` gutter char) | green-400 | `#4ade80` (ANSI green, Phase 2) |
| Removed line background | red-500 at 10% | `bg-red-500/10` |
| Removed line ± marker (`−` gutter char) | red-400 | `#f87171` (ANSI red, Phase 2) |
| Added/removed line text | zinc-50 | `#fafafa` — changed lines are the content of interest |
| Context (unchanged) line text | zinc-400 | `#a1a1aa` — no background |
| Hunk header (`@@ … @@`) | zinc-400 text on zinc-900 row | de-emphasized metadata strip |
| `+A` stat segments (totals bar + file headers) | green-400 | `#4ade80` |
| `−B` stat segments (totals bar + file headers) | red-400 | `#f87171` |

Rules:

- **Scope is the Diff tab and nothing else.** Green appears in exactly two places product-wide: the Phase 4 working dot (green-500) and these diff surfaces (green-400/green-500-tint). Red-400 stays within its existing ANSI scope plus these diff surfaces.
- **Explicitly NOT diff-colored:** the `Diff` tab label and its active indicator (stays accent blue-500, reservation #2), the totals-bar sentence text (zinc-50; only the ± numbers are colored), the refresh button (neutral ghost), file section borders and headers (zinc-800 / zinc-900 — never green/red borders), file paths (zinc-50 mono), empty/loading/error states (Phase 1 neutral + destructive patterns), scrollbars, and every surface outside the Diff tab. Diff colors never bleed into chrome.
- **No new accent uses.** The Diff tab gets the existing active-tab indicator for free; chevrons and the refresh button take the standard focus-visible accent ring (reservation #1).
- **Resume/Reset buttons are NOT colored:** `Resume session` is the standard inverted primary (zinc-50 on zinc-900 — Phase 1 CTA rule, never green); `Reset session` is a neutral ghost. No destructive styling — resetting is routine, not data loss (the transcript belongs to claude, not Kangent).

## Copywriting Contract

Tone inherited: terse, sentence case, no exclamation marks, no "please". Branch/base names in mono. Counts pluralize.

### Resume / Reset (D-54, D-56)

| Element | Copy |
|---------|------|
| Exited banner — resumable (within-run or post-restart attach) | Message: `Agent session ended.` (Phase 4 verbatim — code-free, always). Actions, left to right: `Reset session` (ghost) → `Resume session` (small primary, rightmost). No `Close` — the Agent tab is permanent (D-38) |
| Exited banner — not resumable | Message: `Agent session ended.` Single action `Reset session` (small primary) — Phase 4 contract verbatim, unchanged |
| Resumable pre-start state (post-restart, D-54b) | Heading (Display): `Agent session ended.` Body: `A previous conversation can be picked up where it left off. Reset starts a fresh session instead.` Buttons (sm gap, row): `Reset session` (ghost) + `Resume session` (inverted primary — the focal point) |
| Resume in flight | `Resume session` disabled, label `Resuming…`; `Reset session` disabled (label unchanged) |
| Reset in flight | `Reset session` disabled, label `Resetting…`; `Resume session` (if present) disabled (label unchanged) |
| Resume failure (D-56) | No toast, no dialog. claude's own error output is visible in the (dimmed) terminal; the exited banner returns with `Reset session` only — the resumable offer is gone. No silent fallback to a fresh session |
| Resume/Reset request failure (spawn rejected before claude runs) | Inline destructive 12px text below/near the buttons: `Couldn't start a session. Try again.` (Phase 2/4 copy verbatim) |

Which pair renders is driven by a single server-reported `resumable` flag per task — the UI never infers resumability client-side.

### Diff tab (D-59..D-64)

| Element | Copy |
|---------|------|
| Tab label | `Diff` — third tab: Agent, Description, Diff, Bash 1..N (D-64). Never gets a ×, never gets a leading dot |
| Disabled tab tooltip (no worktree) | `The diff needs a worktree` — mirrors Phase 3's `Bash sessions need a worktree`; trigger wrapped in a span so the tooltip fires on the disabled trigger |
| Totals bar | `{N} files changed, +{A} −{B} vs {base}` — `1 file changed` singular; a zero-count `+0` or `−0` segment is omitted; `{base}` in mono. Uses the true minus sign `−` (U+2212) in stats, matching D-60 |
| Refresh button | Icon-only ghost (`refresh-cw` 16px), tooltip + aria-label `Refresh diff`. While refetching: disabled, icon spins (`animate-spin`, `motion-reduce:animate-none`) |
| File header stats | `+{x}` `−{y}` (12px/500 tabular-nums, colored per palette); zero segments omitted |
| File status suffixes | Muted 12px label after the path: `new` (untracked — rendered as full additions, D-59), `deleted` (removed files). Modified files get no suffix |
| Binary file | Header shows path + muted 12px `Binary file changed` in place of ± stats; section is not expandable (D-62) |
| Empty state (D-63) | Single muted body line, centered: `No changes yet. The worktree matches {base}.` (`{base}` in mono). No heading, no CTA — quiet |
| Loading (first load, no data) | Centered muted body: `Loading diff…` — only shown if the fetch takes >150ms (Phase 2 no-flash rule) |
| Error | Centered: `Couldn't load the diff.` (14px body) + optional muted 12px line with the server-reported git error verbatim + `Retry` button (outline, small) |

### Silence contract (D-58, D-65)

| Element | Copy |
|---------|------|
| Post-restart reconciliation | **No copy.** No banners, no toasts, no notices anywhere. The UI reflects reality: gray exited dots (Phase 4 palette), Resume offered in the task view (D-57) |
| Post-restart bash sessions | **No copy, no stubs.** Bash tabs mirror live sessions (D-28) and none are live — they simply are not rendered |

## Interaction Contract

States the executor must implement; the auditor will check these.

### Resume / Reset lifecycle

| Interaction | Contract |
|-------------|----------|
| Resume (D-55) | Click `Resume session` → POST resume → server spawns `claude --resume <uuid>` in the task's worktree using the persisted `tasks.claude_session_id` → pane attaches in place (pre-start block swaps to TerminalPane, or the banner clears and the fresh session replaces the dead one). Goes through the same one-agent-per-task 409 gate (D-67) |
| Reset | Phase 4 contract verbatim: fresh claude spawn, new UUID overwrites the stored one (newest conversation wins, D-55). Remounts the pane (existing `key={session.id}` mechanism) |
| Both placements behave identically (D-54) | Banner pair and pre-start pair trigger the same two mutations; one consistent pair everywhere a resumable session exists |
| Resume failure (D-56) | The resumed session attaches normally, claude prints its error and exits → standard exited flow: dimmed terminal, banner returns with `Reset session` only (server reports `resumable: false` after a failed resume). The user reads claude's error in the frozen output — honest, no masking |
| Mutual exclusion | While either Resume or Reset is in flight, both buttons disable (prevents double-spawn racing the 409 gate) |
| Post-restart dots (D-57) | Resumable tasks show the normal muted exited dot (zinc-600 / red-500 per Phase 4) — no new dot states, no pulse, no badge. The Resume affordance lives only in the task view |

### Diff tab

| Interaction | Contract |
|-------------|----------|
| Tab placement (D-64) | `Agent, Description, Diff, Bash 1..N, +` — Diff inserted via the existing `TabDef[]` array. Always present; disabled (zinc-600 label, not clickable) when the task has no worktree, with the explanation tooltip |
| Fetch policy (D-61) | Fetch on tab activation + manual refresh button. **No polling, no auto-refresh.** Re-activating the tab refetches |
| Refresh with data present | Current diff stays visible while refetching (no blanking, no layout jump); refresh button disabled + spinning. On success, content swaps in place; expand/collapse state resets to defaults (acceptable — the file set may have changed) |
| Expand/collapse | Entire file header row is the toggle (Radix Collapsible trigger): click or Enter/Space toggles; chevron rotates 90° when open; header gets the accent focus-visible ring on keyboard focus; hover lightens the header one step (`#27272a`, Phase 1 rule) |
| Default state (D-62) | Files expanded by default. Files with >400 changed lines start collapsed (header + stats only). Binary files render header-only, not expandable |
| Read-only (REVW-01) | Diff text is selectable and copyable; no per-line actions, no staging, no comments. Long lines do not wrap — each file body scrolls horizontally (`overflow-x: auto`), preserving line integrity |
| Worktree removed while Diff is open | After Phase 3 cleanup, the Diff tab disables in place; if it was active, activate the Agent tab (Phase 4: Agent is the universal fallback) |
| Empty / loading / error | Per Copywriting; all three render centered in the diff content area, 2xl vertical padding for empty state |

### Reconciliation (D-65)

| Interaction | Contract |
|-------------|----------|
| Startup reconciliation | Entirely server-side and silent. The frontend has **zero** reconciliation UI — its only observable effects are exited dots, the resumable pre-start variant, and absent bash tabs |
| No double-resume (D-67) | If a second client (or tab) races Resume, the 409 response surfaces as the standard inline spawn failure; the winning session attaches normally on the next sessions refetch |

Focal point: on the resumable pre-start state, `Resume session` is the only inverted high-contrast element — the eye lands on continuing the work. In the Diff tab, the colored ± lines are the loudest elements by design; all diff chrome stays neutral so the changes themselves carry the page.
