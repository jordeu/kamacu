<objective>
Add the Part-2 startup hook (`migrate.Complete`) that runs after the schema migration: rewrite the
DB path values under the old root (D-15, MIGRATE-02), repair every managed repo's worktree link files
with `git worktree repair` (MIGRATE-02), and delete the retired `kangent-*` tmux rows (D-07/D-08,
MIGRATE-03). Every step self-gates on observable state so a mid-migration crash rolls forward on the
next boot with no marker file (D-04).

Purpose: The dir moved atomically in Plan 21-02, but four kinds of state still point at the old path
that a filename grep never surfaces — the DB's stored absolute paths and git's two-way worktree link
files. Two RESEARCH findings are load-bearing: `git worktree repair` with NO args is a no-op when both
repo and worktrees move together (pass the explicit new paths, os.Stat-filtered so git never exits 1),
and the rewrite must gate on the `managed` flag + old-root prefix — NEVER a blind string replace, or a
user's external repo living at e.g. `/home/u/dev/kangent-thing` gets corrupted.
Output: `internal/migrate/paths.go` + two test files. Wired into `main.go` in Plan 21-04.
</objective>
