<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem (`~/.kangent` / `~/.kamacu`) | Paths resolved from the process HOME, not from network input; the rename crosses no privilege boundary but is destructive-if-wrong |
| SQLite DB file + WAL | Committed user data lives partly in the hot `-wal`; the rename must preserve crash-recovery invariants |
| old `-L kangent` tmux server | OS process group holding retired shells; retired via CLI, arg-array only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-05-01 | Tampering (user data) | DB file rename with hot WAL | mitigate | `PRAGMA wal_checkpoint(TRUNCATE)` folds the WAL before the single-file rename (RESEARCH Pitfall 1, empirically proven); `-wal`/`-shm` removed after clean close |
| T-21-05-02 | DoS (unbootable half-state) | rename sequence | mitigate | Preflight (src exists, dst absent, same-fs Dev) runs BEFORE any mutation (D-02); rename is the commit point (D-03); on failure return error → refuse-to-boot (D-11) |
| T-21-05-03 | Tampering (partial move) | cross-device rename (EXDEV) | mitigate | `sameFilesystem` Dev-compare preflight + `errors.Is(err, syscall.EXDEV)`; copy-then-swap is out of scope (D-01) → refuse to boot, never fall back |
| T-21-05-04 | Spoofing/ambiguity | both-dirs-present anomaly | mitigate | Gate returns RefuseBoot; never guess which dir is authoritative — refuse to boot naming both (D-11) |
| T-21-05-05 | TOCTOU | dst-absent check → os.Rename | accept | Single-user local process; `os.Rename` itself fails if dst was created between check and call (that error → refuse-to-boot). Residual race only under the documented "old process still running" invariant (RESEARCH A1) |
| T-21-05-SC | Tampering | go module installs | mitigate | No new dependencies — stdlib (os/syscall/path/filepath) + existing in-tree packages only (RESEARCH Package Legitimacy Audit: N/A) |
</threat_model>
