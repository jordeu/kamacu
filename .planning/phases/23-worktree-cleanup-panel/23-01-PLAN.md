<objective>
Deliver the two genuinely-new backend pieces this phase needs, plus the additive
extensions to the shared removal core — all below the HTTP layer, so Wave 2's
handlers have a complete contract to call.

1. A `git worktree list --porcelain -z` parser in `internal/worktree` (no such
   parser exists in the repo today).
2. Two additive extensions to `CleanupWorktreeGated`: (a) an orphan mode
   (`taskID==0` skips the null-columns UPDATE), and (b) a D-01 permission-blocked
   outcome (`BlockedError` carrying the offending path) that is distinct from a
   generic error and never proceeds to a blanket `--force` retry.

Purpose: These are the only load-bearing new mechanisms in the phase. The
research verified both empirically against git 2.43.0 + the Go stdlib on this
machine; they are the source of truth. Everything downstream (enumeration,
classification, force-remove, bulk clean) composes these plus existing helpers.

Output: `List` + `Entry` in `internal/worktree/worktree.go`; `BlockedError` +
orphan/blocked branches in `internal/api/cleanup.go`; unit tests for both.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB/git-list data → git argv | Worktree paths originate from the DB and `git worktree list`; they flow into `git` only as argv elements via `gitRun`, never a shell string. |
| filesystem removal → unprivileged process | `wt.Remove` deletes real filesystem paths as the unprivileged Kamacu process; a foreign-uid subtree can block the delete. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Tampering / Elevation | `List` / `Remove` git calls | mitigate | Every git call uses the arg-array `gitRun` (`exec.CommandContext(ctx, "git", ...)`); no `sh -c`, no string interpolation of the repo/worktree path into a shell (Security Domain V5). |
| T-23-02 | Denial of Service | `CleanupWorktreeGated` on a foreign-uid worktree | mitigate | D-01 detection stops at the FIRST EACCES, returns the `blocked` outcome, and does NOT proceed to `--force` — never leaving the misleading deregistered "is not a working tree" shell (Pitfall 1). The git registration + DB row stay intact. |
| T-23-03 | Elevation of Privilege | the app itself | accept/mitigate | The app never runs `sudo`/`pkexec`; `BlockedError` only carries the offending path as data for a later user-copied hint. No privileged process is ever spawned (D-01). |
| T-23-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this plan. RESEARCH § Package Legitimacy Audit is a no-op (zero new packages). |
