<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → browser panel | The user triggers destructive removals from the panel; every destructive action is behind an explicit confirm dialog that names what will be destroyed. |
| browser → server | The panel only sends `{repo, path, task_id}` the server enumerated; the server re-checks gates and owns all deletion. |
| rendered sudo hint → shell | The `sudo rm -rf <path>` string is rendered as copyable text; it is NEVER executed by the app. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-12 | Elevation of Privilege | blocked-row sudo hint | mitigate | The `sudo rm -rf` string is passed only to `navigator.clipboard.writeText` — pure text for the user to copy. The app never spawns a process, never `eval`s, never shells the hint (D-01, Security V5). |
| T-23-13 | Tampering (destructive-action bypass) | ForceRemoveDialog / CleanEligibleDialog | mitigate | Force-remove is confirm-gated and type-to-confirm-gated when dirty (names uncommitted/unpushed/stash counts + sessions before committing); bulk clean previews the exact server-computed set and its CTA is non-destructive by construction (D-05). The server re-checks gates at remove time regardless of the client snapshot (Pitfall 4/8). |
| T-23-14 | Information Disclosure | XSS via a worktree/branch/path string | mitigate | All paths/titles/branches render as React text children (auto-escaped) or via `withMono` string-splitting — never `dangerouslySetInnerHTML`. A malicious path cannot inject markup. |
| T-23-15 | Repudiation / clarity | blocked outcome vs error | mitigate | A `{outcome:"blocked"}` response renders the informational banner (not a red error), and a real error renders the inline `Couldn't remove…` line — the two are visually distinct so the user is never misled about state (D-01). |
| T-23-SC | Tampering | npm installs | n/a | No package installs in this plan (the `badge` primitive was added in plan 23-04). RESEARCH § Package Legitimacy Audit: zero new packages. |
</threat_model>
