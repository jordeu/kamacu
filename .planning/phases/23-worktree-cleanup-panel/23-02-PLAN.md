<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → server | The panel POSTs a `{repo, path, task_id}` to remove; the server must only ever remove paths it ENUMERATED from `git worktree list --porcelain` at known project repo roots — never trust a client-supplied arbitrary path as authoritative. |
| server → filesystem/git | Removal deletes real paths as an unprivileged process and re-checks gates at remove time. |
| DB/git data → git argv | All paths flow into `git` via arg-array `gitRun`, never a shell. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-07 | Tampering (arbitrary-path deletion) | `remove` / `cleanEligible` handlers | mitigate | The server only removes worktrees it enumerated via `git worktree list --porcelain` at DB-known `repo_path`s. `wt.Remove` runs `git worktree remove <path>` — git refuses a path it does not manage as a linked worktree, and the main worktree is excluded (Pitfall 2). A client-supplied path that is not a registered linked worktree fails at git, not a raw `rm`. Never `os.RemoveAll` on a client path. |
| T-23-08 | Elevation / Tampering (command injection) | every git call | mitigate | All git invocations are arg-array `exec.CommandContext` via `gitRun`/service methods; no `sh -c`, no interpolation of `path`/`branch`/`repo` into a shell string (Security V5, established `gitRun` invariant). |
| T-23-09 | Tampering (confirmation-bypass race) | `remove` force path | mitigate | Force overrides the dirty/session gates, but `CleanupWorktreeGated` re-checks gates at remove time server-side (Pitfall 4/8); the client snapshot is advisory. The stop-then-kill-then-remove ordering prevents the orphan-shell hole. |
| T-23-10 | Denial of Service (undeletable shell) | D-01 blocked path | mitigate | On EACCES the handler returns 200 `{outcome:"blocked"}` and CleanupWorktreeGated does NOT proceed to `--force`; the registration + row stay intact so a retry after manual `sudo rm` succeeds. The `sudo rm -rf` string is data only — never executed (D-01). |
| T-23-11 | Elevation | bulk clean-eligible | mitigate | Bulk NEVER forces (force=false); it only touches provably-safe worktrees the server recomputed (D-04/D-05). A raced gate skips the item — never a silent destructive override. |
| T-23-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this plan (RESEARCH § Package Legitimacy Audit: zero new packages). |
</threat_model>
