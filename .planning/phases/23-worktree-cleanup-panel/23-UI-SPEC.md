# Phase 23 — UI Design Contract

> Visual and interaction contract for the Settings worktree-cleanup panel. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase extends an existing surface.** The panel is a **new `<section>` in the existing full-page Settings route** (`web/src/pages/SettingsPage.tsx`, D-09), rendered exactly like the Agent / Worktrees / Bash tabs / Branches / Cleanup / GitHub sections already there. It reuses the established design system — dark-only zinc ramp, the uppercase `text-xs` section-heading pattern, the `DiffTab` fetch-on-mount + manual-Refresh model (D-10 / D-61), and the `CleanupWorktreeDialog` confirm pattern. It does **not** introduce a new visual language. The panel is a dense, read-then-act admin table; there is nothing decorative to add.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `web/components.json`) |
| Preset | style `radix-nova`, baseColor `neutral`, `cssVariables: true`, no prefix |
| Component library | radix-ui `^1.5.0` (primitives copied into `@/components/ui`) |
| Icon library | lucide-react `^1.17.0` |
| Font (UI) | `ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif` (`--font-sans`) |
| Font (paths / branches / counts / sudo hint) | `ui-monospace, "SF Mono", "Cascadia Mono", Menlo, Consolas, monospace` (`--font-mono`) |
| Theme | Dark-only — `class="dark"` hardcoded on `<html>`; zinc ramp via oklch CSS vars (`web/src/index.css`) |

**Existing primitives reused (no new import):** `alert-dialog` (force-remove + bulk-preview confirms), `button` (has `outline` / `ghost` / `destructive` variants and `icon-sm` size), `tooltip` (icon-button labels), `skeleton` (loading rows), `separator` (project-group dividers, optional). The section-level state machine copies `SettingsField` / `GithubSection` idioms verbatim.

**New shadcn primitive required (one):** `badge` (shadcn official) — the classification chip (Referenced / Orphan / Stale pointer / Blocked) and the per-worktree flag chips (Dirty / Unpushed / Stash). Add with `npx shadcn add badge`. Do **not** hand-roll a `<span>` chip; use the primitive so variant styling is consistent. No `table`, `card`, or `scroll-area` primitive is needed — the panel is CSS-flex rows inside the existing `overflow-y-auto` Settings container, matching the rest of the page.

**Registries:** shadcn **official only**. No third-party registries declared (`components.json` `registries: {}`). Registry vetting gate: not applicable.

## Spacing Scale

Declared values (multiples of 4; matches the compact spacing already used across the Settings page and the diff tab):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `gap-1` between flag chips; icon↔label gap inside a chip; `mt-0.5`-style icon nudge in the blocked banner |
| sm | 8px | `gap-2` between a row's inline controls (badge ↔ flags ↔ Remove button); chip vertical padding |
| md | 16px | `p-4` — the Settings page's outer scroll padding (inherited, unchanged); dialog content padding |
| section | 12px | `gap-3` — the vertical rhythm INSIDE a Settings `<section>` (heading → controls → rows), the exact value every existing section uses |
| group | 24px | `gap-6` — the gap BETWEEN Settings sections and between per-project groups within the panel (matches the page's `gap-6` section stack) |

Exceptions: none. This is a desktop-only localhost admin surface — no 44px touch-target minimum applies. Row height is content-driven (target ~40px per worktree row, `py-2`); do NOT introduce 32/48/64px layout gaps inside the panel.

**Panel width:** inherits the Settings page's `max-w-[640px]` column (`SettingsPage.tsx`). The panel does NOT break out to full width — it is one more section in the same 640px column. Long paths truncate (`truncate` + `title` tooltip) rather than widening the column.

## Typography

The panel uses the **2 sizes + 2 weights** already established on the Settings page. There is no display/heading tier on this surface (the section `<h2>` is `text-xs`, matching every other Settings section); do not invent one.

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Section heading | 12px (`text-xs`) | 500 medium | ~1.33 | sans, `uppercase tracking-wide` | The `Worktrees` section `<h2>` — identical to `Agent` / `GitHub` headings |
| Row primary | 14px (`text-sm`) | 400 regular | 1.5 | mono | Worktree path (basename emphasized) / branch — paths always mono |
| Row secondary | 14px (`text-sm`) | 400 regular | 1.5 | sans | Task title / PR association text ("PR #123", "Task: …") |
| Label / chip / help | 12px (`text-xs`) | 500 medium (chip) / 400 (help) | ~1.33 | sans (chips), mono (counts) | Classification + flag chips; the `text-xs text-muted-foreground` help/empty/error lines that every Settings section already uses |
| sudo hint | 12px (`text-xs`) | 400 regular | 1.5 | mono | The copyable `sudo rm -rf <path>` string in the blocked banner |

Weights declared: **regular 400** (body/paths) + **medium 500** (section heading, chips, labels). No semibold, no bold anywhere on this surface — consistent with the whole Settings page.

## Color

Dark-only zinc ramp. Values are the existing CSS custom properties (oklch); hex annotations are approximate zinc equivalents.

| Role | Token / Value | Usage |
|------|---------------|-------|
| Dominant (60%) | `background` — oklch(0.141) ≈ zinc-950 `#09090b` | Settings page background, panel background, row background |
| Secondary (30%) | `card` / `muted` — oklch(0.21)/oklch(0.274) ≈ zinc-900/800 | Neutral chip fill (`secondary`/`muted` badge variant), row hover (`hover:bg-muted/50`), the project-group header strip |
| Accent (10%) | **not used** | This panel has **no positive accent color**. It is a neutral admin table; the only chromatic color it carries is the destructive/warning red reserved below. Do NOT add a blue/brand accent here. |
| Destructive / Warning | `destructive` — oklch(0.704 0.191) red | Force-remove `Button variant="destructive"`; the confirm dialog's `AlertDialogAction variant="destructive"`; the `Blocked` badge + blocked-row banner border/icon; the `TriangleAlert` warning glyph in a dirty/force confirm |

**No accent-reserved list needed** — the panel deliberately runs monochrome + one semantic red, matching the read-only, do-no-harm intent. Everything the user does here is either neutral (inspect, refresh) or destructive (remove) — there is no "primary happy path" element to paint blue.

### Classification & flag chip color semantics (status, NOT accent)

These are `badge` variants — muted by default, red only for the two states that demand attention. They must read as **quiet metadata**, never as calls to action.

| Chip | Badge variant | Color | Meaning |
|------|---------------|-------|---------|
| `Referenced` | `secondary` / `outline` | zinc (muted) | git-listed AND has a DB task — normal |
| `Orphan` | `outline` | zinc (muted) with `text-muted-foreground` | git-listed, no DB task (WTREE-04) — surfaced, not alarming |
| `Stale pointer` | `outline` | zinc (muted) | DB row whose dir is gone (D-07) — needs a "Clear pointer" action, not a remove |
| `Blocked` | `destructive` | red | D-01 permission-blocked shell — needs manual `sudo` removal |
| `Dirty` | `outline` | `text-amber-400` glyph + muted fill | uncommitted changes present (`DirtyCount > 0`) |
| `Unpushed` | `outline` | muted | commits not on the base ref (`UnpushedCount > 0`); render `Unpushed?` / `Unpushed —` when the base could not be resolved |
| `Stash` | `outline` | muted | stash entries present (`StashCount > 0`) |

- **Blocked row treatment:** the whole row gets a subtle `border-destructive/30` left accent (2px) and an inline banner below it (see Layout). Red is reserved for Blocked + destructive actions only — a plain Dirty/Unpushed worktree is amber/muted, not red (it is still safe to force-remove after a confirm; it is not an error state).
- **Eligible-for-bulk hint (optional, subtle):** a worktree the bulk action would remove MAY carry a quiet neutral marker (e.g. a `Check` glyph in `muted-foreground` or a faint left rule). Do NOT paint it green — green is unused on this surface. The authoritative list of what bulk will remove is the preview dialog, not a per-row color.

## Layout & Interaction Contract

This is the substance of Phase 23. The panel is one Settings `<section>` containing a header row (title + count + Refresh + bulk action) and a per-project grouped list of worktree rows, plus two confirm dialogs.

### Section shell (D-09)
- A new `<section className="flex flex-col gap-3">` in `SettingsPage.tsx`, appended to the existing section stack (component: `WorktreeCleanupSection.tsx`).
- **Section heading:** `<h2 className="text-xs font-medium tracking-wide text-muted-foreground uppercase">Worktrees</h2>` — byte-identical styling to the other section headings. (The existing `Worktrees` heading governs the `worktree_base` field; this new section may read `Worktree cleanup` to disambiguate — planner's call, but keep the exact heading class.)
- One `text-xs text-muted-foreground` help line under the heading stating what the panel does and that it never deletes branches (D-02): e.g. `Every git worktree across all projects. Removing a worktree never deletes its branch.`

### Header controls row (WTREE-01 / WTREE-03 / D-10)
A single flex row: `[title/count (flex-1)] [Refresh icon-btn] [Clean eligible btn]`.
- **Refresh** — `Button variant="ghost" size="icon-sm"`, lucide `RefreshCw`, `aria-label="Refresh worktrees"`, wrapped in a `Tooltip`. While `isFetching`, the icon spins: `className={isFetching ? "size-4 animate-spin motion-reduce:animate-none" : "size-4"}` — the EXACT DiffTab pattern (D-10 / D-61). No polling / no `refetchInterval`.
- **Clean eligible** — `Button variant="outline" size="sm"`, label `Clean eligible` (lucide `Trash2` or `Sparkles` optional, muted). Disabled while the list is loading, while a mutation is in flight, or when the eligible set is empty. Clicking opens the **preview** dialog (never removes directly — D-05).
- **Count:** `text-sm text-muted-foreground`, e.g. `12 worktrees · 3 orphaned`. Uses the fresh server payload, not a stale cache.

### Per-project grouping (D-06)
- Worktrees are **grouped by project** (union scan across all repos). Each group is a small header: the project name (`text-sm`) — optionally the project's `ProjectAvatar` monogram (already a shared component, `web/src/components/ui/ProjectAvatar.tsx`) at `size-4`/`size-5` for a quiet at-a-glance grouping — followed by that project's rows. Groups are separated by `gap-6` (or a `Separator`).
- The **main worktree (repo checkout itself) is excluded** from the list — it is not removable (Research Pitfall 2). Only linked task/PR/orphan worktrees appear as rows.

### Worktree row (WTREE-01)
Layout — a flex row, min-height ~40px, `px-1 py-2`, `hover:bg-muted/50`, `gap-2`:

```
[classification badge] [path (mono, flex-1, truncate + title tooltip)] [flag chips…] [assoc text] [Remove ▸]
```

- **Classification badge** first (Referenced / Orphan / Stale pointer / Blocked) — the primary at-a-glance signal.
- **Path** — `font-mono text-sm truncate`, basename may be emphasized; full path in a `title` tooltip (paths can be long; the 640px column truncates).
- **Association** — `text-sm text-muted-foreground`: `Task: <title>` for a referenced task worktree, `PR #<n>` for a `github_pr` worktree, or nothing for an orphan. If PR state is known, a quiet suffix (e.g. `PR #123 · merged`); if PR state is unavailable (gh off/absent), omit the state suffix silently (Research Open Q1) — never show a broken/error chip for a missing gh call.
- **Flag chips** — `Dirty` / `Unpushed` / `Stash`, only when the corresponding count > 0 (a pristine worktree shows no flag chips — quiet by default).
- **Row action** — one control per row:
  - Referenced / Orphan → **Remove** `Button variant="destructive" size="sm"` (label `Remove`), opens the **force-remove confirm** dialog. Both Referenced and Orphan use the SAME Remove control (D-03: force is the single per-item override).
  - Stale pointer → **Clear pointer** `Button variant="outline" size="sm"` (label `Clear pointer`) — NOT destructive-red (it deletes no worktree, only nulls the DB pointer + prunes the stale git registration, D-07). Behind a lightweight confirm (see Dialogs) or a direct action with an undo-free toast — planner's call; a confirm is preferred for consistency.
  - Blocked → **no active Remove**; instead the row expands the blocked banner (below). Optionally a disabled Remove with a tooltip `Needs manual removal`.

### Blocked-row banner (D-01 — the load-bearing case)
When a worktree is `Blocked` (or a remove attempt returns the `blocked` outcome), render an inline banner beneath the row (NOT a modal, NOT a raw error):
- `border-l-2 border-destructive/40`, `bg-destructive/5`, `p-3`, `rounded-md`.
- A `TriangleAlert` (`size-4 text-destructive`, `mt-0.5 shrink-0`) + a two-line message:
  - Line 1 (`text-sm`): `Blocked — needs manual removal.` then the offending path (`font-mono`), e.g. `A directory inside this worktree is owned by another user and can't be removed by Kamacu.`
  - Line 2 — the copyable hint: a `font-mono text-xs` code line showing `sudo rm -rf <path>` next to a `Button variant="ghost" size="icon-sm"` with lucide `Copy` (`aria-label="Copy command"`), which calls `navigator.clipboard.writeText(\`sudo rm -rf ${path}\`)` and briefly swaps to a `Check` glyph / `Copied` on success. **The app never runs the command** — it only renders the text for the user to copy (D-01, Security Domain).
- The git registration and DB row stay intact — the row remains listed as `Blocked` until the user clears the foreign dir manually and refreshes.

### Empty & loading states
- **Loading:** on section open (or Refresh with no prior data), render 3–4 `Skeleton` rows (`h-8 w-full`, `gap-2`) — mirror the `SettingsPage` skeleton block. On a Refresh with data present, keep the current rows and spin only the Refresh icon (do not blank the list).
- **Empty (no removable worktrees):** a single `text-sm text-muted-foreground` centered line — see Copywriting.
- **Load error:** the section renders a `text-xs text-destructive` line + an inline `Retry` (`Button variant="outline" size="sm"`) — mirror the `SettingsPage` `Couldn't load settings.` / `Retry loading` pattern. Do NOT blow away the whole Settings page for one section's failure.

### Force-remove confirm dialog (WTREE-02 / D-03)
An `AlertDialog` mirroring `CleanupWorktreeDialog.tsx`. It composes from **fresh server state at open** (Pitfall 4/8 — never the list cache), and **names exactly what will be destroyed** before the user commits:
- **Title:** `Force-remove this worktree?`
- **Body variants** (compose, like the existing dialog): the worktree path (mono); if sessions running → `N session(s) running in this worktree will be stopped.`; if dirty → a `TriangleAlert` line `This worktree has N changed file(s) with uncommitted work. Removing it permanently deletes those changes.`; if unpushed/stash → a plain line naming the counts (`M unpushed commit(s)` / `1 stash entry`); ALWAYS a final reassurance line `The branch <name> is kept.` (D-02/D-34 — mono branch).
- **Type-to-confirm gate:** when the worktree is dirty (uncommitted work at risk), require typing the worktree directory basename to confirm — the EXACT gate `CleanupWorktreeDialog` uses (`gateOpen = dirty === 0 || confirmText === target`). A clean-but-orphan worktree needs no type-gate (nothing at risk), just the confirm button.
- **CTA:** `AlertDialogAction variant="destructive"`, label `Force-remove` (or `Stop sessions and force-remove` when sessions are running); pending label `Removing…`. Dialog stays open until the mutation lands; a `blocked` outcome closes the dialog and surfaces the blocked banner on the row (not a red error); a real error renders inline `Couldn't remove the worktree: <message>`.
- **Cancel:** `Cancel` (dismisses, does nothing — D-32/D-01 no silent side effects).

### Clean-eligible preview dialog (WTREE-03 / D-05)
An `AlertDialog` that **previews the exact set** the bulk action will remove, computed server-side (never forces — D-04):
- **Title:** `Clean eligible worktrees?`
- **Body:** a short intro line + a scrollable list of the worktrees to be removed, each showing project · path · why-eligible (`Orphaned`, `Done`, `PR merged`, `PR closed`). If the set is empty, the button was disabled and this dialog does not open.
- A reassurance line: `Only worktrees with no running session, no uncommitted changes, no unpushed commits, and no stash are removed. Nothing is forced; anything blocked or with unsaved work is skipped.`
- **CTA:** `AlertDialogAction` — label `Remove N worktrees` (NOT `variant="destructive"`, because by construction nothing destructive is touched; use the default/primary action styling). Pending: `Cleaning up…`.
- **Result:** the action is best-effort per item (Research A6); after it lands, refetch the list (invalidate the `["worktrees"]` query). If any item raced into a tripped gate and was skipped, it simply remains in the refreshed list (no error modal); optionally a quiet `text-xs text-muted-foreground` summary line `Removed X of Y; Z skipped.`

### Clear-stale-pointer confirm (D-07)
A lightweight `AlertDialog` (not destructive-red): title `Clear stale pointer?`, body `The task's worktree link points to a directory that no longer exists. This clears the link and prunes the stale git registration. The task and its branch are kept.`, CTA `Clear pointer`.

### Fetch policy (D-10 / D-61) — hard rules
- One query `useWorktreeList()` (`queryKey: ["worktrees"]`), fetch-on-mount, `refetch()` on the manual Refresh button, **no `refetchInterval`** — the exact `useTaskDiff` shape. N git calls happen server-side per GET; the client stays dumb.
- Every mutation (`remove`, `clean-eligible`, `clear-pointer`) invalidates `["worktrees"]` on settle so the list reflects reality (Pitfall 4).
- Re-check gates server-side at remove time — the client snapshot is advisory only.

**Destructive actions in this phase (each confirm-gated, none silent):**
1. **Force-remove a worktree** — `AlertDialog`, dirty ⇒ type-the-dirname gate, names uncommitted/unpushed/stash counts + running sessions; branch always kept.
2. **Clean eligible (bulk)** — preview `AlertDialog` listing the exact set; by construction touches only provably-safe worktrees, so it is never destructive (D-05), yet still confirm-gated.
3. **Clear stale pointer** — lightweight confirm; deletes no files, only nulls the DB link + prunes the git registration (not red).

The `sudo rm -rf` string is **rendered text only** — the app never executes it (D-01, Security Domain V5).
