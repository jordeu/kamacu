# Phase 16 — UI Design Contract

> Visual and interaction contract for the Sharper Review Column. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase modifies two existing components — it does NOT introduce a new design system.** Every token below is read out of the live codebase (`web/src/index.css`, `PRCard.tsx`, `ReviewColumn.tsx`, `StatusDot.tsx`, `TaskCard.tsx`, `Column.tsx`). The contract's job is to *pin the exact values* for the locked decisions in `16-CONTEXT.md` (D-01 through D-15) and to fill the genuinely-unspecified gaps (icon sizing/alignment, the full session-border state matrix, the Recently-reviewed subheader, the complete state matrix). Do not invent values not derivable from existing patterns.

## Spacing Scale

The project is on the Tailwind 4-based scale (every utility step = 4px). The values this phase actually touches:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| 0.5 | 2px | Icon top-nudge for optical baseline alignment (`mt-[2px]` on the ↗ link — preserved) |
| 1 | 4px | Inter-row gap inside a card (`gap-1`), in-flight/error note top-margin (`mt-1`) |
| 1.5 | 6px | Dot/icon top-nudge to align with the first title line (`mt-[6px]` — preserved from existing dot) |
| 2 | 8px | Card row gap (`gap-2`), card list vertical gap (`gap-2`), subheader gap |
| 3 | 12px | Card horizontal padding (`px-3`), column list padding (`p-3`) |
| — | 14px | **CI icon + agent-dot-cluster optical size** (`size-3.5`) — matches the existing ↗ link and column chevrons |

**Exceptions:** none beyond the two optical-nudge utilities (`mt-[2px]`, `mt-[6px]`) that already exist in the codebase to vertically center small glyphs against the first line of a 2-line clamped title. These are inherited, not introduced.

**Hard rule (CHECK-02 / dotless-card discipline):** no element in this phase may reserve a fixed-width gutter for an absent icon or dot. When `checks === "none"` or there is no agent session, the element renders **nothing** — siblings reflow, there is **zero layout shift** between a card with and without the signal. This is enforced by conditional render (`pr.checks !== "none" && …`, `entry && …`), never by an opacity-0 placeholder.

## Color

Dark-only zinc ramp from `.dark` in `index.css`. The 60/30/10 split for the Review column surface:

| Role | Value (resolved) | Usage |
|------|------------------|-------|
| Dominant (60%) | `bg-[#101013]` (column list container) + `--background` oklch(0.141 …) page | Column scroll-area background, app background |
| Secondary (30%) | `bg-card` (`--card` oklch(0.21 …), ≈ zinc-900) | PR cards, collapsed-rail count pill; hover lifts to `#27272a` (zinc-800) |
| Accent (10%) | see reserved-for list below | Status signals only — never chrome |
| Destructive | `text-red-500` / `--destructive` | CI fail icon; the existing "Couldn't open this review." inline error |

**Accent reserved for (exhaustive — these are the ONLY colored elements this phase adds; everything else stays `text-muted-foreground` / `border-border`):**

1. **CI status icon** (one per card, only when `checks !== "none"`) — a *bare lucide glyph, no enclosing ring/badge*:
   - pass → `Check`, `text-green-500`, tooltip "Checks passing"
   - fail → `X`, `text-red-500`, tooltip "Checks failing"
   - running/pending → `Circle` (thin outline, no fill), `text-amber-500`, tooltip "Checks running" — **static, NO spinner / NO `animate-spin`**
   - `none` → renders nothing (no icon, no gutter)
   - Size `size-3.5` (14px). (D-01/D-02/D-03)
2. **Agent status dot** (one per card, only when a linked agent-status entry exists) — the reused `StatusDot`, palette unchanged: working `bg-green-500`, waiting `bg-amber-400 animate-pulse`, idle `bg-zinc-400`, exited `bg-zinc-600` (clean/stop) or `bg-red-500` (nonzero exit). 8px (`size-2`). (D-04/D-05)
3. **Open-session left border** (the only border-color change) — see the state matrix below: blue for "I have a session here," pulsing amber for "needs my input." (D-06/D-07)
4. **Stale footer** — existing `text-amber-400` "error · N old" line (unchanged).
5. **Degraded warning** — existing `TriangleAlert` `text-amber-400` (unchanged).
6. **Focus ring** — existing `focus-visible:ring-blue-500` on the card button (unchanged). Note: this blue focus ring already exists and is distinct from the new blue session border (ring vs. left edge) — both may appear together without conflict.

**Color discipline guardrails for the checker:**
- Amber now carries **two** meanings on a card simultaneously possible: a *pulsing-amber left border* = agent waiting, and a *static amber `Circle`* = CI running. These are deliberately different shapes/positions (left edge vs. inline glyph) and different animation (pulse vs. none) — they do not collide. The amber CI icon uses `text-amber-500`; the amber dot/border use `amber-400` — keep these as specified (icon a half-step deeper than the dot) so the two ambers are not pixel-identical.
- Green/red are used *only* for CI pass/fail (icons) and the green working-dot / red exited-error-dot. No green/red chrome, buttons, or text elsewhere in the column.
- The agent dot and the CI icon are independent signals: a card may show a red-fail CI icon next to a green working dot. That is correct and intended (CHECK-01's whole point — free the dot vocabulary for agent state).

## Card Row Contract (locked layout — D-01, Claude's-discretion ordering resolved)

Single row, `flex gap-2`, left-to-right:

```
[ title  flex-1 line-clamp-2 ] · [ StatusDot  if session ] · [ CI icon  if checks≠none ] · [ ↗ external link ]
```

- Mirrors the milestone preview `┃ title  ● ✓ ↗`.
- **Order is fixed:** agent dot *before* CI icon (dot is the "mine" signal, icon is the "its CI" signal — read self-state first). Both sit in the right-aligned cluster after the `flex-1` title.
- Each trailing element is independently conditional; any combination of {dot present/absent} × {icon present/absent} must render with no gutter and no shift.
- The ↗ link stays last, `stopPropagation` on click (opens GitHub only), `text-muted-foreground hover:text-foreground`, `size-3.5`, `mt-[2px]`.
- Dot and icon are non-interactive (a click on them falls through to the card's open-review handler); each is wrapped in a `Tooltip` for its label.
- Row 2 (meta line) is unchanged.

### Session-border state matrix (D-06/D-07 — the one genuinely-new visual; fills the "exact token" gap)

The card root keeps `rounded-md border bg-card px-3 py-2`. The **left edge** is driven *only* by the linked agent-status entry (`entry` = the agent-status row whose `prNumber === pr.number && projectId === projectId`). This **intentionally diverges from TaskCard's D-44** (which tints amber only on waiting and otherwise uses `border-border` all around).

| Session state | Left edge | Other 3 edges | Meaning |
|---------------|-----------|---------------|---------|
| No entry (no open session) | `border-border` (default, 1px) | `border-border` | dotless / unchanged — identical to a plain card |
| Entry exists, `status !== "waiting"` (working / idle / exited) | `border-l-2 border-l-blue-500/60` | `border-border` | "I have a review session here" — always-on, regardless of agent state |
| Entry exists, `status === "waiting"` | `border-l-2 border-l-amber-400` | `border-border` | "needs my input" — preserves the established waiting = amber meaning; pairs with the pulsing-amber dot |

Notes:
- Border thickness steps from 1px → 2px **only on the left** when a session exists; the other three edges stay 1px `border-border` so the card does not appear boxed-in. Achieve with `border border-border` as the base and override the left with `border-l-2 border-l-{color}`.
- The blue at `/60` opacity keeps the session edge present-but-quiet (it is an ambient "you're working here" cue, not an alarm); the waiting amber is full-opacity to read as the louder "act now" state. The waiting **border itself does not pulse** — the pulse lives on the `StatusDot` (`animate-pulse`), which the waiting card always shows; a pulsing border + pulsing dot would double-flash. (If the executor prefers the border to also pulse to match D-44's "waiting language," that is acceptable *only* via `animate-pulse motion-reduce:animate-none` to honor reduced-motion — but the dot pulse is the canonical waiting motion; default to a static amber border.)
- `motion-reduce`: the dot's pulse already carries `motion-reduce:animate-none` (inherited from `dotMeta`). No new motion is introduced by the border.
- Border + dot key on the **same** signal (the entry), so they always appear and disappear together (D-08), in **both** sections (D-05/SIGNL-03 — it's a property of `PRCard`, so the Recently-reviewed list gets it for free).

## Recently Reviewed Section (REVWD-01/04 — fills the subheader/divider gap)

Rendered **inside the same `bg-[#101013] … overflow-y-auto p-3` scroll container**, **below** the awaiting-review cards, as a labeled subsection — **not** independently collapsible (the whole column collapses as one).

Structure (in render order inside the existing list container):

1. Awaiting-review `PRCard`s (existing).
2. The stale footer, **if** stale (existing).
3. **Recently-reviewed subheader** — rendered **only when** `reviewed.length > 0` (quiet-omit, D-11): a thin divider + label row, e.g.
   - top spacing: `mt-2 pt-2 border-t border-border` (a hairline divider separating it from the awaiting list — reuses `border-border`, no new color)
   - label: `text-xs font-medium uppercase tracking-wide text-muted-foreground` reading **`Recently reviewed`** (sentence-case label, uppercase via class — matches the "REVIEW" header treatment exactly)
   - optional sub-count: a `text-xs font-medium text-muted-foreground` number after the label (Claude's-discretion D-11 → **include it**, for parity with the header count; it is the length of the `reviewed` array)
4. The reviewed `PRCard`s — same component, so they get the dot / session border / CI icon for free; ordered most-recently-updated first (server order, do NOT re-sort).

Rules:
- When `reviewed` is empty (or null/degraded): **render nothing** — no divider, no label, no count, no blank space. Same quiet-empty discipline as the column today.
- The **column header count stays the awaiting-review count** (unchanged). The reviewed sub-count is a separate, smaller affordance and never rolls into the header number.
- Drafts are excluded server-side (the `draft:false` search), so the frontend renders whatever `reviewed` contains without filtering.
- Dedup is server-side (REVWD-03): a PR present in `prs` is removed from `reviewed` before the response. The frontend trusts the two arrays as already-disjoint and renders both verbatim.

## State Matrix (the column, with the second list layered in)

The column reuses its existing loading/degraded/empty branches (`ReviewStates` in `ReviewColumn.tsx`); the reviewed list rides the **same** `state`/`stale`/`fetchedAt` (REVWD-04 — one fetch, one classified state, both lists degrade together).

| State | Awaiting list (top) | Recently-reviewed (bottom) | Notes |
|-------|---------------------|----------------------------|-------|
| Loading (first fetch, `data === undefined`) | 2× `Skeleton h-14 w-full` | nothing (no separate skeletons) | Quiet skeletons, no spinner, no overlay (unchanged). The reviewed section never shows its own loading shimmer. |
| Degraded + no cache (`no_gh`/`auth_required`/`error`, both lists empty) | existing `TriangleAlert` inline note | nothing | Both lists degrade as one; the reviewed subheader does not appear. |
| Degraded **with** cached data (`stale === true`, cache present) | render cached `prs` above the amber stale footer | render cached `reviewed` (if any) below | The column never goes blank because a refresh failed; both cached lists stay until the next clean read. |
| Empty (`state === "ok"`, `prs` empty AND `reviewed` empty) | "You're all caught up" / "No PRs are waiting for your review." | nothing | The existing empty copy stands. The reviewed section is omitted (not "no recently reviewed"). |
| Awaiting-empty but reviewed-present (`prs` empty, `reviewed` non-empty) | **show the "You're all caught up" empty block** | render the Recently-reviewed subheader + cards below it | The top section is genuinely empty (caught up on requests) while reviewed PRs still exist — the empty copy is honest and the reviewed list still renders. Do NOT suppress the empty block just because reviewed has items. |
| Populated (`state === "ok"`, `prs` non-empty) | render `prs` | render `reviewed` if non-empty | The steady-state happy path. |

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Click / Enter / Space on a card (either section) | Open-or-reattach the review via `useOpenReview` → navigate to `/projects/{id}/tasks/{task.id}` (unchanged; reused verbatim by reviewed cards). In-flight guard prevents double-open. |
| Click ↗ external link | `stopPropagation` → opens the PR on GitHub in a new tab only (unchanged). |
| Hover / focus a card | `hover:bg-[#27272a]`, `focus-visible:ring-2 focus-visible:ring-blue-500` (unchanged). Coexists with the new blue session left-border (ring is on focus, border is on session — different triggers, different edges). |
| Hover a dot / CI icon | Tooltip with the status label; the glyph is non-interactive and click falls through to open. |
| Manual refresh (header `RefreshCw`) | Re-fetches `?refresh=1`; the single response repopulates **both** lists (REVWD-04). |
| Auto-poll | 60s, visibility-paused (`refetchIntervalInBackground:false`); both lists share it. Agent dots/borders ride the separate shared 5s `useAgentStatuses()` poll (unchanged cadence — waiting surfaces within 5s). |

- The left border replaces the current static `border border-border` on the card root with: base `border border-border` + a conditional left override (`border-l-2 border-l-amber-400` when waiting, `border-l-2 border-l-blue-500/60` when any other session state, nothing extra when no entry). Mirror the `cn(...)` conditional shape from `TaskCard.tsx` but with the diverged three-way (D-06/D-07).
- The Recently-reviewed list comes from `data.reviewed` (D-13). Render it in `ReviewStates` after the awaiting `prs.map` and the stale footer, gated on `data.reviewed?.length`.
