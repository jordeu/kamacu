# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Sources: 03-CONTEXT.md decisions D-22..D-34 (locked), Phase 1 UI-SPEC (approved — design system foundation, dialog + copy patterns), Phase 2 UI-SPEC (approved — TerminalPane component contract carries forward **verbatim**), existing code (`TaskTabs.tsx` TabDef seam, `TaskPage.tsx` header/ellipsis menu, `TerminalPane.tsx`). Claude's discretion areas (exact dialog copy, tab affordances, worktree info placement) resolved below. No user questions were needed.

**Scope note:** This contract EXTENDS Phases 1–2; it never redefines them. Terminal internals (xterm theme, banners, connection states, Stop button) are the Phase 2 contract, untouched. Board columns/cards are the Phase 1 contract, untouched. This phase ADDS: (1) tab strip extensions — `+` spawn button and closeable bash tabs, (2) worktree presence surfaces in the task view — branch meta line, no-worktree states, (3) the cleanup dialog family, (4) the task-view cleanup menu action.

## Spacing Scale

Inherited from Phase 1 verbatim — xs 4 / sm 8 / md 12 / lg 16 / xl 24 / 2xl 32 / 3xl 48. The 12px `md` exception carries forward. No new exceptions.

Phase 3 applications:

| Token | Value | Usage this phase |
|-------|-------|------------------|
| xs | 4px | Gap between tab label and its × affordance; gap between `git-branch` icon and branch name; gap between warning icon and message text in dialogs |
| sm | 8px | Gap between the last tab and the `+` button; gap between no-worktree message and its button; vertical gap between dialog body paragraphs and the type-to-confirm block |
| md | 12px | Horizontal padding inside dialog warning rows |
| lg | 16px | Dialog internal padding (Phase 1 rule); bash tab content padding from main-area edges |
| xl | 24px | Gap between tab strip and tab content (existing `gap-6` in TaskTabs — keep) |

Hit-area note: the tab × affordance is a 16×16px icon target inside a tab trigger whose full row height (~32px) remains the effective hit area vertically; this is within the Phase 1 dense desktop-first 28px-minimum interactive-row convention — no touch-target exception needed.

## Color

Text: zinc-50 `#fafafa` / zinc-400 `#a1a1aa` muted / zinc-600 `#52525b` disabled. xterm theme: Phase 2 verbatim. Status-badge palette remains UNSPECIFIED (reserved for Phase 4) — **this phase introduces no new chrome colors, no amber/yellow "warning" hue.** Worktree trouble is communicated through the established destructive inline-error text pattern (Phase 1: `Not a git repository: {path}`) plus neutral icons, never a third hue.

| Element | Value |
|---------|-------|
| `+` spawn button | Ghost icon button — zinc-400 icon, hover surface one step lighter `#27272a` (Phase 1 hover rule). Disabled: zinc-600 icon, no hover |
| Tab × affordance | zinc-400 at rest; hover: zinc-50 text on `#27272a` rounded-sm background. Never red — closing a bash tab is routine (D-29), not a destructive ceremony |
| Closing/exited tab label | `text-muted-foreground` zinc-400 (matches Phase 2 exited-row muting — liveness by muting, not color) |
| Branch meta line | zinc-400 mono text + zinc-400 `git-branch` icon |
| Worktree-failed message | Destructive red-500 12px text (Phase 1 inline-error pattern) — message only; the `Retry creation` button is standard outline, not red |
| `No worktree yet.` message | zinc-400 muted body — absence is neutral, not an error |
| Cleanup dialog CTA (`Remove worktree` / `Stop sessions and clean up`) | Destructive variant (red-500 fill) — Phase 1 destructive-confirmation convention (`Delete task`) |

| Type-to-confirm input | Standard input, mono text; no red border states — the disabled CTA is the gate signal |

Accent reserved for (unchanged from Phase 1): focus-visible rings, active tab indicator, drag-over column, prose links. Bash tabs get the existing accent active-tab indicator for free (reservation #2). This phase adds **no** new accent uses.

## Copywriting Contract

Tone inherited: terse, sentence case, no exclamation marks, no "please". Branch and slug values always rendered in mono. Counts pluralize: `1 session running` / `3 sessions running`, `1 changed file` / `5 changed files`.

### Tab strip

| Element | Copy |
|---------|------|
| Bash tab label (D-27) | `Bash {N}` — N is the server-assigned per-task spawn ordinal, monotonic per task, never reused. (The `/terminal` dev rail keeps Phase 2's `bash #{N}` global label; the task tab strip uses the task-scoped form) |
| `+` button tooltip / aria-label | `New bash session` (verb implied by +; aria-label `New bash session`) |
| `+` disabled tooltip (D-30) | `Bash sessions need a worktree` — shown on hover of the disabled button (wrap in a span so the tooltip fires) |
| Tab × tooltip | `Stop and close` — closing a tab stops the session (D-29); the tooltip says so up front |
| Tab × aria-label | `Stop Bash {N} and close tab` |
| Spawn failure | Inline right of the `+` button, destructive 12px text: `Couldn't start a session. Try again.` (Phase 2 copy verbatim). Clears on the next spawn attempt or navigation |
| TerminalPane internals | Phase 2 contract verbatim — exited banner `Session exited (code {N})` with `New terminal` / `Close`, connection banners, `Stop`/`Stopping…`. The parent wires the banner's `New terminal` to spawn a new bash session in the worktree; the banner copy is NOT reworded (component portability, D-12) |

### Worktree presence (task view)

| Element | Copy |
|---------|------|
| Branch meta line | `task/{slug}-{id}` in 12px mono muted, `git-branch` icon left. Tooltip: the absolute worktree path (mono) — e.g. `~/.kangent/worktrees/my-repo/fix-login-42` |
| No worktree — creation failed (D-25) | Destructive 12px text: `Couldn't create a worktree: {git error}` + button `Retry creation` (outline, small). While retrying: button disabled, label `Creating…` |
| No worktree — never created (D-26: pre-Phase-3 tasks, post-cleanup tasks) | Muted body: `No worktree yet.` + button `Create worktree` (outline, small). While creating: disabled, `Creating…` |
| Ellipsis menu item (D-31) | `Clean up worktree` — neutral item above the existing destructive `Delete task`, separated by the existing separator convention. Rendered only when the task has a worktree |

### Cleanup dialog family (D-31/D-32/D-33/D-34)

One AlertDialog, title always `Clean up worktree?`; body composed from the worktree state fetched when the dialog opens. Every variant ends with the reassurance line — the branch is never deleted (D-34):

> `The branch task/{slug}-{id} is kept.` (branch in mono)

| Variant | Body | Confirm CTA | Cancel |
|---------|------|-------------|--------|
| (a) Clean tree, no sessions | `The worktree for "{task title}" will be removed.` + branch-kept line | `Remove worktree` (destructive) | `Cancel` — or `Keep worktree` when the dialog was triggered by a move to Done (the decline IS the choice being offered, D-31) |
| (b) Sessions running (D-32) | `{N} sessions running in this worktree will be stopped.` + `The worktree will be removed.` + branch-kept line | `Stop sessions and clean up` (destructive) | same rule as (a) |
| (c) Uncommitted changes (D-33) | Warning row (`triangle-alert` icon): `This worktree has {N} changed files with uncommitted work. Removing it permanently deletes those changes.` + branch-kept line + type-to-confirm block | `Remove worktree` (destructive) — **disabled** until the input matches | same rule as (a) |
| (d) Dirty AND sessions running | Variant (b) sessions line, then variant (c) warning row + branch-kept line + type-to-confirm block | `Stop sessions and clean up` (destructive) — **disabled** until the input matches | same rule as (a) |

| Element | Copy |
|---------|------|
| Type-to-confirm label (D-33) | 12px label: `Type {slug}-{id} to confirm` (target string in mono). Input: mono, empty placeholder, autofocus. Match is exact, case-sensitive. Target string = worktree directory name (e.g. `fix-login-42`) |
| In-flight CTA | Disabled, label `Cleaning up…` (covers stop-then-remove in one state — the grace window is invisible apart from the delay, matching Phase 2's Stop UX) |
| Cleanup failure | Inline destructive 12px text above the dialog footer: `Couldn't remove the worktree: {git error}` — dialog stays open, CTA re-enabled for retry |

## Interaction Contract

States the executor must implement; the auditor will check these.

### Tab strip & bash sessions

| Interaction | Contract |
|-------------|----------|
| Tab order | `Description` first (always), then bash tabs in spawn order (`Bash 1`, `Bash 2`, …), then the `+` button as the last element inside the strip row. Description never gets a × |
| `+` spawn (D-27) | Click → POST spawn (cwd = worktree, task-scoped) → tab appears AND becomes the active tab → pane attaches immediately. Button disabled while the request is in flight; no spinner |
| `+` disabled (D-30) | When the task has no worktree: `+` rendered disabled (zinc-600) with the explanation tooltip. No bash tabs can exist in this state |
| Tabs mirror sessions (D-28) | On task open, tabs render one-per-running-session for this task (server is source of truth), reattaching via Phase 2 replay. Default active tab on load is `Description`. The Phase 2 sessions-list polling keeps the set honest |
| Close tab (D-29) | Click × → stop request fires immediately (no confirmation — consistent with Phase 2 D-14 single-button Stop) → tab enters closing state: label muted, × disabled → on exit notification the tab is removed. If the closed tab was active, activate the left neighbor; if none, `Description` |
| Session exits on its own | Tab stays, label muted, pane shows the Phase 2 exited banner. Banner `Close` removes the tab (same neighbor-activation rule). Banner `New terminal` spawns a fresh bash session tab. On a later revisit, exited sessions produce no tab (D-28: running sessions only) |
| Hidden tab resize | Switching to a bash tab triggers the pane's fit-and-send (the TerminalPane hidden-tab guard already defers fitting until the viewport has dimensions) — switching tabs must never corrupt the TUI |
| Keyboard | Focused terminal consumes keystrokes; Esc goes to the PTY (Phase 2 rule). The task page's Esc-to-board already suppresses on textarea focus, which covers the xterm helper textarea. × affordances are tabbable with visible accent focus-visible rings |
| Tab overflow | Tabs never wrap; the strip scrolls horizontally if bash tabs exceed the width. No cap on tab count |

### Worktree presence

| Interaction | Contract |
|-------------|----------|
| Branch meta line | Single dense row directly under the task title row, above the tab strip: `git-branch` icon + branch in 12px mono muted. Tooltip shows the absolute worktree path. Text is selectable; no click action |
| No-worktree state (D-25/D-26) | Replaces the branch meta line in the same slot (failed → destructive message + `Retry creation`; absent → muted message + `Create worktree`). Task view is otherwise fully usable — git problems never block the Description tab |
| Retry / Create worktree | Click → button disabled `Creating…` → success: row swaps to the branch meta line and `+` enables. Failure: row shows the failed variant with the fresh git error |
| Layout change | The task page container goes full-width; the header row, meta line, and Description tab content keep an inner 860px max-width (prose comfort, Phase 1). Bash tab content is exempt: it fills the full main-area width and the viewport height below the tab strip (min-height 320px) — terminal real estate is the point. The TerminalPane keeps its 1px zinc-800 border + radius inside the tab (Phase 2 framing) |

### Cleanup flow

| Interaction | Contract |
|-------------|----------|
| Trigger on Done (D-31) | Fires on every transition INTO Done (drag or status change) while the task has a worktree, AFTER the move persists — the move itself is never blocked or rolled back by the dialog. Declining (button or Esc) does nothing further; re-entering Done prompts again |
| Trigger from menu (D-31) | `Clean up worktree` ellipsis item opens the same dialog; cancel button reads `Cancel` in this path |
| State fetch | Worktree state (dirty file count, running session count) is fetched when the dialog opens, not from stale cache — the variant shown reflects reality at confirm time |
| Type-to-confirm gate (D-33) | CTA disabled until exact match; Enter in the input activates the CTA only when enabled. Input value never pre-filled |
| Confirm | CTA disabled `Cleaning up…` → sessions stopped (if any) → `git worktree remove` + prune (D-34) → dialog closes → bash tabs are gone (their sessions were stopped) → the meta line slot shows `No worktree yet.` + `Create worktree`, and `+` disables |
| Failure | Dialog stays open with the inline error; CTA re-enabled. Nothing is retried automatically |
| Never silent (D-32) | There is no code path that stops sessions or removes a worktree without this dialog's explicit confirm |

Focal point: the task view's only inverted high-contrast elements remain dialog primary CTAs; within the cleanup dialog the destructive CTA is the focal point. The tab strip stays visually quiet — muted `+`, muted ×, accent only on the active-tab indicator.
