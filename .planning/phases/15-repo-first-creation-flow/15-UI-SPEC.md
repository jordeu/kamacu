# Phase 15 — UI Design Contract

> Visual and interaction contract for the repo-first Add-project flow. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Sources: 15-CONTEXT.md (LOCKED user decisions D-01..D-09 + Claude's-discretion resolutions), REQUIREMENTS.md RPROJ-01/02/03/04 + CKOUT-04, ROADMAP.md/STATE.md § "Phase 15: Repo-First Creation Flow" (goal + the Phase-14 atomicity contract the failure copy must reflect), Phase 10 UI-SPEC (the GitHub-surface design conventions — spacing/typography/color/copy/mono-identifier rules inherited verbatim) and Phase 11 UI-SPEC (additional inherited tokens), and existing source read directly during scout:
- `web/src/components/sidebar/AddProjectDialog.tsx` — THE dialog to evolve (current folder-only form: `Dialog sm:max-w-[480px]`, mono path `Input`, name `Input`, `text-xs text-destructive` inline error, `ApiError`→`sentenceCase`, 409-gets-a-period, `navigate(/projects/{id})` on success, disable-while-pending-or-empty).
- `web/src/components/sidebar/ProjectSettingsDialog.tsx` — the near-complete template for the gh-validated repo field (integration-on gate, `owner/name` mono `Input`, the destructive-alert-under-the-field box, the `repoEdited` don't-clobber guard, the `prevOpen`/`prevSuggestion` adjust-state-on-prop-change reset, exactly-one-of {error|help}).
- `web/src/components/ui/` inventory (confirmed present: `tabs.tsx`, `dialog`, `input`, `button`, `label`; no spinner component — verified 2026-06-15).
- `web/src/components/ui/tabs.tsx` — the chosen segmented-toggle primitive (`default`-variant `TabsList`, `bg-muted h-8 rounded-lg p-[3px]`, `flex-1` triggers).
- `web/src/components/task/DiffTab.tsx` — the established in-flight spinner idiom (`RefreshCw` + `animate-spin motion-reduce:animate-none`); no spinner library.
- `web/src/api/mutations.ts` (`useCreateProject` body `{ name?; repo_path }` — widen to also allow `{ repo }`), `web/components.json` (`registries: {}`), `package.json` (`lucide-react ^1.17.0`).

**Scope note:** This contract EXTENDS the existing `AddProjectDialog`; it never redefines the rest of the app. It covers EXACTLY ONE surface: the Add-project dialog gains (1) a top segmented toggle "GitHub repo | Local folder" when integration is ON, (2) a repo `owner/name` input mode with name-prefill, (3) a blocking clone-in-progress state, and (4) inline failure handling. The folder mode stays byte-for-byte unchanged, and when integration is OFF the dialog is byte-for-byte the current `AddProjectDialog` (no toggle, no repo field).

**Explicitly OUT OF SCOPE for this contract** (do not spec here): the description field (D-05 — captured server-side, surfaces later in Project settings, NOT in this dialog), live clone-progress streaming or a cancel button (CKUX-01 — deferred; D-06's blocking spinner is the v1.4 stand-in), the managed-checkout backend mechanics (Phase 14, shipped), and a repo-info lookup endpoint (D-05 — not chosen).

**No user questions were needed** — CONTEXT.md locks D-01..D-09 and the design system is mature. The single Claude's-discretion item (the segmented-toggle COMPONENT) is resolved below to the existing `ui/tabs.tsx`; all copy is resolved from the CONTEXT "Specific Ideas" + Phase 10 tone.

## Component Contract (phase-specific layout — prescriptive)

> The genuinely-undecided specific (CONTEXT "Claude's Discretion": the toggle COMPONENT) is decided here.

### Mode gate (D-01, D-02, D-04)
- Read the integration flag via `useSettings().github_integration?.value === "on"` (the `ProjectSettingsDialog` precedent — already implies `gh` present). `useGithubStatus()` is acceptable instead/additionally if the planner finds it cleaner, but the toggle's `useSettings` gate is the canonical one.
- **Integration ON:** render the segmented toggle at the TOP of the form, defaulting to `GitHub repo`. Below it, render the repo input block when `GitHub repo` is active, or the existing folder path block when `Local folder` is active. The Name field is shared (renders below the active input in both modes).
- **Integration OFF (D-02):** render NO toggle and NO repo field — byte-for-byte the current `AddProjectDialog` (path `Input` + Name `Input`). The repo-first UI must not mount at all.

### Segmented toggle (Claude's-discretion → DECIDED)
- Use the existing **`Tabs` / `TabsList` / `TabsTrigger`** from `web/src/components/ui/tabs.tsx`, `variant="default"` (the `bg-muted` pill rail). Two `flex-1` triggers: `GitHub repo` (value e.g. `"repo"`, the default) and `Local folder` (value `"folder"`). It is a CONTROLLED selection driving which input renders — the planner may use `Tabs` purely as the segmented control (driving local state) and render the input blocks outside `TabsContent`, or use `TabsContent`; either is contract-compliant as long as the visual is the `default`-variant segmented rail.
- Full dialog width; the active segment is the neutral raised pill from the primitive (no accent override). `aria-label="Project source"` on the group.
- **No new dependency, no new `ui/` file** — `tabs.tsx` is already present (verified 2026-06-15).

### Name prefill (D-04 — repo mode)
- In repo mode, the Name field **prefills from the `name` segment** of the typed `owner/name` (e.g. `seqeralabs/nf-aggregate` → `nf-aggregate`).
- **Never clobber a user edit:** mirror `ProjectSettingsDialog`'s `repoEdited`-style guard — track a `nameEdited` flag; once the user types in the Name field, stop auto-deriving. Use the project's adjust-state-on-change idiom (the `prevOpen`/`prev…` pattern), **no setState-in-effect** (the lint-clean reset rule).
- Trigger latitude (CONTEXT discretion): derive on a valid-looking `owner/name` (or lightly debounced as-you-type). Keep it simple — purely a local string parse, **no `gh` call** (D-09: no as-you-type network).
- A cleared Name is safe — the backend defaults to the repo name (`createByRepo` does `filepath.Base(dest)`), so a blank submit is valid.

### Submit + clone-in-progress (D-06)
- On submit in **repo mode**: POST `{ repo: ownerName.trim(), name: name.trim() || undefined }` (the widened `useCreateProject` body). While `createProject.isPending`: **disable all inputs and the toggle**, swap the primary button (or an in-form region) to the blocking affordance — the `Loader2`/`RefreshCw` glyph (`size-4 animate-spin motion-reduce:animate-none`, `text-muted-foreground`) + `Cloning {owner/name}…`. Keep the dialog OPEN. No cancel button (D-07 — live cancel deferred to CKUX-01).
- On submit in **folder mode**: POST `{ repo_path: path.trim(), name: name.trim() || undefined }` — unchanged shape; disable-while-pending as today. (Folder creation is fast; the `Cloning…` copy is repo-mode-only.)
- The primary `Add project` is disabled when `isPending` OR the active mode's required input is empty (repo mode: empty `owner/name`; folder mode: empty path — mirrors the existing `repoPath.trim() === ""` guard, generalized per mode).

### Failure + success (D-07, D-08)
- **Failure:** catch `ApiError` → `sentenceCase`; 409 gets the trailing period; render in the destructive-alert box (`ProjectSettingsDialog` style); keep the dialog OPEN; preserve all field values + the active mode. Re-enable the inputs and toggle. Non-`ApiError` → the `Couldn't add the project. Try again.` fallback.
- **Success:** close the dialog, clear the fields, and `navigate(/projects/{id})` (verbatim current behavior). Invalidate the `["projects"]` query (already in `useCreateProject.onSuccess`).

### Reset on open/close (lint-clean idiom)
- On open: default the toggle to `GitHub repo` (when integration on), clear inputs, clear `nameEdited`/`repoEdited`, clear any error. Switching modes mid-dialog clears the error (mirror `ProjectSettingsDialog`'s `onChange` `setError(null)`). Use the `prevOpen` adjust-state-on-change pattern — **no `useEffect` setState**.

## Interaction Contract

States the executor must implement; the auditor will check these.

| Interaction | Contract |
|-------------|----------|
| Render gate (RPROJ-04, D-02) | `github_integration === "on"` → toggle + repo mode available, defaulting to `GitHub repo`. `=== "off"` → byte-for-byte the current folder-only `AddProjectDialog`: no toggle, no repo field, no repo-first code path mounted |
| Mode switch (D-01) | The segmented toggle swaps the input block below (repo `owner/name` ↔ folder path). The Name field persists across the switch (shared). Switching clears any visible error. Repo mode is the default selection |
| Name prefill (RPROJ-02, D-04) | Repo mode: Name derives from the `name` segment of `owner/name`, editable, never clobbering a user edit (`nameEdited` guard). Pure local parse, no network |
| Validate timing (D-09, RPROJ-05) | **Submit only.** No as-you-type / on-blur `gh` calls. The backend's existing gh-validate runs inside the synchronous create. Syntactic-invalid (400), gh-unverifiable (400), clone-failure, and already-added (409) all surface in the same destructive box |
| Clone-in-progress (CKOUT-04, D-06) | Repo-mode submit → disable inputs + toggle, show the muted spinner + `Cloning {owner/name}…`, keep the dialog open until the synchronous create returns. No cancel (CKUX-01 deferred) |
| Failure (CKOUT-04, D-07) | Inline destructive-alert box, dialog stays open, field values + active mode preserved, inputs re-enabled. Phase-14 atomicity → no orphan row, no partial dir → the copy never implies a half-created project to clean up; it just shows the server reason and the user retries |
| Success (D-08) | Close, clear fields, `navigate(/projects/{id})`, `["projects"]` invalidated |
| Folder mode (RPROJ-03/04, D-03) | Behaviorally unchanged: `{ repo_path, name? }`, existing `validateRepoPath` path, existing error handling. Existing folder-based projects untouched |
| Description (D-05) | **No description field in this dialog.** Description is captured server-side at create (best-effort, degrade-don't-break) and surfaces later, editable, in Project settings. The Add dialog shows no description input or preview |
| Mutation body | Widen `useCreateProject` to `{ name?; repo_path? ; repo? }` — exactly one of `repo` / `repo_path` is sent per active mode |
| Concurrency | Single-user app: no conflict UI |

Focal point: the dialog's only emphasized control remains the primary `Add project` button (standard primary). The segmented toggle is a calm neutral rail; the clone spinner is muted; errors are the boxed destructive alert. Nothing competes with the routine create CTA, and no new accent surface is introduced.
