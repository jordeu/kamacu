# Phase 12 — UI Design Contract

> Visual and interaction contract for **Open-a-Review**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Governing principle:** this phase is **NOT net-new UI**. A PR review is a `tasks` row with `source='github_pr'` rendered through the **same `TaskPage` shell + `TaskTabs`** (Agent / Description / Diff / bash). The contract below specifies only the small, specific deltas that branch on `source='github_pr'`, expressed in classes/tokens **lifted verbatim** from the existing task view and the Phase 11 PR card — **zero new tokens, zero new colors, zero new npm deps, no new layout.** Every value is the value the app already uses, re-stated so the executor matches, not reinvents. Locked decisions come from `12-CONTEXT.md` (D-01..D-13); the visual language to stay consistent with comes from `11-UI-SPEC.md`.

## Spacing Scale

Inherited from the task view — the de-facto Tailwind 4px base. Declared values in play this phase (all multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|

| sm | 8px (`gap-2`, `p-2`) | header element gap (`flex items-center gap-2`), card body inter-element gap, meta-line gaps, terminal viewport inset (`p-2`) |
| md | 12px (`px-3`, `py-2`) | PR card padding (`px-3 py-2`), terminal/banner header padding (`px-3`), worktree-meta-line horizontal rhythm |
| lg | 16px (`p-4`) | `TaskPage` outer padding (`p-4`), Diff/Description content padding |
| xl | 24px (`gap-6`) | `TaskPage` vertical section gap (`flex … gap-6 p-4`), `TaskTabs` `gap-6` |

Exceptions (verbatim sub-4 optical nudges that already exist — do NOT "correct"):
- Checks dot offset on the PR card stays `mt-[6px]`; the ↗ icon stays `mt-[2px]` (both verbatim `PRCard`).
- The checks dot is `size-2` (8px) and ↗ glyph is `size-3.5` (14px) — verbatim `PRCard` / quota footer.
- Static-title button padding `px-1 py-0.5` is lifted verbatim from the editable-title button so the read-only title sits at the same baseline as the editable one (no layout shift between task and review headers).

> The review reuses `TaskPage`'s exact paddings/gaps so a PR review and a task view line up pixel-for-pixel. Spacing is **inherited, not chosen**.

## Copywriting Contract

Voice: terse, factual, lowercase-where-the-app-is; match the existing task view and the quota/PR card quiet tone. Never alarm on a soft-dependency failure — degrade quietly, surface inline, never block.

| Element | Copy |
|---------|------|
| Primary CTA (open the review) | **none as a label** — the affordance is the **PR card body click** (D-02). The card has no button text; its open intent is conveyed by the hover surface + pointer cursor (see Component Contract). The ↗ stays "Open PR #{number} on GitHub" (`aria-label`, verbatim Phase 11). |
| Primary CTA (start the agent) | `Start agent` (verbatim `AgentTab`; `Starting…` while pending). **Unchanged from a task** — the only delta is the prefilled seed (below), not the button. |
| Seed prompt (prefilled, NOT sent — D-06/D-07) | `Review PR #<n> "<title>". Summarize the changes, then flag bugs, risky changes, and missing tests.` — interpolate the live PR number and title; single short instruction; not configurable this phase. Typed into the agent prompt on Start via the existing paste handle; the user edits and presses Enter to send (it is **never** auto-submitted). |
| Read-only PR title | the PR title verbatim from GitHub (`title` field). Non-editable (D-08). `title` attribute (hover tooltip) = the full PR title (so a `line-clamp`/`truncate` long title is still readable); **no** "Edit title" tooltip. |
| PR meta line | `#{number} · @{author} · {baseRefName}` followed by the ↗ "open on GitHub" link. Use `·` (middot) separators, mirroring `PRCard`. The base branch is the PR's own base (e.g. `main`, or a non-default base) shown as plain text in `text-muted-foreground`; render the base in `font-mono` to match `WorktreeMetaLine`'s branch treatment. |
| Description tab — empty PR body (D-11) | `No description.` (`text-muted-foreground`, verbatim the existing `DescriptionTab` empty copy) — but **without** the "Edit" button (read-only). |
| Description tab — populated | the PR `body` rendered read-only as markdown (`prose prose-invert prose-sm`), **no** "Edit" button, no Textarea, no Save/Cancel. |
| Diff tab — empty | `No changes yet. The worktree matches <base>.` (verbatim `DiffTab`; `<base>` is the PR base in `font-mono`). |
| Loading — provisioning the worktree on first open (Claude's Discretion, decided here) | A quiet, **non-blocking** inline state inside the review shell while `git fetch refs/pull/<n>/head` + `worktree add --detach` runs. Copy: `Setting up the review worktree…` (`text-sm text-muted-foreground`, centered in the working area), shown only after a **150ms delay** (no flash — mirrors `TerminalPane`'s `showConnecting` and `DiffTab`'s `showLoading`). The header (back-arrow, read-only title, PR meta line) renders immediately around it. No spinner library, no modal, no overlay over the board. |
| Error — worktree provisioning failed (degrade-don't-break, decided here) | Inline, never a modal, never blocks the board. Copy headline `Couldn't open this review.` + secondary `Couldn't set up the worktree: {error}` (`text-sm` + `text-xs text-muted-foreground`/`text-red-500` for the detail — message carries the color, verbatim `WorktreeMetaLine` failed-state rule) + a neutral `outline`/`sm` **`Retry`** button. The user can always back out to the board (Esc / back-arrow) — the error never traps them. |
| Agent session error | `Couldn't start a session. Try again.` (verbatim `AgentTab`; 409 conflict copy rendered verbatim from the server, verbatim `TaskPage` trailing). |
| Destructive confirmation | **not applicable** — a PR review has no Delete and no destructive action in this phase (D-10; ⋯ menu omitted). Cleanup is Phase 13 (GHCLN-03). |

## Component Contract (phase-specific deltas — prescriptive)

> These are the genuinely-undecided visual specifics (CONTEXT "Claude's Discretion" + the locked deltas). They are now **decided** and locked here. All other task-view behavior is inherited verbatim.

### A. PR card — body becomes the open trigger (D-02)

The Phase 11 `PRCard` body was deliberately inert (Phase 11 D-08: "whole-card click reserved for Phase 12"). It now becomes the open/reattach affordance. Specify the new interactive affordances:

- **Surface:** keep `rounded-md border border-border bg-card px-3 py-2`. **Add** a hover surface change `hover:bg-[#27272a]` (verbatim the zinc-800 hover the task `CardRow` uses — the same neutral hover already in the design language; **never a hue**) and `cursor-pointer`. (Use `cursor-pointer`, not `cursor-grab` — a PR card is opened, never dragged; it is not a dnd item, D-13.)
- **Click target:** the whole card body opens/reattaches the review. Implement as an `onClick` on the card root, or wrap the two-row content in a focusable element so it is keyboard-reachable: `role="button"`, `tabIndex={0}`, Enter/Space activate, `aria-label="Open review for PR #{number}"`, and `focus-visible:ring-2 focus-visible:ring-blue-500` (verbatim the focus ring used by the tab × control and the terminal pane). Hover/focus must be visually equivalent (both reveal the clickable surface).
- **↗ stays the GitHub link and must `stopPropagation`** (D-02): the existing `<a href={pr.url}>` keeps `target="_blank" rel="noreferrer"` and `aria-label="Open PR #{number} on GitHub"`, and its `onClick` calls `e.stopPropagation()` so clicking ↗ opens GitHub and does **not** also open the review. Same for keyboard activation on the anchor.
- **Checks dot stays non-interactive** (D-02): the `role="img"` dot does not call `stopPropagation` and is not a click target — a click on the dot falls through to the card body (opens the review). Its tooltip behavior is unchanged.
- **No other change** to the card: same two-row layout, same meta line, same `size-2` dot at `mt-[6px]`, same ↗ at `size-3.5`. No diffstat, no fork pill (deferred GHCARD).

### B. Review view shell — read-only identity (D-08/D-09/D-10)

Branch `TaskPage` on `source === 'github_pr'`. The shell (outer `flex h-full w-full flex-col gap-6 p-4`, the `gap-6` header block, `TaskTabs`) is **unchanged**. Three header deltas:

1. **Back-arrow** — unchanged (`ArrowLeft`, `ghost`/`icon-sm`, `aria-label="Back to board"`, tooltip "Back to board (Esc)", routes to `/projects/{id}`). Esc-to-board is inherited verbatim.
2. **Read-only title replaces the editable-title button** (D-08). Render a non-interactive element in the title slot with the **same typography and box** as the editable button so there is zero layout shift: `min-w-0 flex-1 truncate text-base font-medium px-1 py-0.5 text-left`. **Remove** the `hover:bg-muted/50`, the `onClick`, the `title="Edit title"`, and the `type="button"` — make it a `<span>`/`<h1>`, not a `<button>`. Add `title={prTitle}` (full title on hover). The visible difference from the editable title: **no hover surface, no pointer cursor, no Edit affordance** — it reads as a label, not a control.
3. **`QuotaIndicator`** — unchanged (kept; the agent still consumes quota).
4. **⋯ menu OMITTED** for `source='github_pr'` (D-10): do not render the `DropdownMenu` trigger at all this phase. (No Delete-task, no Clean-up-worktree yet — Phase 13 re-adds a "Clean up worktree" item.) ↗ "open on GitHub" already lives in the PR meta line, so no single-item menu is needed.

### C. PR meta line — replaces/augments `WorktreeMetaLine` (D-09)

In the meta-line slot below the header, for `source='github_pr'` render a **PR meta line** instead of (or alongside) the worktree meta line. Layout echoes both `PRCard`'s meta row and `WorktreeMetaLine`'s dense single row:

- Container: `flex min-w-0 items-center gap-2 text-xs text-muted-foreground` (the `WorktreeMetaLine` density + the `PRCard` meta tone).
- Content left-to-right, `·`-separated:
  1. `#{number}` — `text-muted-foreground`.
  2. `@{author}` — `text-muted-foreground`.
  3. base branch — `font-mono text-muted-foreground` (mirrors `WorktreeMetaLine`'s branch treatment; this is the PR's own `baseRefName`, the diff base).
  4. ↗ **open on GitHub** — lucide `ExternalLink` `size-3.5` inside `<a href={pr.url} target="_blank" rel="noreferrer">`, `text-muted-foreground hover:text-foreground`, `aria-label="Open PR #{number} on GitHub"` (verbatim the `PRCard` ↗).
- **Worktree path (Claude's Discretion — decided):** keep the worktree branch/path available but **subordinate**. Show it as today's `WorktreeMetaLine` active row (`GitBranch size-3 text-zinc-400` + branch in `font-mono text-xs text-muted-foreground`, full path in tooltip) **after** the PR meta line (e.g. a second dense row, or `·`-appended). The PR identity reads first; the worktree path is secondary debug detail. Do not show the "Create worktree" / "Retry creation" affordances for a PR review — the worktree always exists by the time the review view renders (it is provisioned on open), so the absent/failed `WorktreeMetaLine` states do not apply here (provisioning failure is handled by the shell-level error state in §F).

### D. Tabs — feed PR-shaped content, add nothing (D-04/D-11)

- **Default tab = Agent** (D-04): reuse `TaskPage`'s `useState("agent")` verbatim — **no** source-based override. Carry D-39 forward.
- **Diff tab enabled immediately** (D-04): the worktree exists from the moment the review opens, so `"diff"` is in `tabIds` (the `task.worktree_path` gate is already satisfied). The Diff tab is the normal enabled tab, **never** the disabled/no-worktree variant. Its UI is unchanged; only its base ref is the PR base (server-side, `pr_base_ref` — no UI delta).
- **Description tab = read-only PR body** (D-11): render the PR `body` through the existing `prose prose-invert prose-sm max-w-none prose-a:text-blue-500` markdown block, **without** the "Edit" button, the Textarea, or Save/Cancel. Empty body → `No description.` in `text-muted-foreground` (verbatim copy) with **no** Edit button. This is review context and must not drift from GitHub.
- **Bash tabs** — unchanged (the `+` spawn, close-on-running, kept-mounted terminals all carry over verbatim).
- The `TabDef[]` array shape is unchanged — **no new `TabDef` field, no structural tab change** (the seam stays exactly as Phase 1 designed it).

### E. Agent Start — seeded, prefilled-not-sent (D-05/D-06/D-07)

- **Explicit Start** (D-05): the Agent tab opens on the existing pre-start banner (`No agent session` headline `text-xl font-medium`, body `text-sm text-muted-foreground`, `Start agent` primary). **Unchanged** from a task — opening a review does NOT auto-spawn `claude`.
- **Seed prefill on Start** (D-06): when the user clicks `Start agent` for a `source='github_pr'` task, after the session spawns and the terminal connects, the seed text is **typed into the agent prompt via the existing `pasteApiRef.current?.paste(seed)` handle** — the same imperative path "Insert description" already uses (`AgentTab` → `TerminalPane.onReady({paste})` → `term.paste()`, which xterm wraps in bracketed-paste `\x1b[200~..\x1b[201~` so claude receives it as a single un-submitted prompt). It is **prefilled into the input, never auto-sent** — the user reviews/edits and presses Enter.
- **Seed text** (D-07): `Review PR #<n> "<title>". Summarize the changes, then flag bugs, risky changes, and missing tests.` with the live PR number and title interpolated. Fixed template, not configurable this phase.
- **No new banner, no new button, no new copy** for the seed — the seed is a behavior on the existing `Start agent`, invisible until the agent is running and the prompt is populated. (Distinct from a normal task Start, which leaves the prompt blank.)

### F. Loading & error on open (Claude's Discretion — decided here)

Opening a review provisions a worktree (`gh pr view` + `git fetch refs/pull/<n>/head` + `git worktree add --detach`). This can take a moment on first open; reopening reattaches (D-03, instant, no provisioning).

- **Loading (first open, provisioning):** render the review shell immediately (back-arrow + read-only title + PR meta line from the PR summary the card already carries), and in the working area below show a **quiet, delayed, inline** loading state: `Setting up the review worktree…` (`text-sm text-muted-foreground`, centered), revealed only after **150ms** (mirrors `TerminalPane.showConnecting` / `DiffTab.showLoading` — no flash on a fast open). No spinner, no modal, no board overlay. Skeleton placeholders (`Skeleton`, verbatim the `TaskPage` `isPending` skeletons) are an acceptable alternative to the text line — pick one, not both.
- **Error (provisioning failed):** degrade-don't-break — inline, non-blocking, escapable. Headline `Couldn't open this review.` (`text-sm font-medium`) + detail `Couldn't set up the worktree: {error}` (`text-xs text-red-500` — message carries the color) + a neutral `outline`/`sm` **`Retry`** button (verbatim `WorktreeMetaLine` failed-state shape). Back-arrow / Esc always returns to the board. **Never** a modal, **never** blocks the board.
- **Reattach (D-03):** reopening a PR that already has a `source='github_pr'` row routes straight to the existing review (no provisioning, no loading state) — identity key `project_id` + `pr_number`. The transition is indistinguishable from opening an existing task.

## Interaction Contract

- **Open / reattach:** PR card body click → open/reattach the review (D-02/D-03). First open provisions (loading state §F); reopen reattaches instantly. The ↗ link `stopPropagation`s (opens GitHub only); the checks dot is non-interactive (falls through to open).
- **Default tab:** always Agent (D-04, verbatim D-39). Diff enabled immediately.
- **Read-only everywhere it mirrors GitHub:** PR title (D-08) and PR body/Description (D-11) are non-editable — they must not drift from GitHub. The Diff base is the PR's own base (D-12) — a UI no-op (server-side), but the base shown in the Diff totals bar / empty state must be the PR base, not the project default.
- **No board leak (GHREV-04, D-13) — UI-side guarantee:** a `source='github_pr'` review is reached **only** via the Review column card body. It is never rendered as a kanban card, never dragged, never dropped, never calls `/move`. (The authoritative guard is the backend `WHERE source='manual'` + `/move` 409; the UI must not create any path that would surface a PR row on the board.)
- **Esc / back-arrow → board:** inherited verbatim from `TaskPage` (always the explicit board route, suppressed while typing in the terminal/inputs or with a dialog open).
- **Agent session:** Explicit Start; seed prefilled-not-sent on Start (§E); all other agent lifecycle (resume/reset, dot, insert-description) inherited verbatim — the PR seed does not change the resume/reset contract.
- **Degrade-don't-break:** provisioning failure surfaces inline with Retry and never traps the user (§F). `gh`/git failures never block the board.
