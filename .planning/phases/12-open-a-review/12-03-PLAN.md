<objective>
Make a PR review's Diff tab match GitHub's Files-changed by computing the diff against the PR's OWN base branch (`pr_base_ref`), not the project's configured default base (GHREV-03). The change is ENTIRELY in the diff handler — `internal/diff` is NOT touched (it already does correct three-dot merge-base). Reuse the renderer; only the base ref selection branches on `source`.

Purpose: a PR targeting a non-default base (e.g. a release branch) would otherwise show a misleading mega-diff against `main`. Per RESEARCH §3 / Pitfall 3, the base ref must be FETCHED first (so `origin/<base>` exists) and resolved via the stable `origin/<base>` remote-tracking ref — never `FETCH_HEAD`.
Output: a diff handler that picks the PR base for github_pr tasks and the project base for manual tasks, with the manual path untouched.
</objective>
