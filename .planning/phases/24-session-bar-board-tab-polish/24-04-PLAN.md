<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser rename input → PATCH /api/sessions/{id} | The user's typed label crosses to the server via `useRenameSession`; server-side validation (trim + 200-rune cap + unknown-id 404) is owned by Plan 01. The client sends the raw trimmed draft |
| label render | The renamed label renders back into the tab trigger (JSX-escaped) — never into the PTY |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-09 | Injection | rename input → tab label render | accept | The label is the user's own tab name; it renders only as a React text node in the tab trigger (auto-escaped) and is never pasted into the terminal PTY. No injection surface |
| T-24-10 | Denial of Service | unbounded label from client | mitigate | The client sends the trimmed draft; the server (Plan 01) caps it at 200 runes — the client relies on that server-side bound rather than trusting input length |
| T-24-11 | Tampering | renaming a foreign session | mitigate | The mutation targets `s.id` from the task's own scoped `useSessions` list; the server rejects unknown/foreign ids with 404 (Plan 01, T-24-02) |
| T-24-SC | Tampering | npm installs | mitigate | No new packages (Input, dropdown, TanStack Query, client all in repo); slopcheck N/A |
</threat_model>
