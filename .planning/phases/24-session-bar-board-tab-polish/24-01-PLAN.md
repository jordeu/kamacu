<objective>
Deliver the backend for renameable bash/tmux tabs (TABS-01/TABS-02): a mutex-guarded
`Session.SetLabel` rename write path, a `PATCH /api/sessions/{id}` handler that renames the
in-memory session label (and, for tmux-backed tabs, persists it to the `tmux_sessions.label`
row so it survives a server restart), and a hardening pass on the D-04 label-persistence so a
restarted tmux tab can never surface the `"Bash ?"` fallback.

Purpose: The frontend rename editor (Plan 04) needs a server endpoint to commit against, and
TABS-01 requires the custom name to survive a restart via the existing `tmux_sessions.label`
column. This plan owns every backend seam so Plan 04 is a pure UI wiring task.

Output: `Session.SetLabel` in `session.go`; a `rename` handler + `PATCH /api/sessions/{id}`
route + hardened INSERT/reconcile in `sessions.go`; new tests in `sessions_test.go`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → PATCH /api/sessions/{id} | The one genuinely new attack surface: user-supplied `{label}` crosses into the server, gets stored in `tmux_sessions.label`, and is rendered back as a tab trigger |
| tmux name → derived ordinal | `reconcileTmux` parses `<n>` out of the machine-minted `kamacu-<task>-<n>` name — server-controlled, not user input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Denial of Service | rename handler | mitigate | Cap the trimmed label at 200 runes before `SetLabel`/persist so an unbounded label can't bloat the row or the rendered strip (Task 2) |
| T-24-02 | Tampering | rename handler | mitigate | Reject unknown/foreign session ids: `h.mgr.Get(id)` returns 404 for any id not in the live manager map, so a client can never rename an arbitrary or non-existent session (Task 2) |
| T-24-03 | Injection | label render path | accept | The label renders only as a React tab trigger / header string (JSX auto-escapes) and is NEVER written into the PTY — confirmed: no code path pastes `label` to `WriteInput`. Trim covers control-char noise; no HTML/PTY injection surface exists |
| T-24-04 | Information Disclosure | tmux_sessions row | accept | Local-only single-user binary on localhost; the label is the user's own tab name, no cross-user exposure possible |
| T-24-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan (backend-only, stdlib + existing deps); slopcheck N/A |
</threat_model>
