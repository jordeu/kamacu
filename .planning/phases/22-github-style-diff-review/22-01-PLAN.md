<objective>
Add a server-authoritative, rendered-per-file diff hash to the diff pipeline. The hash keys the Viewed persistence (Plan 02) and drives auto-reset (DIFF-04): a file whose rendered diff changes gets a new hash and therefore no matching Viewed row.

Purpose: The same bytes that key persistence must be authoritative and deterministic (structured-diff-on-server, dumb-map-on-client). This is a pure Go function — the strongest test seam in the phase.
Output: `diff.File` gains `Hash` (computed) and `Viewed` (field, default false, populated later by the API handler in Plan 02); `hashFile()` helper; table-driven hash-invariant tests.

<notes>
## Binary-file Viewed-reset limitation — STRICT D-01 (RESOLVED, do NOT "fix")

The hash is computed over rendered content only (Status/Binary/OldPath/Hunks) — NOT the worktree blob and NOT the git `index <oid>..<oid>` line. A binary file renders a content-invariant "Binary file changed" header with no hunks, so a binary file whose bytes change (but whose status/path/header do not) will NOT reset its Viewed state. This is an ACCEPTED, DOCUMENTED limitation locked by the user (D-01).

DO NOT add `index <oid>..<oid>` blob-OID capture to `parse.go`. DO NOT fold blob OIDs into `hashFile`. The strict rendered-only reading is the intended behavior. Document the binary case in the `hashFile` doc-comment and cover it with a stability test (Task 2) so a future maintainer does not mistake it for a bug.
</notes>
