    1. **DIFF-01 (tree + scroll):** Confirm a left-hand tree lists ALL changed files, with folders nested and single-child folder chains path-compressed (e.g. `internal/api`), folders expanded by default. Click a file row deep in the list — the right pane scrolls so that file's header sits just under the sticky totals bar. Scroll the right pane manually — the highlighted (blue-left-border) tree row follows the file at the top of the viewport. Toggle the tree with the PanelLeft button (aria "Hide file tree" / "Show file tree"). Confirm clicking a tree row does NOT change that file's collapse or Viewed state (scroll-only).
    2. **DIFF-02 (collapse/expand):** Click a file header's chevron to collapse it, click again to expand — independent of Viewed (collapsing does not check Viewed).
    3. **DIFF-03 (Viewed + persist):** Check "Viewed" on a file — it collapses and its header + tree row dim; the checkbox is blue. Switch to another tab and back to the Diff tab — the file is still Viewed + collapsed. Restart the server, reopen the same task's Diff tab — the file is STILL Viewed + collapsed (server-persisted). Confirm binary files (if any) also show a Viewed checkbox.
    4. **DIFF-04 (auto-reset on change):** With a file marked Viewed, edit that file's content in the worktree (so its rendered diff changes). Reopen/refresh the Diff tab — that file comes back UN-viewed and RE-EXPANDED, while other unchanged viewed files stay collapsed + viewed. Revert the file to its exact previously-viewed content and reopen — its checkmark is restored automatically (keep-history).

    **Accepted limitation (do NOT report as a bug):** a BINARY file marked Viewed will NOT auto-reset when only its bytes change (its rendered "Binary file changed" header is content-invariant; strict D-01, locked by the user). Text files reset correctly.

    Copy/style spot-check: deletions use `−` (U+2212), counts are `tabular-nums`, chrome stays neutral zinc with blue-500 only on active/selected/focus/checked, tone is sentence-case.
