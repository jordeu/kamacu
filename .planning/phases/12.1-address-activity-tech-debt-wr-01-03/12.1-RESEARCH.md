## Summary

Phase 12.1 closes three non-blocking quality gaps the v1.12 milestone audit surfaced in Phase 11's Activity page. All three fixes are **surgical edits to existing files** — no backend, no SQL, no migration, no new API, **no new dependency**. WR-01 and WR-02 both land in `web/src/lib/useActivityView.ts` (the hook that owns scope/window state); WR-03 is a one-line `aria-label` edit in `web/src/components/activity/ReviewsList.tsx`. The gate forwarding touches `web/src/pages/ActivityPage.tsx` (one destructure + one arg). `web/src/api/queries.ts`'s `useActivity` already has the `enabled` parameter — it needs no change. `web/src/components/activity/ScopeSelector.tsx` needs no functional change for WR-02 (its stale→"Global" label fallback becomes dead-or-defense code once `useActivityView` demotes upstream).

The established pattern WR-02 mirrors — `web/src/lib/useActiveWorkspace.tsx:53-66` (`ActiveWorkspaceProvider`) — is a `useMemo` over `(rows, savedId)` that resolves a stale saved id against live rows and falls back without persisting the fallback. WR-02 translates this shape 1:1 to the Activity scope: a `useMemo` over `(savedScope, workspaces, projects)` that demotes a stale `workspace:N`/`project:N` to `global` as the **effective value**, leaving `localStorage` untouched. This is the highest-leverage design choice in the phase and it is already locked (D-04/D-05/D-06).

**Primary recommendation:** Implement WR-01's `scopeResolved` as a `useMemo` (not the audit's state+effect snippet) and WR-02's demotion as a `useMemo`-derived effective scope (not a `setScopeState("global")` effect) — both for the same reason: they mirror `useActiveWorkspace`, avoid the project's documented `react-hooks/set-state-in-effect` lint debt class, and never touch the persisting setter. Do NOT extract a pure helper purely to add a unit test (D-12) — there is **no test runner installed** in `web/` (no vitest, no jest), so extraction-for-testability would either violate the "no new dependency" boundary or ship an untested helper. The inline `useMemo` form is cleaner and matches the established pattern.

```ts
export function ActiveWorkspaceProvider({ children }: { children: ReactNode }) {
  const { data: workspaces } = useWorkspaces();
  const [savedId, setSavedId] = useState<number | null>(readSavedId);

  const activeWorkspaceId = useMemo<number | null>(() => {
    if (!workspaces) return null;                                    // still loading

}
```

### WR-01 — wire the `enabled` gate (`gate-wired`)

**Where:** `useActivityView.ts` (compute `scopeResolved`) + `ActivityPage.tsx:24-25` (forward it).

**D-02 semantics validation against the real loading states:**
- `activeWorkspaceId` is `null` **only while `useWorkspaces()` is loading** (`useActiveWorkspace.tsx:59`: `if (!workspaces) return null;`). Therefore `activeWorkspaceId !== null` ⟺ "workspaces loaded → promotion effect can settle". D-02's signal is correct. `[VERIFIED: codebase — useActiveWorkspace.tsx:57-66]`

1. The "has-saved-scope" half is session-constant; the only reactive input is `activeWorkspaceId`. A `useMemo` re-derives cleanly on that one dependency with no state/effect pair.
2.
```ts
// useActivityView.ts — recommended shape

  () => localStorage.getItem(ACTIVITY_SCOPE_KEY) !== null || activeWorkspaceId !== null,
  [activeWorkspaceId],
```

**Return widening:** `useActivityView` returns `{ scope, setScope, window, setWindow, scopeResolved }`. Update the return-type JSDoc (line 91) to mention `scopeResolved`.

### WR-02 — stale-scope demotion to `global` as the value (`stale-scope-resolved`)

**Where:** `useActivityView.ts` only (D-05 — centralized). `ScopeSelector` gets the resolved scope transparently.

**Recommended shape: `useMemo`-derived effective scope (mirror `useActiveWorkspace`), NOT an effect+`setScopeState`.** This is the single most important structural choice in the phase.

Rationale:
1. **D-06 compliance is structural, not behavioral.** A `useMemo` *derives* the effective scope without calling any setter — `localStorage` is untouched by construction. An effect calling `setScopeState("global")` would also comply (it's the in-memory setter, not the persisting `setScope` wrapper), but it (a) diverges the in-memory `scope` from the saved value, creating a "what does `scope` mean now?" ambiguity for future readers; (b) is a set-state-in-effect call (the project's documented lint-debt class); (c) requires guarding against re-entry. `useMemo` has none of these costs.
2. It is the **literal `useActiveWorkspace` shape** (lines 57-66) — `savedId` state + `useMemo`-derived `activeWorkspaceId`, persist only via `setActiveWorkspaceId`. Translating: `savedScope` state + `useMemo`-derived effective `scope`, persist only via `setScope`. Consistency with the established pattern is worth more than a marginally smaller diff.

**Concrete shape (rename internal state for clarity, mirroring `savedId`):**
```ts

const { data: workspaces } = useWorkspaces();

const [savedScope, setSavedScope] = useState<ActivityScope>(() => readScope("global"));
const [window, setWindowState] = useState<ActivityWindow>(readWindow);

// Promotion effect (D-05) — unchanged logic, now writes the renamed setter.
useEffect(() => {
  if (
    activeWorkspaceId !== null &&
    localStorage.getItem(ACTIVITY_SCOPE_KEY) === null
  ) {
    setSavedScope(`workspace:${activeWorkspaceId}`);
  }
}, [activeWorkspaceId]);

// WR-02/D-04/D-07 — effective scope: grammar-validated saved scope, demoted to
// "global" once rows have loaded and the id is not found. While rows are still
// loading, the grammatically-valid saved scope is used as-is (no premature demote).
const scope = useMemo<ActivityScope>(() => {
  if (savedScope === "global") return "global";
  if (savedScope.startsWith("workspace:")) {
    const id = Number(savedScope.slice("workspace:".length));
    if (workspaces && !workspaces.some((w) => w.id === id)) return "global";
    return savedScope;

  const id = Number(savedScope.slice("project:".length));
  if (projects && !projects.some((p) => p.id === id)) return "global";

  setSavedScope(s);
  localStorage.setItem(ACTIVITY_SCOPE_KEY, s);
```

## Common Pitfalls

### Pitfall 1: Demoting via the persisting `setScope` wrapper (D-06 violation)
**What goes wrong:** Calling `setScope("global")` on staleness overwrites `kamacu.activity.scope` silently — the user's last explicit pick is destroyed, and it diverges from `useActiveWorkspace`'s resolve-don't-persist discipline.
**Why it happens:** The wrapper is the obvious-looking entry point; the in-memory `setScopeState` is less visible.
**How to avoid:** Derive the effective scope via `useMemo` — never call any setter for the demotion. If an effect form is somehow chosen, call `setScopeState` (in-memory) directly, never `setScope`.
**Warning signs:** A `useEffect` whose body calls `setScope(...)`; a `localStorage.setItem(ACTIVITY_SCOPE_KEY, ...)` outside the `setScope` wrapper.

### Pitfall 2: Premature demotion while rows are loading
**What goes wrong:** Demoting a grammatically-valid `workspace:N` to `global` before `workspaces` arrives causes a flash to "Global" then back to the workspace name once rows load (if the id is in fact live).
**Why it happens:** Forgetting the `if (workspaces && ...)` loading guard.
**How to avoid:** Gate the liveness check on the rows being defined (D-07). The `useMemo` shape above short-circuits on `undefined` rows.
**Warning signs:** A liveness check of the form `if (!rows.some(...)) return "global"` without the `rows &&` prefix.

### Pitfall 3: Deleting `useDisplayName`'s "Global" fallbacks too eagerly
**What goes wrong:** After WR-02 demotes upstream, the `?? "Global"` fallbacks in `useDisplayName` (ScopeSelector.tsx:31, 34) look dead and get deleted — but they still fire during the loading window (rows `undefined`, effective scope = saved `workspace:N`, `(workspaces ?? [])` is `[]`, find fails).

## Code Examples

### WR-01 + WR-02 combined — the widened `useActivityView` (recommended shape)
```ts
// Source: translation of web/src/lib/useActiveWorkspace.tsx:53-71 (the established pattern)
// + 11-REVIEW.md WR-01 fix snippet. [VERIFIED: codebase]

import { useEffect, useMemo, useState } from "react";
import { useActiveWorkspace } from "@/lib/useActiveWorkspace";
import { useProjects, useWorkspaces } from "@/api/queries";

export function useActivityView() {
  const { activeWorkspaceId } = useActiveWorkspace();
  const { data: workspaces } = useWorkspaces();
  const { data: projects } = useProjects();

  const [savedScope, setSavedScope] = useState<ActivityScope>(() =>
    readScope("global"),
  );
  const [window, setWindowState] = useState<ActivityWindow>(readWindow);

  // Adopt the active workspace as the default scope on first open (D-05).
  useEffect(() => {
    if (
      activeWorkspaceId !== null &&
      localStorage.getItem(ACTIVITY_SCOPE_KEY) === null
    ) {
      setSavedScope(`workspace:${activeWorkspaceId}`);
    }
  }, [activeWorkspaceId]);

  // WR-01/D-02: gate trips once a saved scope exists OR the active workspace resolved.
  const scopeResolved = useMemo(
    () =>
      localStorage.getItem(ACTIVITY_SCOPE_KEY) !== null ||
      activeWorkspaceId !== null,
    [activeWorkspaceId],
  );

  // WR-02/D-04/D-06/D-07: effective scope. Grammar-validated saved scope,
  // demoted to "global" once rows have loaded and the id is absent. Never persisted.
  const scope = useMemo<ActivityScope>(() => {
    if (savedScope === "global") return "global";
    if (savedScope.startsWith("workspace:")) {
      const id = Number(savedScope.slice("workspace:".length));
      if (workspaces && !workspaces.some((w) => w.id === id)) return "global";
      return savedScope;
    }
    const id = Number(savedScope.slice("project:".length));
    if (projects && !projects.some((p) => p.id === id)) return "global";
    return savedScope;
  }, [savedScope, workspaces, projects]);

  const setScope = (s: ActivityScope) => {
    setSavedScope(s);
    localStorage.setItem(ACTIVITY_SCOPE_KEY, s);
  };

  const setWindow = (w: ActivityWindow) => {
    setWindowState(w);
    localStorage.setItem(ACTIVITY_WINDOW_KEY, w);
  };

  return { scope, setScope, window, setWindow, scopeResolved };
}
```
