<objective>
Make cleanup and deletion account for tmux sessions so no shell is ever orphaned in a deleted directory (TMUX-08):
- D-92: the cleanup dialog's "N sessions running" count folds in LIVE detached tmux sessions (probe each `tmux_sessions` row via `has-session`) — one number, no tmux-specific wording (D-77).
- D-92/D-93: confirmed cleanup AND task deletion kill the task's tmux sessions (`has-session` -> `kill-session`) BEFORE `wt.Remove` / row delete.
- D-93: a once-at-startup, DB-driven orphan sweep kills any live `kangent-*` session with no matching `tmux_sessions` row or whose task no longer exists — reconciling deletes that happened while the server was down.

The branch is always kept (D-34 unchanged); the reaper never touches worktrees (D-87, that's 09-05).

Purpose: close the orphan-shell hole — `git worktree remove` happily deletes a tree with a daemonized tmux server still cwd'd inside it, and deletes/removes that happen while Kangent is down leave orphans the startup sweep reconciles.
Output: tmux-aware counting + kill in the worktree-remove and task-delete handlers, plus a startup orphan sweep in main.go.
</objective>

From internal/api/worktrees.go — the handlers to extend:
```go
func WorktreeRoutes(mux, db, wt *worktree.Service, mgr *session.Manager)
type worktreeHandlers struct { db *sql.DB; wt *worktree.Service; mgr *session.Manager }

// runningSessions(taskID) int  -> counts mgr.ListByTask running sessions (in-memory only TODAY)
// get():    returns {branch, path, dirty_files, running_sessions: h.runningSessions(id)}  // cleanup dialog source
// remove(): gate1 runningSessions>0 && !StopSessions -> 409; gate2 dirty; then h.mgr.StopAllForTask(id); h.wt.Remove(...)
```
StopAllForTask already stops in-memory tmux sessions (their killer = KillSession), but a DETACHED tmux session (survived a leave/restart) has NO in-memory session — StopAllForTask cannot see it. THAT is the orphan this plan kills directly by DB row.

From internal/api/tasks.go delete (~:487-503):
```go
func (h *taskHandlers) delete(w, r) {
    h.mgr.StopAllForTask(id)
    h.db.Exec(`DELETE FROM tasks WHERE id = ?`, id)  // tmux_sessions FK-cascades? NO -> see note
    ...
}
```
NOTE: tmux_sessions has `task_id INTEGER NOT NULL REFERENCES tasks(id)` WITHOUT `ON DELETE CASCADE` (see migration 00005). So deleting a task does NOT auto-delete its tmux_sessions rows. The delete handler must kill the live tmux sessions first; row cleanup is handled by killing + the startup sweep + lazy GC (09-03). Do not add cascade — kill is the correct action.

From internal/tmux/tmux.go (09-01 added ListSessions):
