<objective>
Deliver the headline durability payoff (TMUX-05, D-88): a tmux session that survives a Kangent restart reattaches automatically and invisibly when the user reopens the task — no Resume button, no banner. This deliberately diverges from the agent's explicit-Resume pattern (Phase 5 D-54) because tmux reattach is cheap and lossless (D-77/D-78).

Mechanism mirrors the Phase 5 reconcile (agents.go two-pass), but the WS handler requires a LIVE in-memory session (`mgr.Get(id)`), so a DB-derived ghost cannot be WS-attached directly. Instead: `GET /api/sessions` reports surviving tmux rows as "orphaned" entries (live per `has-session`, no in-memory session); the frontend, on seeing an orphaned entry, fires one reattach spawn (`POST /api/sessions` with the persisted name) which runs `new-session -A` — attach-or-create reconnects to the surviving session losslessly. Dead rows (D-89) are lazily DELETEd and never surface.

Purpose: complete the "sessions survive a server restart" promise that motivated the whole milestone.
Output: a reconcile branch in the sessions list handler, a reattach variant of the spawn handler, and thin frontend wiring that auto-reattaches restored tabs.
</objective>
