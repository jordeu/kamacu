## Typography

The avatar monogram and editors reuse the existing zinc theme scale. Two weights: 400 regular + 500 medium (`font-medium`). This matches the established system — `ProjectSettingsDialog` already pairs 400 body with `text-xs font-medium` (500) labels, and the sidebar's own emphasis weight is `font-medium`. No third weight is introduced. 3 roles in scope.

| Role | Size | Weight | Line Height | Tailwind | Usage |
|------|------|--------|-------------|----------|-------|
| Monogram (rail, 32px avatar) | 14px | 500 (medium) | 1 (centered, no wrap) | `text-sm font-medium leading-none` | Letters on `icon_color`, fixed white text (D-04). White `font-medium` on the saturated palette hue stays high-contrast and legible at 32px, and matches the sidebar's existing medium-weight emphasis. Auto-scales by size prop. |
| Monogram (inline, 20px avatar) | 12px | 500 (medium) | 1 | `text-[10px] font-medium leading-none` | Smaller glyph for the 20px inline avatar (D-05); 10px keeps 2 chars legible inside 20px. |
| Body / row label | 14px | 400 | 1.5 | `text-sm` | Project name in expanded row (existing, unchanged). |
| Field label / help / counter | 12px | 500 (medium) | 1.5 | `text-xs font-medium` (label) / `text-xs text-muted-foreground` (help) | Settings editor labels + help text (matches existing dialog L133/L157). |

**Letter color is ALWAYS `text-white` (`#ffffff`)** — fixed by D-04/D-13/Phase-18-D-01 for AA contrast against every Tailwind-600 palette hue. Never derive text color from background.

**Monogram legibility rule:** background is one of the 9 curated Tailwind-600 hues only (palette membership enforced server-side, Phase 18 D-11); white `font-medium` letters on a 600-weight hue meet AA at these sizes. Do not allow off-palette backgrounds.

## Color

Dark-only zinc theme (oklch). The avatar palette is a **bounded 9-color accent system layered ON TOP of** the neutral surface ramp — it is the project-identity signal, deliberately the only saturated color in the sidebar besides the amber waiting indicator.

| Role | Value | Token | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `oklch(0.141 0.005 285.823)` | `--background` | App background, `<main>` |
| Secondary (30%) | `oklch(0.21 0.006 285.885)` | `--sidebar` / `--card` | Sidebar surface (rail + expanded), cards |
| Avatar identity (the 10% accent) | 9-hue curated palette (below) | `project.icon_color` | **Reserved exclusively for the `<ProjectAvatar>` background.** Nothing else uses these hues. |
| Active marker | `oklch(0.552 0.016 285.938)` | `ring-sidebar-ring` | Ring around the active project's **collapsed rail avatar** (D-06). Expanded active row keeps existing `data-active:bg-sidebar-accent`. |
| Waiting signal (semantic) | Tailwind `amber-400` | `bg-amber-400` (dot) / `bg-amber-400/10 text-amber-400` (chip) | Collapsed: static amber dot overlay (D-07). Expanded: existing amber count chip, unchanged (D-08). |

| 2 | `#ea580c` | orange-600 | | 7 | `#4f46e5` | indigo-600 |

## Component & Interaction Contract

### `<ProjectAvatar>` (shared, ICON-07/10)
- **Shape:** rounded-square `rounded-md` (~4.8px at `--radius: 0.375rem`) — reads as a workspace/project icon (GitHub/Slack style), NOT a circular person avatar (D-04).
- **Fill:** inline style `backgroundColor: project.icon_color` (a palette hex). **Letters:** `project.icon_letters`, `text-white font-medium`, centered (`flex items-center justify-center`), `leading-none`.
- **Sizes (prop `size: "rail" | "inline"`):** `rail` = `size-8` + `text-sm`; `inline` = `size-5` + `text-[10px]` (D-05).
- **Fallback:** letters are server-guaranteed non-empty (Phase 18 D-10 `?` fallback); render whatever the field holds, never blank.
- **Reuse:** ONE component instance type, used in rail, expanded row, and settings preview (ICON-10).

### Collapsed rail (ICON-05/06/07/08/09)
- **Mechanism:** switch `<Sidebar>` in `ProjectSidebar.tsx` to `collapsible="icon"` (D-01). The 3rem rail and `group-data-[collapsible=icon]` states are built into `ui/sidebar.tsx` — restyle, don't hand-roll.
- **Re-expand:** toggle pinned at top of the rail (`SidebarTrigger`/icon button) (D-02). **Retire** `CollapsedSidebarTrigger` in `AppLayout.tsx`; drop `<main>`'s collapsed `pl-9` (rail now occupies layout space).
- **Contents when collapsed:** project avatars ONLY. Footer Add(+) / Settings(gear) hidden in icon state (D-03, ICON-FUT-05 deferred).
- **Click:** each avatar wraps the existing `<Link to="/projects/{id}">` (the row action) — click switches project without expanding (ICON-06).
- **Active marker:** active avatar gets `ring-2 ring-sidebar-ring` (and `ring-offset-2 ring-offset-sidebar` for separation on the sidebar surface) driven by `projectId === String(project.id)` (D-06, ICON-07).
- **Tooltip (ICON-08):** wrap each rail avatar in the existing `Tooltip` (`side="right"`), content = full `project.name`. `TooltipProvider delayDuration={0}` already set in `AppLayout`.
- **Waiting badge (ICON-09):** when `waitingByProject.get(project.id) >= 1`, overlay a static `size-2 rounded-full bg-amber-400` dot at top-right of the avatar (`absolute -top-0.5 -right-0.5` *discretion default*). Presence-only, **no number**, **static** (never `animate-pulse` — matches existing chip). Count exposed via `aria-label` on the avatar/link: `"1 agent waiting for input"` / `"N agents waiting for input"` (reuse existing chip copy, D-07).
- **Rail overflow (discretion):** when projects exceed viewport height the rail scrolls vertically; `SidebarContent` already applies `overflow-auto` + `no-scrollbar` — keep it. No new scroll affordance.

### Expanded sidebar (ICON-10)
- Inline `<ProjectAvatar size="inline">` (`size-5`) renders left of the project name inside the existing `SidebarMenuButton` row, before the truncating name span.
- Existing name display + **static amber count chip preserved unchanged** (`bg-amber-400/10 text-amber-400`, L81). Do NOT add the dot badge here — would double-signal (D-08).
- Expanded active treatment unchanged: `data-active:bg-sidebar-accent` (D-06).

### Settings editors (ICON-11/12) — in `ProjectSettingsDialog.tsx`
- **Live preview (D-09):** `<ProjectAvatar size="rail">` at the top of the dialog reflecting the in-progress `letters` + `color` (local state, not the saved project).
- **Letters editor (D-10, ICON-11):** `<Input maxLength={2}>` with live client normalization mirroring the server rule — `.toUpperCase()`, strip non-alphanumerics, keep ≤2 chars. Server is the enforcer; client mirror is UX. Empty input is allowed in the field but Save is disabled (or surfaces the inline 400) when letters would be empty (≥1 required).
- **Color editor (D-11, ICON-12):** a grid of the 9 `PROJECT_PALETTE` swatches. Current selection clearly indicated with **`ring-2 ring-sidebar-ring` + a centered lucide `Check` (white)**. Each swatch: `size-7 rounded-md`, `backgroundColor` = its hex, `aria-label` = the hue name or hex, `aria-pressed`/`role` for the selected one. Selecting sets local `color`. No free-form hex (ICON-FUT-03 deferred).
- **Swatch grid columns (discretion default):** single row of 9 (`flex flex-wrap gap-2`) — wraps naturally on narrow dialogs; acceptable alternative is a `grid grid-cols-9 gap-1`. Either satisfies the contract.
- **Save wiring (D-12):** extend the existing conditional PATCH (`useUpdateProjectSettings`). Send `icon_letters` / `icon_color` **only when changed** (same omitted-=-untouched pattern as description/github_repo). 2xx → close dialog; 400 (e.g. empty letters) → inline destructive alert like the repo error (existing L182 styling), dialog stays open, draft preserved.

### Accessibility
- Rail avatar link: `aria-label` = project name (+ waiting count when present); tooltip is supplementary, not the only name source.
- Active avatar: rely on the existing `isActive`/route state; ring is the visual cue, `aria-current="page"` on the active link is recommended.
- Swatches: keyboard-focusable buttons with visible focus ring (`focus-visible:ring-2 ring-sidebar-ring`); selected swatch announces state via `aria-pressed`/`aria-checked`.
- Letters input: associated `<Label htmlFor>` (existing dialog pattern); `maxLength` + live uppercase do not trap the keyboard.
- Respect reduced motion: the waiting dot is static by design (no motion to gate); tooltip uses the existing primitive's transitions.
