<objective>
Gap 1 (backend half): surface `gh` CLI availability to the web UI.

Today `github.Available()` exists but is internal-only — nothing tells the frontend whether `gh` is installed. The /settings Switch flips on/off with no `gh` awareness. This plan adds a small, always-200 `GET /api/github/status` endpoint (modeled on the `internal/quota` degrade pattern) that reports `gh` availability so the frontend (Plan 10-05) can gate the toggle's default/enable behavior.

This plan does NOT touch the frontend or the toggle copy — that is Plan 10-05 (Wave 2). It only stands up the backend signal.

Purpose: Give the frontend a read for "is gh installed" without restart (call-time LookPath), reusing the existing `github.Available()`.
Output: `GET /api/github/status` returning `{"gh_available": true|false}`, always 200.
</objective>
