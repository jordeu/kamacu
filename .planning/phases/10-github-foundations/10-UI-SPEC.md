# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Sources: 10-CONTEXT.md (LOCKED user decisions D-01..D-13 + Claude's-discretion resolutions), REQUIREMENTS.md GHSET-01/02/03 + GHPRJ-01/02/03, ROADMAP.md § "Phase 10: GitHub Foundations" (goal + 5 success criteria incl. the `gh`-removed degrade test and toggle-off test), STATE.md Accumulated Context (the `github_integration` KV default `on`, `internal/github` degrade-don't-break, migration 00007 column set), Phase 6 UI-SPEC (the established settings-page design contract — spacing/typography/color/copy conventions inherited verbatim), and existing source read directly: `SettingsField.tsx` (per-field commit state machine), `SettingsPage.tsx` (section layout, `withMono`, max-w-[640px]), `RenameProjectDialog.tsx` (dialog pattern + `sentenceCase`), `ProjectMenu.tsx` (the ⋯ DropdownMenu), `web/src/components/ui/` inventory (confirmed: no `switch.tsx`; `textarea.tsx` present), `web/components.json` (`registries: {}`), `web/src/api/types.ts` + `settings.ts` (Project / SettingEntry shapes).

**Scope note:** This contract EXTENDS Phases 1–6; it never redefines them. The board, terminal, agent, diff, and the existing four settings groups are untouched. This phase ADDS exactly TWO new frontend surfaces:

1. A **"GitHub" section on `/settings`** containing a single on/off **Switch** (the `github_integration` toggle, default ON — D-02). When OFF, all GitHub UI disappears app-wide (D-03); the app is byte-for-byte pre-v1.3.
2. A **"Project settings" dialog** opened from the project `⋯` dropdown (D-05), mirroring `RenameProjectDialog`, holding an optional short **description** field + a **GitHub repo-link** field (origin-prefilled, soft-save-with-warning — D-07/D-08/D-11).

**Explicitly OUT OF SCOPE for this contract** (later phases — do not spec here): the PR Review column, PR cards, CI rollup pills, the PR review workspace/diff (Phases 11–13). This contract covers only the Switch, the new settings section, the dialog shell, the two fields, and their states.

**No user questions were needed** — CONTEXT.md locks every decision and the design system is mature and established. Claude's-discretion items from CONTEXT.md (D-02 switch integration approach, D-07 description affordance + cap, D-08 auto-detect delivery, D-11 warning copy/placement, D-09 canonicalization) are resolved below.

## Color

Inherited Phase 1/6 budget unchanged: dominant zinc-950 `#09090b`, secondary zinc-900 `#18181b` surfaces / zinc-800 `#27272a` borders, accent blue-500 `#3b82f6`, destructive red-500 `#ef4444`. Text: zinc-50 `#fafafa` / zinc-400 `#a1a1aa` muted / zinc-600 `#52525b` disabled. **This phase introduces no new colors.**

| Element | Value |
|---------|-------|
| `GitHub` group label | zinc-400 muted (column/section-header treatment, identical to the other settings groups) |
| Switch — ON (checked) | Track = accent blue-500 `#3b82f6` (shadcn `data-[state=checked]:bg-primary` → the zinc theme's primary). Thumb = zinc-50 `#fafafa`. **This is a sanctioned accent use — added to the reserved list below.** |
| Switch — OFF (unchecked) | Track = zinc-800 `#27272a` (`bg-input`), thumb zinc-50 — calm, low-contrast off state |
| Switch — focus | Standard blue-500 focus-visible ring (reservation #1 — free, no new accent use) |
| Switch — disabled (in flight) | shadcn default `disabled:opacity-50`; the row stays interactive-looking, no spinner |
| Help text (Switch + dialog fields) | zinc-400 muted |
| Dialog surface | zinc-900 `#18181b` content on the standard backdrop — `DialogContent` default, identical to `RenameProjectDialog` |
| Repo-link / description inputs | Standard shadcn `Input`/`Textarea` on zinc-900, zinc-800 border — no new treatment |
| Inline validation error (dialog) | red-500 12px text under the field. The input gets **no red border** — the message is the signal (Phase 3/6 rule) |
| **Soft "couldn't verify" warning** | **zinc-400 muted** 12px text under the repo field — NOT red, NOT amber. Rationale: D-11 makes this a successful save with a non-blocking advisory; red would read as a failure (the save succeeded) and amber is reserved for the agent waiting state (Phase 4). A muted line, optionally led by a 12px `triangle-alert` glyph also in zinc-400, keeps it calm and non-alarming. Distinct from a hard validation error, which IS red |
| `gh`-degraded note (syntactic-only save) | zinc-400 muted 12px — same calm treatment; absence of `gh` is not an error condition (degrade-don't-break) |
| Linked-state indicator | The presence of a value in the mono repo field IS the linked indicator. **No green "linked" badge, no checkmark** — confirmation is calm; the status palette (green/amber/red dots) belongs to agent state only (Phase 4 rule, carried forward) |

**Accent blue-500 reserved for (Phase 1 list + ONE addition this phase):** focus-visible rings, active tab indicator, drag-over column, prose links, **and the ON-state Switch track**. The Switch's checked track is the only new accent surface in this phase and is the canonical, expected use of accent for a binary on/off control. No other new accent uses — the dialog buttons, inputs, and the `⋯` menu item get the standard focus ring for free.

## Copywriting Contract

Tone inherited verbatim: terse, sentence case, no exclamation marks, no "please". Repo refs / URLs / `owner/name` always render in mono. Server messages are mirrored verbatim, sentence-cased for dialog display (the `sentenceCase` helper in `RenameProjectDialog`).

### Settings page — new "GitHub" section (GHSET-01)

| Element | Copy |
|---------|------|
| Section group label (12px uppercase muted) | `GitHub` |
| Switch row label | `GitHub integration` |
| Switch help (under the row, 12px muted) | `Show GitHub features across Kangent. Turn off to hide all GitHub UI — the app behaves exactly as it did before.` |
| Switch `aria-label` | `GitHub integration` |
| Save failure (network/5xx) | Inline under the Switch row, destructive 12px: `Couldn't save. Try again.` — the toggle reverts to its last saved position (it never gets stuck mid-flip) |

> Note: the GitHub section ALWAYS renders on `/settings` (it is the control that hides everything else — it cannot hide itself). When integration is OFF, every OTHER GitHub surface is hidden, but this Switch row stays visible so the user can turn it back on.

### Project settings dialog — chrome (GHPRJ-01)

| Element | Copy |
|---------|------|

| Dialog title | `Project settings` |
| Footer — cancel | `Cancel` (ghost button — `RenameProjectDialog` precedent) |

### Project settings dialog — Description field (GHPRJ-01/02, D-07)

| Element | Copy |
|---------|------|
| Label | `Description` |
| Control | Multi-line `Textarea` (`web/src/components/ui/textarea.tsx` exists), 3 rows, full dialog width, sans font. Optional — empty is valid (cleared = no description) |
| Placeholder | `Optional short description` |
| Help (12px muted, under the field) | `Shown here in project settings.` (D-07: dialog-only this phase; no board/sidebar surfacing) |
| Soft length cap (discretion, resolved) | **280 characters.** Enforce with a live muted counter `{n}/280` right-aligned on the label row only once the user passes ~240 chars (don't clutter the empty/short case); hard-stop input at 280. Server also caps; if the server rejects, mirror its message verbatim |

### Project settings dialog — GitHub repository field (GHPRJ-03, D-08/D-09/D-11)

This field renders **only when the global toggle is ON** (D-06). Read the toggle via the shared `useSettings()` query.

| Element | Copy |
|---------|------|
| Label | `GitHub repository` |
| Control | Single-line `Input`, `font-mono`, full dialog width |
| Placeholder | `owner/name` (mono) |
| Prefill behavior | On open, the field is prefilled with the canonicalized `owner/name` derived from the project's git `origin` remote when the project is not yet linked (D-08). If already linked, prefill with the saved `github_repo`. The user can edit, override, or clear it |
| Help (default, 12px muted) | `Detected from this repo's origin remote. Accepts owner/name or a GitHub URL.` (with `owner/name` in mono) |
| Help when no origin could be detected | `Accepts owner/name or a GitHub URL.` (drop the "detected" clause — never imply a detection that didn't happen) |
| Cleared / not-linked state | Empty input + the default help line. Empty = not linked (`github_repo` NULL). No empty-state illustration — a dialog field's placeholder is the empty state |
| Soft "couldn't verify" warning (D-11) — `gh` PRESENT but can't confirm | Muted 12px under the field, replacing the help line after a save that soft-succeeded: `Saved, but couldn't verify {owner/name} on GitHub — check access or the name.` (repo ref in mono). Non-blocking: the dialog still closes / the value is still stored |
| `gh`-degraded note (D-11) — `gh` ABSENT or unauthenticated | Muted 12px under the field: `Saved without verifying — the gh CLI isn't available.` (`gh` in mono). Non-blocking; syntactic validation only |
| Hard validation error (syntactically invalid) — the ONLY blocking case | Destructive red 12px under the field, server message verbatim+sentence-cased, e.g. `Not a valid repository — use owner/name or a GitHub URL.` The draft stays for correction; the dialog does NOT close |

**Empty states:** Description and repo-link are both legitimately empty (optional / not-linked) — the placeholder serves as the empty affordance; no dedicated empty illustration or copy. **Destructive actions:** none in this phase — clearing the description or unlinking the repo is routine and instantly re-editable; it gets **no confirmation ceremony** (consistent with Phase 6 `Reset to default`). `Delete project` (destructive, red, confirmed) already exists in `ProjectMenu` and is untouched.

## Interaction Contract

States the executor must implement; the auditor will check these.

### Settings — GitHub Switch (GHSET-01/02/03, D-01/D-02/D-03)

The Switch's value flows through the EXISTING settings KV REST surface (`PUT /api/settings/github_integration`, value `"on"`/`"off"`) and the shared `useSettings()`/`useSaveSetting()` hooks (D-01/D-13). No new endpoint.

| Interaction | Contract |
|-------------|----------|
| Placement | A new `<section>` on `SettingsPage`, appended after the existing `Cleanup` section, with the standard section structure: 12px uppercase muted `GitHub` label → md gap → the Switch row. Reuse the `flex flex-col gap-3` section + `text-xs font-medium tracking-wide text-muted-foreground uppercase` label classes already in `SettingsPage` |
| Switch row | One row: the Switch (left) + `GitHub integration` label (right, clickable to toggle via `htmlFor`/Radix label association), `sm` gap; the 12px muted help line sits below the row |
| Commit | Toggling the Switch → immediate `PUT` of `"on"`/`"off"` (the select-style immediate-commit model from `SettingsField`, NOT blur/Enter — a Switch has no draft). While in flight: the Switch reflects the new position optimistically, stays enabled, no spinner |
| Success | The new state is the saved state. **No `Saved` flash is required for the Switch** (the visual position IS the confirmation) — but a muted `Saved` flash beside the label for 2s is acceptable and consistent with `SettingsField` if the planner extends that component. Either is contract-compliant |
| Failure (network/5xx) | The Switch reverts to its last saved position and shows `Couldn't save. Try again.` (destructive 12px) under the row. It never sticks mid-flip |
| OFF cascade (GHSET-02, D-03) | When `github_integration === "off"`, ALL other GitHub UI is hidden app-wide, gated on the shared `useSettings()` value: (a) the `GitHub repository` field is removed from the Project settings dialog (only Description remains — D-06); (b) from Phase 11 on, the Review column. The board, tasks, sessions, and every existing flow are byte-for-byte unchanged. The GitHub Switch row itself stays visible (it is the re-enable control) |
| Default | ON. Absent KV row = code default `"on"` (D-01) — the Switch reads checked on first run with no stored value |
| Degrade (GHSET-03) | The toggle is pure local state — it never calls `gh` and cannot be affected by a missing/unauthenticated `gh`. Flipping it always works |

### Project settings — entry point (GHPRJ-01, D-05)

| Interaction | Contract |
|-------------|----------|
| Menu item | Add a `DropdownMenuItem` `Project settings` to `ProjectMenu`, positioned **between `Rename` and `Delete project`** (settings is non-destructive; keep the destructive `Delete project` last and visually separated as it already is). `onSelect` opens the dialog via local state (mirror the existing `renameOpen` pattern) |
| Visibility | The `Project settings` item ALWAYS shows (the Description field is integration-agnostic — D-06); only the repo-link FIELD inside is gated by the toggle. Do not hide the menu item when integration is off |

### Project settings — dialog (GHPRJ-01/02/03, D-07/D-08/D-09/D-11)

Modeled on `RenameProjectDialog`: a Radix `Dialog` with `DialogHeader`/`DialogTitle`, a `<form onSubmit>` body (`flex flex-col gap-4`), and a `DialogFooter` with `Cancel` (ghost) + `Save changes` (primary). One PATCH carries both fields.

| Interaction | Contract |
|-------------|----------|
| Open | Each time the dialog opens: prefill Description from `project.description`; prefill the repo field from `project.github_repo` if linked, else from the origin-derived suggestion (D-08). Clear any prior error/warning. (Mirror the `useEffect(() => { if (open) {...} }, [open, ...])` reset in `RenameProjectDialog`) |
| Origin auto-detect (D-08) | The origin suggestion is fetched **when the dialog opens** — never on every project-list response. Delivery is planner's discretion (a dedicated suggestion endpoint or an on-open derived read). While the suggestion is loading, the repo field may show a brief disabled/loading state; if detection fails or returns nothing, fall back to an empty field + the no-origin help copy. Detection failure is silent (it's a convenience, not a requirement) |
| Save | `Save changes` (or Enter in a single-line field) → one `PATCH /api/projects/{id}` with `{ description, github_repo }` (D-13). Server canonicalizes the repo ref to `owner/name` (D-09) and applies soft validation (D-11). Button disabled while the PATCH is in flight |
| Save success (verified or no-gh) | Dialog closes; the project query is invalidated so the stored values refresh. If the server returned a soft-verify or gh-degraded advisory (see below), the dialog instead stays open just long enough to surface the muted note, then closes — OR closes immediately and the note is non-blocking; planner's discretion, but a soft advisory must NEVER block closing |
| Soft-verify warning (D-11, `gh` present, unverifiable) | The PATCH succeeds (the value IS stored). Surface the muted "couldn't verify" line under the repo field. The user may close the dialog — the link is saved. This is the explicit non-blocking path |
| gh-degraded (D-11, `gh` absent/unauth) | The PATCH succeeds via syntactic validation. Surface the muted "saved without verifying" line. Non-blocking |
| Hard validation error (syntactically invalid repo ref) | The PATCH 4xx's; the dialog STAYS OPEN; the destructive red message (sentence-cased server copy) renders under the repo field; the draft is preserved for correction; the Description value is not lost. This is the ONLY case that blocks the dialog |
| Clear / unlink | Emptying the repo field and saving stores `github_repo = NULL` (not linked). Emptying the description and saving clears it. No confirmation — routine |
| Cancel / dismiss | `Cancel`, Esc, or backdrop click closes the dialog and discards unsaved edits (standard `Dialog` dismissal; nothing is persisted until `Save changes`) |
| Field gating | The `GitHub repository` field renders only when `github_integration === "on"` (D-06). When off, the dialog contains only the Description field + footer |
| Network failure (5xx) | `Couldn't save. Try again.` destructive 12px under the form (or under the field that triggered it); dialog stays open, drafts preserved (`RenameProjectDialog` catch precedent) |
| Concurrency | Single-user app: last write wins; no conflict UI |

Focal point: neither surface introduces a high-contrast inverted CTA. On `/settings` the visual anchor remains the `Settings` heading and the calm one-column form; the new GitHub section is just one more quiet group with a single accent-track Switch. In the dialog, the primary `Save changes` button is the only emphasized control (standard primary), exactly as in `RenameProjectDialog` — the soft-verify path deliberately keeps warnings muted so nothing competes with the routine save.
