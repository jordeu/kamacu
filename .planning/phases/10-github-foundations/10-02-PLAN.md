<objective>
Extend the backend so a project can be linked to a GitHub repo with a description, with origin auto-detect and soft-save-with-warning validation that never hard-blocks on `gh`.

This plan adds the read-only `internal/github` leaf package (LookPath presence + `gh repo view` canonicalization), the origin auto-detect read (`git remote get-url origin`), grows the `Project` JSON/columns/scan by the two new fields, turns `PATCH /api/projects/{id}` from rename-only into a partial update accepting `description` + `github_repo`, and adds the origin-suggestion endpoint the dialog reads on open.

Purpose: This is the server contract Plan 03's Project settings dialog consumes (the PATCH shape + the origin endpoint). It honors degrade-don't-break: `gh` absent/unauthenticated never blocks linking.
Output: `internal/github` package, extended PATCH, grown Project shape, and a `GET /api/projects/{id}/github-origin` endpoint.
</objective>

Verified gh/git commands (STACK.md, run live on gh 2.82.0):
- Canonicalize/verify a repo: `gh repo view <owner/name> --json nameWithOwner` → exit 0 + `{"nameWithOwner":"cli/cli"}` on success; nonzero + `GraphQL: Could not resolve to a Repository...` on a bad ref.
- Presence: `exec.LookPath("gh")`.
- Origin detect: `git -C <repo_path> remote get-url origin` → e.g. `git@github.com:owner/name.git` or `https://github.com/owner/name.git` (nonzero if no origin).

URL/shorthand canonicalization rule (D-09) — canonicalize ALL of these to `owner/name`:
- `owner/name`                          → `owner/name`
- `https://github.com/owner/name`       → `owner/name`
- `https://github.com/owner/name.git`   → `owner/name`
- `git@github.com:owner/name.git`       → `owner/name`
- `git@github.com:owner/name`           → `owner/name`
Reject (syntactically invalid → the ONLY hard error): empty after canonicalization, more/fewer than 2 path segments, whitespace inside a segment, a leading `-`.

Test harness (projects_test.go): `newTestServer(t)` opens a fresh migrated DB + httptest server with all routes; `gitRepo(t)` runs `git init` in a temp dir for a real repo path. Use these for the PATCH and origin tests.
