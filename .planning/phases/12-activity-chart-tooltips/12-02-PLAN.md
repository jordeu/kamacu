## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local backend (GET /api/activity) → SPA chart render | The chart renders numeric day-bucket counts derived from `data.tasks[].doneAt` + `data.reviews.prs[].completedAt` (already-fetched server data); no new fetch, no new endpoint |
| shadcn ChartStyle → DOM | ChartStyle injects `--color-*` CSS vars via `dangerouslySetInnerHTML` (library-internal); values sourced from ChartConfig.color (PROJECT_PALETTE hexes), not server/user data |

## STRIDE Threat Register

ASVS level 1, block threshold "high". This plan is pure client-side rendering of
server-provided counts through a vetted charting library + a 2-line formatter swap.
No new boundary, no auth, no new input surface beyond what Phase 10/11 already
exposed. No high/critical threats.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-04 | Tampering / Information disclosure (XSS via chart data) | ActivityChart recharts rendering of day-bucket counts | low | accept | recharts renders numeric `dataKey` values (integer counts) — no HTML/string rendering path for server data. Tooltip labels come from ChartConfig (developer-authored "Tasks"/"Reviews"), not the server. ChartTooltipContent renders `item.value.toLocaleString()` (numeric) and `config.label` (developer-authored). React/recharts auto-escape. No `dangerouslySetInnerHTML` in app code. |
| T-12-05 | Tampering (CSS injection via ChartStyle) | shadcn ChartStyle dangerouslySetInnerHTML (consumed by ChartContainer) | low | accept | The `--color-*` values injected into the `<style>` tag come from ChartConfig.color — sourced from PROJECT_PALETTE (the hardcoded hex array in palette.ts), NOT from server/user data. Safe by construction; a compromised palette.ts would be a separate supply-chain issue. |
| T-12-06 | Denial of service (chart render on huge dataset) | bucketByDay over a large tasks/reviews array | low | accept | The window caps at 30 days; the bucketing is a single O(n) pass over already-fetched data with a Map lookup per entry. N (7-30 buckets) is tiny. No unbounded loop, no recursion. The Month view's 30 bars is the worst case and is trivially fast. |
| T-12-07 | Information disclosure (timezone-shifted bucket leak) | bucketByDay local-calendar-day keying | low | accept | Bucketing by local day (not UTC) is the CORRECT behavior (Pitfall 4 — the user thinks in their timezone); it is not a disclosure. No mitigation needed — the local-day bucketing IS the mitigation against the UTC-shift bug. |
</threat_model>
