# Phase 11: Plan 03 — Non-nil Activity Wire Contract Summary

**Closed the UAT Test 1 "black page on /activity" blocker: GET /api/activity now emits `tasks:[]` / `reviews.prs:[]` (never `null`) on every path, with three layers of frontend null defense — a fresh/empty instance renders the page instead of blanking.**

## Accomplishments
- Restored the Phase 11 ACT-01 truth ("User can open a dedicated top-level Activity page") on empty instances — the blocker that prevented UAT Test 1 from proceeding.
- Established the non-nil-slice wire contract as a project pattern: Go API fields typed as JSON arrays initialize non-nil slices on every return path (happy-empty, error, degrade).
- Added a byte-level regression test that locks the contract — a decoded `len==0` check cannot catch a nil-slice regression because `json.Unmarshal` accepts `null` for a slice; the raw-body `"tasks":[]"` / `"prs":[]"` assertion is load-bearing.
- Defense-in-depth at all three Activity render sites (groupByProject, ReviewsList prs normalize, ActivityPage list-prop guards) so a future contract regression degrades to an empty list, not a blank page.
