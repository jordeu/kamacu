<!-- Wire protocol (server side implemented in 02-03 — bytes are fixed): -->
- client→server binary frames: 0x30 + raw stdin bytes; 0x31 + JSON {"cols":N,"rows":N}

    Create a hook that owns the SOCKET lifecycle only (the Terminal instance is owned by TerminalPane and passed in — it must survive reconnects so scrollback stays usable):
    ```typescript
    export type ConnState =
      | { kind: "connecting" } | { kind: "connected" }
      | { kind: "reconnecting"; attempt: number }
      | { kind: "lost" }                       // retries exhausted
      | { kind: "exited"; code: number }       // 'x' frame
      | { kind: "not-found" };                 // close 4404
    export function useTerminalSocket(opts: {
      sessionId: string;
      term: Terminal | null;                   // attach IO once non-null
      onState: (s: ConnState) => void;
    }): { sendResize: (cols: number, rows: number) => void; retry: () => void };
    ```
    Implementation requirements (all from research):
    - `ws.binaryType = "arraybuffer"`. onmessage: `data[0] === 0x30` → `term.write(data.subarray(1))`; `data[0] === 0x78` → parse `{code}`, set state exited, expect server close 1000 (do NOT schedule reconnect for it).
    - `term.onData`: gate on `ws.readyState === WebSocket.OPEN && !exited`; frame as 0x30 + TextEncoder bytes. Bracketed-paste wrappers arrive inside onData strings — pass through UNTOUCHED (D-17).
    - `sendResize(cols, rows)`: 0x31 + JSON bytes. (Change-detection lives in the pane's ResizeObserver, not here.)
    - `connect()` function with attempt counter. On ws.onopen: if this is a RE-connect (not first attach), call `term.reset()` BEFORE any frame is processed, then reset attempt counter, state connected; replay arrives as ordinary 0x30 frames; the pane re-fits and sends resize (which triggers the server-side jiggle).
    - onclose handler decision table:
      - `disposed` ref set (unmount/session switch) → do nothing
      - state is exited (post-'x' close 1000) → stay exited
      - `ev.code === 4404` → state not-found, NO retries
      - else transient → schedule reconnect with backoff [500, 1000, 2000, 4000, 8000] ms, states `reconnecting {attempt}`; after 5 failures → state `lost`
    - `retry()` restarts the cycle from attempt 0 (UI-SPEC "Retry connection").
    - Single effect keyed on `[sessionId, term]`; cleanup: set disposed ref, clearTimeout pending reconnect, `ws.close()` (safe in CONNECTING), dispose the onData listener. StrictMode runs setup→cleanup→setup — exhaustive cleanup makes the double-mount invisible to the server (attach→detach→attach).
    - First connection: emit `connecting` immediately; the >150ms display delay is the pane's concern, not the hook's.
  </action>
