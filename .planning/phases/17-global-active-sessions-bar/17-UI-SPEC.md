# Phase 17 — UI Design Contract

> Visual and interaction contract for the Global Active Sessions Bar. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is an INTERNAL feature reusing the EXISTING design system.** No new component library, no new styling approach, no new design primitives. The contract's job is to lock spacing, typography, color tokens, copywriting, states, and the overlay-panel layout/interaction precisely enough that planner/executor make zero ad-hoc styling decisions. Every status color comes from `dotMeta()`; every panel surface mirrors `ReviewColumn`; the collapse idiom mirrors `ReviewColumn` + `AppLayout`.

## Typography

Two weights only (`font-medium` 500 + default/`font-normal` 400 — matching the existing app, which never goes above `font-medium`). Sizes drawn from the two the bar needs (the app body default is `text-sm`/14px per `index.css`).

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|----------|
| Row label — project + task/PR title | 14px | 400 normal | 1.5 | `text-sm` |
| Row emphasis — current-task project name (optional) | 14px | 500 medium | 1.5 | `text-sm font-medium` |
| Counts, badges, "No active sessions", section affordances | 12px | 500 medium | 1.4 | `text-xs font-medium` |
| Numeric counts (all) | 12px | 500 medium | 1.4 | `text-xs font-medium tabular-nums` |

**Rules:**
- All numeric counts use `tabular-nums` so digits don't jitter on each 5s poll (matches the sidebar chip).
- Long project names and task/PR titles `truncate` within a min-width-0 flex child (mirror `ProjectSidebar`'s `min-w-0 flex-1 truncate`); the full title is available via the row `title`/aria-label.
- No heading or display type in this phase — the bar carries no titles.

## Color

The bar lives entirely inside the existing dark zinc/neutral palette. The ONLY chromatic colors are the four `dotMeta()` status colors (which are themselves the app's reserved status language) — green/amber/zinc — plus the muted-foreground for chrome and text. No new color tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(0.141 …)` zinc-950-ish) | The bar sits on the app background; collapsed bar surface. |
| Secondary (30%) | `bg-[#101013]` (the exact `ReviewColumn` panel chrome) | The expanded overlay panel surface and the collapsed bar fill. Border `border-border` (`white/10`). |
| Accent (10%) — status | `dotMeta()` colors ONLY: green `bg-green-500` (working), amber `bg-amber-400` (waiting, `animate-pulse motion-reduce:animate-none`), zinc `bg-zinc-400` (idle) | The state dots (collapsed counts + per-row indicators) and the waiting emphasis. |
| Chrome / text | `text-muted-foreground` | Chevron, "No active sessions", non-emphasized counts, secondary text. |
| Foreground | `text-foreground` | Row labels (project + title). |
| Destructive | not used | No destructive actions in this phase. |

**Accent reserved for (explicit, never "all interactive elements"):**
1. The three status dots (working green / waiting amber-pulse / idle zinc) — collapsed counts and per-row indicators, sourced from `dotMeta()`.
2. The waiting-count emphasis: amber count text + the amber pulse on the waiting dot (and only the waiting dot pulses — exactly as `dotMeta('waiting')` does; mirror the sidebar chip's amber treatment `text-amber-400` / `bg-amber-400/10`).

**Waiting emphasis (SBAR-03 / D-01 / D-14) — in-bar only:**
- Waiting dot keeps `bg-amber-400 animate-pulse motion-reduce:animate-none` from `dotMeta()`.
- Waiting count renders in amber: `text-amber-400 tabular-nums` (matches sidebar chip color); optional `bg-amber-400/10 px-1 rounded-full` pill to match the sidebar chip exactly when count > 0.
- When the waiting count is 0, the waiting group renders with the same muted treatment as working/idle (no amber, no pulse) — emphasis appears ONLY when something is actually waiting.
- NO browser/OS notifications, NO tab-title/favicon changes (D-14). Emphasis is strictly visual, inside the bar.

**PR `#<n>` badge (D-06):** muted, non-chromatic — `rounded-full bg-card px-1.5 text-xs font-medium text-muted-foreground tabular-nums` (mirrors the `ReviewColumn` collapsed-rail count pill `rounded-full bg-card px-1.5 text-xs`). It is an identifier, not a status — must NOT use a status color.

**Current-task row highlight (D-07, "you are here"):** subtle, non-chromatic — `bg-muted` / `bg-sidebar-accent` background on the row (reuse the sidebar active-item treatment `bg-sidebar-accent text-sidebar-accent-foreground`). Must NOT introduce a new accent color and must NOT compete with the amber waiting emphasis.

## States

The bar is a single always-present surface. It is the 4th consumer of the existing `useAgentStatuses()` 5s poll. Mirror `ReviewColumn`'s quiet inline-state idiom (no spinner, no modal, never blocks the view — SBAR-09).

| State | Condition | Treatment |
|-------|-----------|-----------|
| Loading (first poll) | `useAgentStatuses().data === undefined` | Collapsed bar present with a single quiet `Skeleton` where the counts go (mirror `ReviewColumn`'s skeleton, no spinner). Bar height unchanged. |
| Zero / empty (SBAR-09 / D-02) | data resolved, 0 LIVE sessions (after filtering out `exited`) | Bar stays present. Collapsed: muted `text-xs text-muted-foreground` "No active sessions" — it recedes, never grabs attention. Expanded panel (if user expanded): same muted "No active sessions" centered, `py-6 text-center` like `ReviewColumn`'s empty block. No pulse, no badge. |
| Populated — collapsed (SBAR-02/03/D-01) | ≥1 LIVE session | Per-state colored dot + count groups (working / waiting / idle) using `dotMeta()` colors, plus a total. Waiting group amber-emphasized + pulsing only when its count > 0. Whole bar is the toggle; chevron-up indicates "expand". |
| Populated — expanded (SBAR-04/05/D-03/D-05) | user expanded, ≥1 LIVE session | Panel floats UP over content (overlay/popover anchored to the bottom bar — main content + xterm NEVER reflow/resize). Flat list across all projects, sorted attention-first: waiting → working → idle. Height-capped + `overflow-y-auto` for overflow (D-10). Chevron-down indicates "collapse". |
| Row (D-06) | per LIVE session | `[state dot · project name · task/PR title]`; `source==='github_pr'` rows append a muted `#<n>` badge. Current open task's row subtly highlighted (D-07). Whole row is the click target. |

**Scope filter (D-09 / D-12):** the bar renders ONLY `status ∈ {working, waiting, idle}`. `exited` entries (including DB-derived/post-restart `status:"exited"` resumable rows) are filtered out client-side and never appear. Counts and rows derive from the same filtered set.

**No error state surfaced by the bar itself:** the poll is a shared, already-resilient query (TanStack Query, 5s). On a transient fetch failure the bar simply shows the last good data (stale-while-revalidate) and updates within ~5s when the next poll succeeds — consistent with how card dots / sidebar chips already behave off this feed. The bar does not render a degraded/error message of its own.

## Interaction Contract

| Behavior | Spec | Source |
|----------|------|--------|
| Placement | Pinned to the bottom of the app shell, outside `<Outlet/>`, in `AppLayout.tsx`. Present on every route (board, task, settings). | SBAR-01 / D-13 |
| Expand direction | Panel floats UPWARD over content as an overlay/popover anchored to the bottom bar. Content and xterm terminals NEVER reflow or resize (the explicit reason overlay beats a docked push-up layout). | D-03 |
| Toggle target | The WHOLE collapsed bar is the click target to expand/collapse (mirror `ReviewColumn`'s collapsed-rail `role="button"` whole-thing-click). A chevron shows direction (up = will expand, down = will collapse), using lucide `ChevronUp`/`ChevronDown` `size-3.5`. | D-04 |
| Persistence | Collapse state in `localStorage` under a single GLOBAL key `kangent:sessions-bar-collapsed`. Default collapsed: absent key ⇒ collapsed (use the `!== "0"` idiom from `ReviewColumn`; expanded persists as `"0"`). | SBAR-07 / D-04 |
| List order | Flat across all projects, attention-first: waiting → working → idle. No project grouping. Stable secondary order within a state (keep feed order) to avoid jitter on each poll. | SBAR-05 / D-05 |
| Row navigation | Click → `useNavigate('/projects/${projectId}/tasks/${taskId}')`. Works cross-project (the currently-open project need not match the row's). Both ids are on every feed entry. | SBAR-06 / D-08 |
| Freshness | Sessions appear/drop within ~5s off the existing poll. No new polling hook. | SBAR-08 / D-12 |
| Animation (Claude's Discretion, locked) | Expand/collapse: a short height/opacity transition on the overlay panel (~150ms ease-out), honoring `motion-reduce` (no transition under reduced motion), consistent with the `dotMeta` pulse's `motion-reduce:animate-none`. | D-46 |

**Accessibility:**
- Toggle carries `role="button"` (or a `<button>`), `aria-expanded`, and an `aria-label` describing current counts (e.g. `Active agent sessions: 2 working, 1 waiting, 0 idle — expand`) — mirror `ReviewColumn`'s `aria-label`/`aria-expanded` and `ProjectSidebar`'s pluralized count aria-labels.
- Each row is keyboard-focusable and Enter/Space activates navigation.
- State dots keep `StatusDot`'s `role="img"` + `aria-label` and tooltip from `dotMeta()`.
- Respect `prefers-reduced-motion`: the waiting pulse and the expand transition both no-op (the pulse already does via `motion-reduce:animate-none`).

## Copywriting Contract

This phase has no forms, no destructive actions, and no primary CTA in the conventional sense (the bar is a navigation/status surface). Copy is minimal and quiet.

| Element | Copy |
|---------|------|
| Primary action (row) | Whole row navigates — no button label. Aria: `Open <task or PR title> in <project name>`. |
| Toggle affordance | No visible label (chevron only). Aria: `Active agent sessions: {w} working, {a} waiting, {i} idle — {expand\|collapse}`. |
| Collapsed counts | Numeric only beside each colored dot: `{n}` per state + a total `{n}` (no inline words; the dot color + tooltip carry meaning). Dot tooltips from `dotMeta()`: "Working" / "Waiting for input" / "Idle". |
| Empty state (collapsed) | `No active sessions` — muted, `text-xs text-muted-foreground`. |
| Empty state (expanded) | Heading: `No active sessions` · Body: `Agent sessions appear here while they're running.` (quiet, centered; matches `ReviewColumn`'s muted empty tone). |
| Waiting emphasis label (for the count's aria, mirror sidebar) | `1 agent waiting for input` / `{n} agents waiting for input`. |
| PR row badge | `#{prNumber}` (e.g. `#1423`) — identifier only, tabular-nums. |
| Error state | None surfaced by the bar (stale-while-revalidate; recovers on next 5s poll). No error copy required. |
| Destructive confirmation | None — this phase has no destructive actions. |

**Tone:** quiet, factual, lowercase-noun where the existing app is (matches "No PRs are waiting for your review." / "You're all caught up"). Never alarming except the single intended amber waiting emphasis.
