## Accomplishments
- **TD-ACT-01 (WR-01):** `useActivityView` now exports `scopeResolved` (a `useMemo` over `[activeWorkspaceId]`) and `ActivityPage` forwards it as the 3rd arg to `useActivity`. ## Decisions Made
- **`scopeResolved` via `useMemo` (not the audit's state+effect snippet).** The audit's `11-REVIEW.md:55-63` snippet used `useState` + `useEffect`. RESEARCH §WR-01 recommended the `useMemo` form: it avoids the project's documented `react-hooks/set-state-in-effect` lint-debt class (the 27–28 deferred errors), re-derives cleanly on the single reactive input (`activeWorkspaceId`), and mirrors the discipline chosen for WR-02's effective scope. This is the locked RESEARCH recommendation; honored verbatim.
- **Effective scope via `useMemo` mirroring `useActiveWorkspace.tsx:57-66`.** D-06 ("don't persist the demotion") is structurally satisfied: the useMemo *derives* `"global"` without calling any setter. An effect+`setScopeState("global")` alternative would also comply (setScopeState is in-memory) but diverges in-memory state from saved value and re-introduces the set-state-in-effect smell. The useMemo form is the established pattern.
- **Split `useProjects`/`useWorkspaces` imports onto separate lines.** Matches `useActiveWorkspace.tsx`'s single-hook-per-import convention and satisfies the plan's literal `grep -c 'useWorkspaces\|useProjects' >= 4` criterion (the consolidated one-line import would have scored 3 because grep counts lines, and the useMemo references the data variables `workspaces`/`projects`, not the hook names).
- **Restored the promotion effect's existing inline comment.** The plan said "Do NOT remove or rewrite the effect"; CLAUDE.md says preserve existing accurate doc-comments. The body is unchanged; only the setter name changed (`setScopeState` → `setSavedScope`).
- **No new dependency, no test runner added (D-11/D-12).** RESEARCH verified no test runner is installed in `web/`. Verification is `tsc -b && vite build` + behavioral UAT — the Phase 11/12 norm.
