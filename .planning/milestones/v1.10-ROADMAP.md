# Milestone v1.10: Configurable Agents

## Overview

Make agents first-class configurable data — users define custom agent CLIs in global Settings and assign them per-project, with opencode joining Claude Code as a second built-in engine with its own activity-based status and restart-resume. The `engine` column encodes a capability tier (`claude` | `custom` | `opencode`) so the spawn engine branches cleanly; the claude path is frozen byte-for-byte (fake-claude regression green) while custom + opencode paths are additive.

### Phase 04: Gated status plugin unlocks waiting and idle

**Goal:** Fix the load-bearing defect where the opencode status plugin silently no-op'd (curl absent), blocking waiting/idle.
**Depends on:** Phase 03 (opencode engine spawn + status plugin)
**Plans:** 2 plans

Plans:
- [x] 04-01: opencode status plugin notify() curl→fetch+AbortController(3s) defect fix
- [x] 04-02: Build-tagged real-opencode e2e lifecycle proof (plugin loads, POSTs reach receiver, env-gate no-ops)

**Key decisions:** `notify()` switched from a curl shell-out (which silently no-op'd when curl was absent, so activity signals never unlocked waiting/idle) to `fetch()`+`AbortController(3s)` — fetch is available in the opencode plugin runtime; the 3s timeout bounds the post so a stuck receiver can't hang the plugin. Status-signal delivery must fail loudly or time out, not silently no-op.

### Phase 05: Session resume and argv regression hardening

**Goal:** Close the opencode restart-resume loop.
**Depends on:** Phase 03 (opencode_session_id column + resume argv)
**Plans:** 3 plans

Plans:
- [x] 05-01: tasks.opencode_session_id column (migration 00016) — nullable, upgrade + fresh-install tests
- [x] 05-02: opencode resume argv regression hardening
- [x] 05-03: captureOpencodeSessionAsync — async bounded poll discovers + persists opencode session id

**Key decisions:** Capture is an ASYNC bounded poll launched at spawn, never a spawn-time read — opencode mints its opaque `ses_…` id sometime after start, so kamacu must DISCOVER it; best-effort + warn-only (a capture failure costs only restart-resume, not the live session); poll is gated on the session's Done channel so it stops when the session exits; persisted id is what the resume argv keys off — closes the restart-resume loop. Per-engine session identity: claude_session_id (kamacu-minted, present at spawn) vs opencode_session_id (opaque, discovered async, nullable) — never mixed.

## Milestone Summary

**Key Decisions:**
- The `engine` column encodes a capability tier (`claude` | `custom` | `opencode`) — spawn branches on it, never name-string matching (extensible to future engines).
- Custom agents report only running/exited status (D-M001-2) — custom TUIs can't be reliably introspected; opencode gets real heuristics via its own engine branch + plugin, not the generic custom path.
- Extra Claude params (`--dangerously-skip-permissions`) consolidated onto the Claude agent's own row (migration 00014), not an orphaned global setting.
- opencode status plugin uses `fetch()`+`AbortController(3s)`, not a curl shell-out (silent-no-op defect fix).
- opencode session identity discovered via async bounded poll, not read at spawn (opaque foreign-minted id).

**Issues Resolved:**
- Custom command render tokenize-then-substitute bug (paths with spaces broke under initial replace-then-tokenize — caught by unit test, fixed).
- opencode status plugin silent-no-op (curl absent → activity signals never reached receiver → waiting/idle never unlocked) — rewritten on fetch+AbortController.
- Three shared tests that assumed a single-system-agent baseline regression-fixed for the new second system agent.
- opencode session id not available at spawn — solved by async bounded poll capture.

**Issues Deferred:**
- Additional built-in engines beyond claude + opencode with their own status heuristics + restart-resume (AGFUT-03).
- Per-agent workspace-scoped overrides (AGFUT-01).
- Agent template export/import sharing (AGFUT-02).

**Technical Debt Incurred:**
- None significant for v1.10's scope. The milestone reuses established v1.9 patterns end-to-end.
