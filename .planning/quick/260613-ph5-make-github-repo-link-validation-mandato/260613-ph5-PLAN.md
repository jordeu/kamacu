<objective>
Make GitHub repository linking validation MANDATORY (hard-block) in Project settings, superseding the soft "save but warn" verify_state behavior from quick task 260613-osu.

When the user clicks Save in Project settings, the backend verifies the GitHub repo BEFORE saving. If it can't be verified, the API returns 400 WITHOUT persisting, and the dialog shows a clearly-highlighted destructive error and stays open. A valid/verified repo saves and the dialog closes normally. Description/name-only edits never touch gh.

This is a deliberate, user-decided reversal of D-11's "never hard-block on gh" — but ONLY for the repo-link UX. `github.ValidateRepo` already returns the correct `verified` bool; the work is to ACT on it (block) instead of soft-saving, and to revert the 260613-osu advisory machinery on both ends.

Purpose: A linked repo is now guaranteed real, so downstream PR phases (11–13) never carry a phantom link.
Output: Reverted+hardened `update` handler, host-independent test, cleaned dialog with a highlighted error, optional-github_repo mutation, trimmed Project type, rebuilt embedded SPA.
</objective>
