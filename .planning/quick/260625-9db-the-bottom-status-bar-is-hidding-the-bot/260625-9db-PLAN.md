<objective>
Fix the bottom status bar (`ActiveSessionsBar`) overlapping sibling content.

The `ActiveSessionsBar` is `fixed inset-x-0 bottom-0 z-30` with a collapsed height of `h-9` (36px). It is a true overlay: the app shell never reserves vertical space for it. As a result:
1. The sidebar's container (`fixed inset-y-0 h-svh`) extends to the full viewport bottom, so its `SidebarFooter` ("Add project" + Settings) is hidden behind the 36px bar and the Add-project button cannot be clicked.
2. `<main>` (`flex-1`, full `min-h-svh`) also extends to the viewport bottom, so the bottom ~36px of its content — the xterm agent terminal / bash shell view — is clipped behind the bar.

The original D-03/D-13 decision intentionally overlaid the bar to avoid reflowing the height-sensitive xterm terminals. We keep that overlay/expand behavior but reserve clear space underneath it by adding bottom padding equal to the bar height (`pb-9` = 36px) to BOTH overlapped surfaces: `<main>` and the sidebar container. Because `<main>`'s usable height shrinks by 36px, the `TerminalPane` `ResizeObserver` (already watching the viewport element) automatically re-fits xterm — no terminal code changes needed.

Purpose: Restore access to the "Add project" affordance and stop clipping the agent/shell view, with the smallest possible change that matches the existing layout idiom (Tailwind utility classes, no edits to the generated shadcn `sidebar.tsx` primitive).
Output: Two one-line className edits, build + lint green, human-verified runtime.
</objective>
