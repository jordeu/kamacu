# Quick Task 260728-s5a: Fix send_session_message terminator (CR vs LF)

## Objective

`send_session_message` currently appends `\n` to terminate the message. Raw-mode TUI agents (Claude Code via Ink, opencode, anything readline/bubbletea-based) read `\r` (carriage return, 0x0d) as the Enter key — a `\n` is a literal line feed that does not submit the prompt. The prompt text arrives at the agent but the agent never processes it because its readline never sees Enter.

The browser WebSocket path works because xterm.js sends `\r` on Enter. The existing integration test (`internal/ws/integration_test.go:137`) passes because it drives `bash`, whose cooked-mode line discipline translates `\n`→`\r` on input — bash is not the affected code path.

## Background

PTY input bytes per surface:
- **Browser (xterm.js → WS → `sess.WriteInput`):** Enter key produces `\r`. Multi-line via Shift+Enter produces different escape sequences. Agents in raw mode read `\r` as submit.
- **MCP HTTP bridge (the broken path):** Currently appends `\n`. Raw-mode TUIs do not interpret `\n` as submit; the prompt text is queued but the agent's readline never fires.

This is a one-character correctness bug in the terminator normalization, not a deeper architectural issue.

## Tasks

### Task 1: Fix the terminator normalization in the input handler

**Files:**
- `internal/api/sessions.go` (modify, ~lines 537-540 of the `input` handler)

**Action:**

The current normalization is:

```go
msg := req.Message
if !strings.HasSuffix(msg, "\n") {
    msg += "\n"
}
```

Replace with CR-normalization that handles all three input cases explicitly. Use `strings.TrimSuffix` to strip a trailing `\n` (if present) and then unconditionally append `\r` — this collapses `\n`, `\r`, `\r\n`, and no-terminator all to a single `\r`:

```go
msg := req.Message
// Strip any trailing LF or CR-LF, then append a single CR. Raw-mode TUIs
// (Claude Code, opencode) read \r as the Enter key; \n is a literal line
// feed that does not submit. xterm.js sends \r on Enter — we mirror that.
msg = strings.TrimSuffix(msg, "\n")
msg = strings.TrimSuffix(msg, "\r")
msg += "\r"
```

Internal `\n`s in a multi-line body are preserved verbatim — only the terminator is normalized. (Note: agents like Claude Code may have their own multi-line input conventions via Shift+Enter escape sequences; the MCP tool deliberately does not synthesize those — single-line submit is the only supported shape.)

Update the comment block above the handler (currently lines 512-523) so "Newline normalization" reads "CR-terminator normalization" and explains the raw-mode-TUI rationale in one sentence.

**Verify:**

```bash
go build ./...
grep -n 'TrimSuffix\\|msg +=' internal/api/sessions.go   # confirm the new normalization is in place
```

**Done:**

Input handler writes `msg + "\r"` to the PTY, with any request-supplied trailing `\n`/`\r`/`\r\n` collapsed to a single `\r`.
