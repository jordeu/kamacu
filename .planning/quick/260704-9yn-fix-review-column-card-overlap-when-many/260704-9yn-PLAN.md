# Quick Task 260704-9yn: Fix Review column card overlap

## Problem

In the Review column, when there are many cards the cards overlap: a two-line PR
title is clipped and the meta row bleeds into the next card (see user screenshot,
2026-07-04).

## Root cause

The card-list container (`web/src/components/board/ReviewColumn.tsx:144`) is a
`flex min-h-0 flex-1 flex-col gap-2 overflow-y-auto` box. Its children (`PRCard`)
default to `flex-shrink: 1`, so once the cards' total height exceeds the column,
the flex algorithm **compresses** each card below its natural (content) height
instead of letting the container scroll. `PRCard`'s root has `overflow-hidden`
(`PRCard.tsx:112`), so the compressed card **clips** its `line-clamp-2` title's
second line and the `#num · @author · updated …` meta row overlaps the next card.

The sibling kanban `TaskCard` is in an identical container but has **no**
`overflow-hidden`, so the same latent compression doesn't visibly clip there —
which is why only the Review column shows the bug.

## Tasks

1. **Add `shrink-0` to the `PRCard` root** (`web/src/components/board/PRCard.tsx`)
   - action: insert `shrink-0` into the root `<div>` className so each card keeps
     its content height and the `overflow-y-auto` container scrolls instead of
     compressing cards.
   - scope: PRCard is used only by ReviewColumn (awaiting list + Recently
     Reviewed), so the fix is contained to the Review column; the kanban board is
     untouched.
   - verify: `cd web && npm run build` (tsc -b + vite build) exits 0.
   - done: with many PRs, cards render at full two-line height and the column
     scrolls; no clipping/overlap.

## Out of scope

- `TaskCard` has the same latent flex-shrink behavior but is masked (no
  overflow-hidden); not changing kanban behavior the user did not report.
