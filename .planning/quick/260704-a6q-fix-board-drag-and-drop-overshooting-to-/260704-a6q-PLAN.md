# Quick Task 260704-a6q: Fix board drag-and-drop column overshoot

## Problem

Dragging a task card to the adjacent column is often impossible — it jumps past
it to the column after. Reported: in project "Fusion", dragging any card from
"In Progress" to "In Review" lands it in "Done" instead.

## Root cause

`Board.tsx` used `collisionDetection={closestCorners}`. `closestCorners` ranks
droppables by the distance between the dragged element's RECTANGLE corners and
each droppable's corners. A task card is a full column-width box, so when dragged
sideways its leading corners already reach into the FAR column; corner-distance
minimization then selects that far column instead of the one under the cursor.
This is worsened by `handleDragOver`, which live-moves the card into the hovered
column on hover — that grows the target column and shifts every rect, so the
corner-closest target oscillates to the next column on the following mousemove.
Net effect: the drop target overshoots by one column and the adjacent column is
effectively unreachable.

The drag handlers (`resolveTargetColumn`, insert-index math, `handleDragEnd`) are
correct GIVEN a correct `over` target — the defect is only WHICH droppable the
collision strategy returns.

## Fix

Replace `closestCorners` with a pointer-first custom `CollisionDetection`
(`boardCollisionDetection`):
- Use `pointerWithin` — the droppable the cursor is literally inside. A column's
  horizontal position is stable across the vertical reflow, so the target no
  longer overshoots or oscillates.
- Among pointer hits, prefer a card (numeric id) over its enclosing column
  (`column:<status>` id) so the within-column insert index stays precise.
- Fall back to `closestCorners` when `pointerWithin` is empty (cursor in the
  horizontal gaps between columns, or keyboard dragging which has no pointer) so
  gap-hover and keyboard accessibility keep working.
