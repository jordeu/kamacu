## UAT Type

- UAT mode: runtime-executable — the unit-level content guards AND the real-binary plugin→receiver loop are automatable now (the build-tagged `opencode_e2e` suite runs on this host where opencode 1.17.15 is installed; it `t.Skip`s cleanly elsewhere so default CI is unaffected).
- The browser-visible LIVE behavior (status-dot transitions working→waiting→idle in the UI for a real opencode task) still requires the real binary + a running dev server and is **not** automatable in CI; it remains deferred to the **milestone M002 UAT gate** as a `human-follow-up` check (see "Deferred LIVE opencode UAT" below). This slice's UAT scope is the plugin-content contract + the real-binary loop proof.

## Preconditions

- Go toolchain present; module `kamacu` builds (`go build ./...`).
- Worktree at `.gsd-worktrees/M002`; S02 task artifacts present (`internal/opencode/kamacu-status.js`, `plugin.go`, `plugin_test.go`, `e2e_test.go`).
- For the real-binary checks (UAT-03/04): `opencode` on PATH and a provider config in `~/.config/opencode/opencode.json` (else the tests `t.Skip` — still a valid outcome, recorded as NEEDS-HUMAN on a host lacking opencode).

## Automated runtime checks (this slice's scope)

### UAT-01 — plugin uses fetch()+AbortController, NOT curl (content contract)
- Steps: `go test ./internal/opencode/ -run TestPluginSourceMatchesFile -count=1 -v`; `grep -c curl internal/opencode/kamacu-status.js`.
- Expected: test PASS (assertPluginContent asserts `fetch` + `AbortController` present AND the negative `curl`-absent assertion holds against the `//go:embed` bytes). `grep -c curl` on `kamacu-status.js` == 0. This is the regression guard for the fixed silent-no-op defect.
- Edge: a future edit reintroducing `curl` into the plugin source fails the suite loudly.

### UAT-02 — default opencode plugin suite still green (receiver-half regression intact)
- Steps: `go test ./internal/opencode/ -count=1`.
- Expected: all 7 plugin cases pass (no-op-when-absent, no-op-when-target-is-file, writes-when-present, idempotent-skip, overwrites-stale, config-dir-error, source-matches-file). The e2e file is excluded from the default suite by the build tag.

### UAT-03 — real-binary e2e: shipped plugin loads in opencode 1.17.15 and its POSTs reach a receiver (Stop → idle unlocks)
- Steps: `go build -tags opencode_e2e ./internal/opencode/`; `go test -tags opencode_e2e ./internal/opencode/ -run E2E_RealTurnPostsLifecycle -count=1 -v -timeout 240s`.
- Expected: test PASS. The httptest receiver observed ≥1 POST AND `counts["Stop"] ≥ 1` from a real `opencode run` turn with the shipped fetch-based plugin installed into an isolated temp `XDG_CONFIG_HOME`. This is the load-bearing assertion (not softened).
- Edge: `t.Skip` when `opencode` is absent or no provider config exists → NEEDS-HUMAN (re-run on a host with opencode + a working provider). On a provider runtime error the lifecycle still fires Stop (MEM031); on a session-SETUP-class failure (auth/connection-refused) Stop may not fire — re-run before treating as a failure.

### UAT-04 — real-binary e2e: env-gate no-ops against the real binary (D014 gate)
- Steps: `go test -tags opencode_e2e ./internal/opencode/ -run E2E_EnvGateNoopWhenSessionIDUnset -count=1 -v -timeout 240s`.
- Expected: test PASS. With `KAMACU_SESSION_ID` omitted (token + base set), the receiver recorded ZERO POSTs. Pre-existing `KAMACU_*` in the test process env is scrubbed so the result is deterministic even inside a Kamacu session.

### UAT-05 — regression: unchanged hook receiver + env injection + claude overlay intact
- Steps: `go test ./internal/api/ -run OpencodeHook -count=1`; `go test ./internal/session/ -run Opencode -count=1`; `grep -c curl internal/session/agent.go`.
- Expected: api receiver suite ok (hooks.go unchanged); session env-injection suite ok (manager.go/session.go unchanged, `TestCustomEngineDoesNotGetHookEnv` negative guard green); `agent.go` curl-count == 1 (claude overlay untouched by design).

- Preconditions: opencode CLI installed; `~/.config/opencode/` present; kamacu dev server running on localhost.
- Steps: create a project whose agent is opencode; create a task; open the task Agent tab; trigger a permission prompt and a turn end.
- Expected: opencode launches in the terminal; status dot transitions working→waiting (permission.ask)→idle (turn end) in the browser; `hooksAlive=true` after the first SessionStart; the managed plugin file exists at `~/.config/opencode/plugin/kamacu-status.js`. Critically this now works on hosts WITHOUT curl on PATH (the T01 fix).
- Non-automatable because: requires the real opencode binary + browser, not present in CI.
