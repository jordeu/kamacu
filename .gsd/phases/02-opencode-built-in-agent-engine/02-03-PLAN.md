# S03: Session resume and argv regression hardening

**Goal:** Make an opencode task resume its prior conversation after a kamacu restart by capturing opencode's own session id (ses_…) into a persisted tasks.opencode_session_id column and spawning `opencode -s <id>` on Resume, and lock the exact fresh-vs-resume spawn argv behind a committed fake-opencode regression stub (mirroring the fake-claude argv guard that has protected the claude path since Phase 5). The capture is isolated from the CI-testable core: the column, the resume argv, and the resumable flag are all strategy-invariant.
**Demo:** After this: restart kamacu, an opencode task's session resumes to the same conversation; the fake-opencode test guards the exact argv we build.

## Must-Haves

- Resume of an opencode task spawns `opencode -s <tasks.opencode_session_id>`: a committed fake-opencode argv guard asserts the resume argv is `[fake-opencode, "-s", "ses_test…"]` and the fresh spawn argv is `[fake-opencode]` (no `-s` token).
- GET /api/agents/status reports `resumable:true` for an EXITED opencode task with a stored opencode_session_id + worktree, engine-gated (NO claude transcriptExists glob requirement), so the existing engine-agnostic Resume button appears — both in the live manager pass and the post-restart survivor pass.
- tasks.opencode_session_id is captured and persisted for a live opencode session (via the plugin's session.created -> SessionStart hook carrying the ses_id as primary, with `opencode session list --format json` subprocess discovery filtered by worktree directory as fallback), so a kamacu restart can resume it — proven by a host-gated //go:build opencode_e2e test (opencode 1.17.15 is installed on this host).
- Migration 00016 adds the nullable tasks.opencode_session_id column idempotently on both the upgrade (stage at 00015) and fresh-install paths.
- The fake-claude suite (R016), the custom-engine suite incl. TestCustomEngineDoesNotGetHookEnv (R017), and the S01 opencode hook-status integration stay green — the claude and custom spawn/status paths are byte-for-byte unchanged (no -s leaks into a fresh opencode spawn; opencode resume never routes through claude's --resume).
- No frontend change: web/src/api/sessions.ts useResumeAgent already sends `{task_id, kind:"agent", resume:true}` engine-agnostically and the Resume button is shown whenever resumable is true.

## Proof Level

- This slice proves: high — CI unit tests pin the resume argv (fresh vs -s), the engine-gated resumable flag, the migration idempotency, and the capture-persist write path; a host-gated //go:build opencode_e2e test proves real-binary resume against opencode 1.17.15 (installed on this host). The LIVE browser restart-resume (restart kamacu, click Resume, confirm prior conversation in the terminal) remains the human milestone UAT gate — not automatable in CI.

## Integration Closure

Consumes S01 (the opencode engine seed + D014 KAMACU_SESSION_ID/HOOK_TOKEN/HOOK_BASE spawn env + the on-disk env-gated status plugin + the agentStatusLocked opencode full-heuristics gate) and S02 (the fetch-based plugin + the //go:build opencode_e2e real-binary harness pattern + the proven plugin->receiver loop + the httptest receiver mirroring the production X-Kangent-Token contract). Adds one nullable column (tasks.opencode_session_id, migration 00016), an engine branch in the spawn resume-validation + AgentArgs-build path (sessions.go), an engine-gated resumable derivation + survivor-pass widening (agents.go), and an async capture->persist write path (plugin session.created -> SessionStart hook -> manager-injected persist hook -> DB, with subprocess-discovery fallback). The claude and custom spawn/status paths stay byte-for-byte unchanged: TestCustomEngineDoesNotGetHookEnv and the fake-claude suite are the negative guards. Provides the milestone UAT its deferred restart-resume proof and a permanent fake-opencode argv guard. No frontend change (the Resume button + useResumeAgent are already engine-agnostic).
