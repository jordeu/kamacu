## Live browser steps (the deferred restart-resume proof — human milestone UAT)
1. Open kamacu in the browser; select a project whose agent is opencode.
2. Create a task -> the opencode TUI launches in the terminal; status shows working/idle.
3. Type a turn (e.g. "say hello"); opencode responds.
4. Exit the opencode session (Ctrl+C / exit); status -> exited.
5. `GET /api/agents/status` -> the task shows `resumable: true` (engine-gated, no claude transcript glob).
6. **Restart kamacu** (kill + relaunch the process).
7. After restart, the board reloads; the opencode task still shows `resumable: true` (survivor pass keys off the persisted opencode_session_id).
8. Click Resume -> the terminal spawns `opencode -s <ses_id>` -> **expected: the prior conversation is visible/restored in the browser terminal** (the strongest proof; deferred to human UAT per slice proof level).

## Expected outcomes
- Fresh opencode spawn: no `-s` token; resume: `opencode -s <id>`.
- resumable:true appears for exited opencode tasks with a stored id + worktree, live AND post-restart.
- Prior conversation resumes after restart (the human milestone gate).

## Edge cases
- Resume with NULL opencode_session_id -> 409 "no session to resume" (never silently forks a fresh session).
- Resume with a stale/deleted ses_id -> "Session not found" surfaces in the terminal honestly (no silent fresh fork).
- Fresh opencode spawn never leaks a `-s` token.
- A claude project's resume path is unchanged (--resume; TestRecoveryLifecycle stays green).
- A custom (non-claude, non-opencode) agent is unaffected (no hook env, no -s).
