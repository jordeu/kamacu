**Goal:** Establish the opencode engine seam: a task assigned the opencode agent spawns a real opencode session in a PTY and reports working/idle/exited via the existing activity heuristics. No waiting yet (that needs the plugin in S02).
**Demo:** After this: create a task with the opencode agent, watch it launch in the terminal, status toggles working/idle as it runs.

## Must-Haves

- New engine value "opencode" in the full-heuristics branch of agentStatusLocked() (alongside claude), verified by an engine-matrix test.
- manager.go spawn branch builds the opencode argv (opencode --session <id> <extras>) in a PTY with inherit-all env; fails cleanly (LookPath error) when opencode is absent.
- DB migration 00015 adds the opencode system seed (is_system=1, engine='opencode') + a backfill safety net; opencode is NOT the default (claude stays default).
- sessions.go resolves engine='opencode' from the task's agent row and carries it through Spawn WITHOUT misrouting to the custom-render path.
- Existing claude + custom paths unchanged (fake-claude regression green).

## Proof Level

- This slice proves: automated: engine-matrix unit test (T02), fake-opencode argv + lookpath test (T03), migrate/backfill idempotency test (T01), opencode end-to-end integration test (T04); manual cross-check: spawn real opencode in a task once the binary is present
