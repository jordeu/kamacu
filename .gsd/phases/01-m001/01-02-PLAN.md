# S02: Agent management UI and per-project selection

**Goal:** Build the agent management UI (global Settings Agents section with list/add/edit/delete/set-default) and the per-project agent selector in Project Settings, and make the quota indicator + Agent tab engine-aware so custom agents render correctly with running/exited status. Closes with a human-verify gate exercising the full loop end-to-end.
**Demo:** After this: the user adds a custom agent in Settings, picks it on a project, opens a task, and sees that agent run in the Agent tab with running/exited status and working terminal reattach; switching the project back to Claude restores working/waiting + resume with no UI regression.

## Must-Haves

- Frontend API client complete: useAgents() query (key \"agents\"), useCreateAgent/useUpdateAgent/useDeleteAgent/useSetDefaultAgent mutations, all invalidating the \"agents\" query on success. Agent interface in types.ts mirroring the backend (id, name, command, engine, is_default, is_system, timestamps).\n- Global Settings gains an Agents section: ordered list (default-first, mirroring the backend sort), add (name + command-template fields + inline help for {{worktree}}/{{session_id}} placeholders), edit, delete (disabled-with-tooltip when is_system OR in-use by a project, mirroring ManageWorkspacesDialog's countByWorkspace pattern), and set-default (a radio/flag control). The claude seed renders as a system agent (non-deletable, engine badge) with its name + command editable.\n- Project Settings dialog gains an Agent selector (shadcn Select dropdown of all agents, default-first then alpha), defaulting to the project's current agent_id. Changing it is a conditional PATCH (only sent when agent_id actually changes, mirroring the github_repo/icon_letters pattern).\n- The QuotaIndicator is hidden or inert when the active project's agent is non-claude (claude quota is a claude-only feature); the planner picks the cleaner of the two and implements it.\n- Zero new npm/Go dependencies (D007); reuse existing ui/ primitives (Dialog, Input, Select, Button, the WorkspaceNameDialog/ManageWorkspacesDialog shapes as templates).\n- Frontend gate green: cd web && tsc -b && vite build (both exit 0).\n- Human-verify gate passes: add a custom agent in Settings, select it on a project, spawn it in the Agent tab, confirm running/exited status + terminal reattach; switch the project back to Claude and confirm working/waiting + resume with zero regression.

## Proof Level

- This slice proves: human-verify-gate

## Integration Closure

The Settings Agents section and Project Settings selector both consume the typed /api/agents feed (TanStack Query useAgents) and the same mutations (create/update/delete/setDefault); the Agent tab's per-task spawn already carries the project, and S01 resolves project.agent_id -> spawn server-side, so the Agent tab needs no spawn change — only engine-aware status rendering (already added in S01 T06: \"running\" case in StatusDot/PRCard). The QuotaIndicator branches on the active project's agent engine (claude-only feature).
